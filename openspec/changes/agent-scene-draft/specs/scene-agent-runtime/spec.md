# Spec Delta

## ADDED Requirements

### Requirement: 场景草稿必须受控且按镜头隔离

agent MAY 通过受控工具读写场景草稿；草稿 MUST 存放在应用固定的草稿目录，按项目和当前镜头隔离，MUST NOT 接受模型传入的任意路径、绝对路径或 `..`。草稿 MUST 有总大小和单次写入上限，并与现有代码大小上限一致。取消、丢弃或工作台关闭后 MUST 清理草稿；MUST NOT 把草稿写入项目数据。

#### Scenario: 分段写入

- **WHEN** agent 连续调用追加或替换工具
- **THEN** 只有当前镜头对应的草稿变化，其他镜头不受影响

#### Scenario: 任意路径

- **WHEN** agent 尝试指定草稿路径
- **THEN** 工具拒绝并说明只能操作当前镜头草稿

#### Scenario: 清理

- **WHEN** 用户取消或关闭工作台
- **THEN** 草稿被清理，项目数据和旧代码不变

### Requirement: 长场景代码必须分片提交

运行时 SHALL 提供开始、追加、按行读取、局部替换、提交和丢弃草稿的工具。追加和替换 MUST 接受有上限的分片；读取 MUST 支持按行范围取片段。提交 MUST 先经过与一次性提交相同的静态准入，成功后把草稿设为本次 agent 会话的当前代码；MUST NOT 直接改写工作台草稿，渲染试运行通过后才可成为工作台草稿。提交失败 MUST 保留上一版会话代码。

#### Scenario: 长代码分片

- **WHEN** 一次模型输出不足以写完代码
- **THEN** agent 可以分多次追加，最后提交完整草稿

#### Scenario: 局部修改

- **WHEN** agent 只修改几十行
- **THEN** 可以按行替换，不需要重发全文

#### Scenario: 提交失败

- **WHEN** 草稿缺少 `build`/`pose` 或不满足准入
- **THEN** 提交被拒绝，上一版会话代码继续有效

#### Scenario: 试运行边界

- **WHEN** 草稿提交成功但还没有通过渲染试运行
- **THEN** 它只是 agent 会话的当前代码，不成为工作台草稿

### Requirement: 草稿操作必须可审计

运行时 MUST 记录草稿的开始、进度、提交和丢弃事件，事件 MUST 包含草稿标识、行数或字符数、状态和失败原因；MUST NOT 在事件中重复完整代码。提交后模型历史 MUST 用草稿摘要或引用替代分片工具调用，后续修改通过读取片段完成。

#### Scenario: 进度

- **WHEN** agent 追加或替换草稿
- **THEN** 事件流给出新的行数或字符数，聊天可显示进度

#### Scenario: 提交

- **WHEN** 草稿提交成功
- **THEN** 事件包含新代码哈希和行数，不包含完整代码

#### Scenario: 历史压缩

- **WHEN** 草稿提交后进入下一轮模型调用
- **THEN** 历史中保留草稿摘要而不是所有分片
