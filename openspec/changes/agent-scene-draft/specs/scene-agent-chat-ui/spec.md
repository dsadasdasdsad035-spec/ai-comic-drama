# Spec Delta

## ADDED Requirements

### Requirement: 草稿进度与提交状态必须可见

聊天 SHALL 以草稿卡展示当前场景草稿的行数、字符数和状态（暂存 / 已提交 / 已试运行 / 失败）。卡片 MUST 随追加、替换、提交和试运行更新；MUST NOT 在聊天消息里铺完整代码。草稿失败 MUST 显示原因，并保留上一版已生效代码。

#### Scenario: 分段进度

- **WHEN** agent 追加草稿
- **THEN** 草稿卡显示更新后的行数和字符数

#### Scenario: 提交

- **WHEN** 草稿提交成功
- **THEN** 卡片显示"已提交，待试运行"

#### Scenario: 试运行

- **WHEN** 试运行通过
- **THEN** 卡片显示"已生效"，代码页签显示完整代码

#### Scenario: 失败

- **WHEN** 提交或试运行失败
- **THEN** 卡片显示失败原因，旧代码不变

### Requirement: 草稿预览不得冒充已生效代码

聊天 SHALL 提供只读草稿预览，并 MUST 明确标记"未试运行"；工作台代码页签 MUST 继续显示已提交且通过试运行的代码。草稿预览 MUST NOT 提供保存、运行或成为当前草稿的入口；这些动作只能由 agent 工具或用户显式操作完成。

#### Scenario: 查看草稿

- **WHEN** 用户打开草稿预览
- **THEN** 看到当前草稿内容，并看到"未试运行"标记

#### Scenario: 代码页签

- **WHEN** 草稿尚未通过试运行
- **THEN** 代码页签仍显示上一版已生效代码

#### Scenario: 不冒充生效

- **WHEN** 用户尝试从预览直接保存
- **THEN** 没有可用入口，必须先提交并通过试运行
