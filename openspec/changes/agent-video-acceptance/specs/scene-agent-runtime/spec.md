# Spec Delta

## MODIFIED Requirements

### Requirement: agent 工具集受控且最小化

运行时 SHALL 只向 agent 暴露受控工具：读取当前镜头上下文、提交场景代码、沙箱试运行、抓取关键帧、关键帧验收和结束。工具 MUST NOT 提供任意 shell、文件写入、网络请求、跨镜头修改或渲染/保存能力。finish 后的 MP4 渲染、抽帧和视频验收 MUST 由应用编排执行，不是 agent 工具；只有视频验收通过才允许保存。

#### Scenario: 允许的上下文读取

- **WHEN** agent 调用上下文工具
- **THEN** 只返回当前镜头、参考内容和当前代码的摘要

#### Scenario: 禁止越权

- **WHEN** agent 尝试修改其他镜头或访问网络
- **THEN** 没有可用工具能完成该操作，请求被拒绝

#### Scenario: agent 不持有渲染工具

- **WHEN** agent 结束代码阶段
- **THEN** 工具列表中没有渲染、保存或写项目文件的工具，MP4 渲染由应用编排在 finish 后执行

#### Scenario: 视频通过后由应用保存

- **WHEN** 代码通过沙箱、关键帧初筛完成且 MP4 帧验收通过
- **THEN** 应用原子保存代码、参考上下文、MP4 和视频元数据，不需要再让 agent 调用保存工具

#### Scenario: 视频失败不覆盖旧结果

- **WHEN** MP4 渲染失败、抽帧失败或视频验收未通过
- **THEN** 当前镜头已保存的代码和旧视频保持不变，草稿仍可供继续修复

#### Scenario: 不自动保存

- **WHEN** agent 完成代码和关键帧验收
- **THEN** 代码仍作为草稿；只有应用编排的视频验收通过后才保存到镜头

## ADDED Requirements

### Requirement: finish 只结束代码阶段

agent 的 finish 工具 SHALL 只表示代码和关键帧初筛阶段结束，MUST NOT 直接标记场景完成。最终完成状态 MUST 等 MP4 视频验收结束；未通过时 MUST 显示视频验收未通过或待人工验收。

#### Scenario: finish 成功

- **WHEN** agent 调用 finish 且沙箱与关键帧初筛满足条件
- **THEN** 聊天显示代码阶段完成，并自动进入 MP4 视频验收，不提前显示场景完成

#### Scenario: finish 后视频失败

- **WHEN** finish 后 MP4 渲染或视频验收失败
- **THEN** 聊天显示视频验收未通过，不显示场景完成

#### Scenario: finish 前失败

- **WHEN** 沙箱未通过或关键帧初筛未完成
- **THEN** finish 不被接受，视频验收阶段不启动

### Requirement: finish 后必须用 MP4 帧做最终验收

finish 成功后，应用编排 SHALL 用最终代码和本次参考上下文渲染 clean MP4，并按镜头有效时长从该 MP4 抽取 5–9 帧交给视觉清单。最终验收 MUST 只使用 MP4 帧，MUST NOT 使用沙箱抓帧或只依据文本总结。

#### Scenario: 普通时长镜头

- **WHEN** 镜头有效时长为 4 秒
- **THEN** 渲染 4 秒 MP4，从 MP4 抽取覆盖开头到结尾的帧并逐项验收

#### Scenario: 长镜头

- **WHEN** 镜头有效时长为 8 秒或 12 秒
- **THEN** 抽帧按全时长分布，覆盖镜头后半段，不固定只抓 0–4 秒

#### Scenario: MP4 渲染失败

- **WHEN** 隐藏沙箱或 MP4 转码失败
- **THEN** 视频验收以渲染失败结束，保留代码草稿和旧项目视频

#### Scenario: MP4 抽帧失败

- **WHEN** MP4 已生成但无法抽取帧
- **THEN** 视频可预览，但状态为无法自动验收并转人工，不伪造通过

### Requirement: 视频验收通过后才保存

只有 MP4 帧验收全部通过时，系统 SHALL 原子保存最终代码、参考上下文、MP4 和视频元数据。未通过、无视觉模型、抽帧失败、取消或渲染失败 MUST NOT 覆盖当前镜头已保存视频；草稿 MAY 保留供继续修复。

#### Scenario: 视频验收通过

- **WHEN** MP4 帧验收所有要求通过
- **THEN** 保存的代码哈希、视频元数据和 MP4 地址互相对应，节点和项目数据同步更新

#### Scenario: 视频验收未通过

- **WHEN** 至少一项要求未通过
- **THEN** 旧视频和旧元数据不变，聊天显示失败项和继续修复入口

#### Scenario: 没有视觉模型

- **WHEN** 当前没有可用视觉模型
- **THEN** 渲染 MP4 供预览，状态标记为需人工验收，不自动保存，允许用户人工采用

#### Scenario: 取消或超时

- **WHEN** 用户在视频阶段取消或视频阶段超时
- **THEN** 渲染中止，不保存新视频，旧代码和旧视频保持有效

### Requirement: 视频验收结论必须可追溯

聊天最终文字和卡片 SHALL 由视频验收结构化结果生成，至少包含代码哈希、MP4 地址或时长、MP4 帧时间点和逐项结果；MUST NOT 让文本模型声明未在 MP4 帧中验证的画面细节。旧验收卡在代码哈希变化后 MUST 标记失效。

#### Scenario: 视频通过后的结论

- **WHEN** 视频验收通过
- **THEN** 聊天只报告代码沙箱、关键帧初筛、MP4 渲染和 MP4 帧验收的可验证结果

#### Scenario: 视频未通过后的结论

- **WHEN** 视频验收存在失败项
- **THEN** 聊天列出失败项与对应帧，不出现场景完成或全部符合的表述

#### Scenario: 代码变化

- **WHEN** 代码哈希发生变化
- **THEN** 旧视频和旧验收卡标记为过期，不与新代码或新视频混用

### Requirement: 视频验收阶段必须有独立进度、超时和取消

视频渲染、MP4 抽帧和视频验收 SHALL 作为 finish 后的独立阶段运行，提供可观察进度、独立超时和取消。超时或取消 MUST 中止并保留旧保存状态；切换聊天/代码页签 MUST NOT 中断该阶段。

#### Scenario: 进度更新

- **WHEN** 视频阶段开始
- **THEN** 聊天依次显示渲染进度、抽帧状态和视觉验收状态，而不是等全部结束才出现

#### Scenario: 视频阶段超时

- **WHEN** 渲染或验收超过独立时限
- **THEN** 阶段以超时结束，不保存新视频，显示可重试信息

#### Scenario: 视频阶段取消

- **WHEN** 用户点击取消
- **THEN** 正在执行的渲染或验收中止，草稿保留，旧视频不变

#### Scenario: 切换页签

- **WHEN** 视频阶段运行中用户切到代码页签
- **THEN** 阶段继续执行，切回聊天仍能看到最新进度和结果
