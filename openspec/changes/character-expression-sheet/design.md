# Design

## Context

当前实现见 `proposal.md` 的 Why。关键约束：

- `CharacterSheet.expressions` 是按情绪索引的单图；`CharacterBoard` 生成时一次请求 `n: 2`，并且只用 `lookEn` 文本，不传角色三视图。`collectShotReferences` 会把表情排在角色身份图之前。
- 画布素材卡只有一张 `url`，角色卡内部的表情图不会出现在画布上。
- 视频请求 `buildShotVideoRequest` 把候选参考截到 4 张，当前顺序是当前画面、表情、身份、相邻镜、素材；双人镜头很容易挤掉身份或场景。
- `shot-performance-direction` 已完成但尚未归档，本变更对它的表情实现做加法式替换：新总图优先，旧逐情绪图只读回退。`shot-video-prompt` 已有“参考图 N/4、省略项”要求，本设计扩展分配策略。

## Goals / Non-Goals

**Goals:**

- 一个角色一张表情总图，一次生成一张图；有身份图时用身份图约束长相。
- 总图可发布为一张画布素材卡；分镜按表演裁出单格，整图不进入生成参考。
- 视频表情参考默认关闭，显式开启后只占一个说话角色槽位，并在提交前展示预算。
- 角色卡以主图、摘要、单一主操作和渐进披露重新组织。

**Non-Goals:**

- 不做单格局部重绘；单格不满意时重生成整张或上传替换，后续再考虑局部编辑。
- 不自动把旧逐情绪图迁移成总图，也不删除旧图。
- 不改图片/视频 provider 协议，不改 4 张视频参考的硬上限。
- 不为每个情绪创建独立画布素材卡，不把总图整张发给模型。
- 不重做素材板、分镜 Inspector 或聊天工作台；只改角色卡和与表情相关的参考入口。

## Decisions

### 1. 总图是角色级可选资产，旧单图保留为只读回退

新增：

```ts
type ExpressionSheetCell = {
  emotion: PerformanceEmotion
  x: number; y: number; w: number; h: number   // 0..1，归一化
  cropUrl?: string
  cropFingerprint?: string
}

type CharacterExpressionSheet = {
  image: string
  columns: 4
  rows: 2
  cells: ExpressionSheetCell[]
  source: 'generated' | 'uploaded'
  fingerprint: string       // identityFingerprint
  stale?: boolean
  modelKey?: string
  createdAt?: string
}
```

`CharacterSheet.expressionSheet?: CharacterExpressionSheet`；项目蛇形字段为 `expression_sheet`。旧的 `expressions?: Partial<Record<PerformanceEmotion, CharacterExpression>>` 原样保留。读取优先级：有效总图 > 旧单图 > 文字表演。

为什么不把格子拆成八条独立记录：那会回到当前的多文件状态，画布和项目字段都会膨胀；总图用一张图 + 固定格序，正好对应“一张画布素材”。

为什么不把旧数据迁移：旧项目可能已经为某些镜头选过表情，自动迁移会改身份/资产语义；只读回退更安全。

### 2. 一次生成一张 4×2 总图，默认不使用候选

生成流程：

- 4 列 × 2 行，固定顺序 neutral、happy、sad、angry、fearful、disgusted、surprised、calm。
- `n: 1`，比例 `16:9`，走现有 `view` 能力；有角色三视图时作为 `refImage`，没有则只用 `lookEn` 并在 UI 标注“无身份图参考”。
- Prompt 明确要求 equal grid、无边框、无文字、无标签、同一发型/服装/配饰/光线/中性背景；只改变表情。
- 成功后才原子替换总图；失败保留旧图。生成入口显示“1 张图”的成本，不显示候选数量。
- 上传替换允许，但固定按 4×2 顺序映射，不做自动格子识别；上传成功清空裁剪缓存。

替代方案是继续逐情绪生成：目标精准，但 8 个情绪 × 2 候选的成本和卡片高度不可接受；而且用户明确要一张图。替代方案是一次生成 2 张总图候选：仍可保留为未来的高级选项，但不作为默认，避免重复费用。

### 3. 单格裁剪是派生物，不是第二真相源

- 格子矩形由 4×2 等分计算并归一化保存，方便以后调整 inset。
- 首次需要某情绪时，在浏览器用 canvas 从总图裁出对应矩形，经 `/api/save-image` 写入项目媒体目录；把 `cropUrl` 和 `cropFingerprint` 写回该格缓存。
- `cropFingerprint` 由总图 URL、格子矩形和总图指纹组成；总图替换或 `lookEn` 变化导致 stale 时，缓存失效。
- 裁剪失败（图片加载失败、canvas 被跨域污染、保存失败）时回退文字表演并显示原因，不阻塞出图。
- 整张总图永远不进入 `refImages`；只有 `cropUrl` 可以。

为什么在浏览器裁：总图和上传图都落在同源项目媒体目录，canvas 可以直接读取；避免为一次裁剪新增服务端图像处理依赖。若后续出现跨域或大图性能问题，再加服务端裁剪适配器，不改变数据契约。

### 4. 画布只发布一张素材卡，连线不改变情绪选择

- `ProjectAsset` 增加可选 `characterName`；`kind` 使用 `expression-sheet`。画布节点数据同样带 `characterName`，图片仍只用 `url`。
- 发布按角色名 upsert：已有同角色 `expression-sheet` 卡就更新 `url/title`，保留位置和 `refIds`；没有则创建一张卡。重复发布不产生第二张。
- 画布卡片显示总图；`KIND_META` 增加“表情”标签。
- 右键连线仍复用现有素材卡连线；连线本身只表示“这张总图属于该镜头的可用素材”，不决定情绪。
- `collectShotReferences` 的处理：
  1. 按 `performance` 自动解析有效总图的单格（优先），或旧单图回退；
  2. `asset-` 分支遇到 `expression-sheet` 时跳过整图，不重复添加；
  3. 没有表演/没有对应格时只保留身份/场景，并记录原因。
- 角色改名时同步更新已发布卡的 `characterName` 和标题；如果找不到旧卡，不创建孤儿卡。

自动解析仍保留，是为了不破坏现有“按表演自动带表情”的行为；画布卡解决可见性和素材管理，不要求用户额外连线才能使用表情。

### 5. 视频表情默认关闭，参考预算按“画面/身份/场景/表情”分配

新增镜头字段 `useExpressionRef?: boolean`，项目字段 `use_expression_ref`，默认 `false`，随镜头持久化并进入 `bizSignature`。

`buildShotVideoRequest` 的分配：

1. 当前画面（`refImage`）优先保留；
2. 所有入画角色身份图；
3. 场景/道具/相邻镜/手工参考；
4. 只有用户显式开启时，追加一张说话角色的有效表情单格。

最多 4 张。超限时先省略表情，再省略场景/道具；当前画面和身份图不得静默省略。若当前画面 + 身份图已经超过 4 张，返回阻止原因并要求用户取舍，不提交一个偷偷删身份图的请求。面板在提交前显示开关、四个槽位、省略项和原因；不再只靠提交后的 Toast。

为什么默认关闭：视频当前画面通常已经带有本镜表情，参考图槽位比图片生成更稀缺；把表情当默认项会挤掉身份/场景，且用户无法在提交前看到。显式开启让“想要更强表情约束”的用户自己付一个槽位。

### 6. 角色卡改为“主图 + 摘要 + 页签 + 抽屉”

```text
+------------------------------------------+
| [ 三视图 | 表情总图 | 音色 ]              |
|                                          |
|        一张主图（16:9）                   |
|                                          |
| 林岚  主角  28        [就绪]             |
| 音色：青涩青年声 [试听]  表情 8/8         |
+------------------------------------------+
| 表情总图：8 格，单击预览                  |
| 成本：1 张 · ¥0.22   本镜参考 2/4 · 表情关 |
+------------------------------------------+
| 外观锚点 [展开]                 [编辑]     |
+------------------------------------------+
```

- 主图区只显示一张图，页签切换三视图/表情总图/音色；默认优先三视图，其次总图，最后空状态。
- 摘要行承担扫描信息；身份字段和试音稿移入编辑抽屉，保存/取消明确，取消丢弃草稿。
- 每卡只有一个主操作，按状态映射：无三视图 → 生成三视图；有三视图无有效总图 → 生成表情总图；总图有效且未发布 → 发布到画布；其余低频动作进入更多菜单。
- 表情总图用 4×2 覆盖层显示八格，格子至少 44×44，标签和选中环同时存在；点击只预览，不改镜头 `performance`。
- 成本 chip 显示“1 张 · ¥0.22”；参考预算 chip 只在能确定选中镜头时显示，避免伪造数字。
- 空状态把生成按钮放进主图区，不再出现“点下方”但按钮在折叠线以下。

### 7. 兼容与归档顺序

- 旧 `expressions` 继续读；总图有效时总图优先。旧项目不会自动生成总图。
- 新视频行为对旧镜头默认关闭表情参考；这是一次有意的行为变化，需在 README/迁移说明中写清。
- `shot-performance-direction` 尚未归档，本变更与其 `character-expression` 语义重叠。归档顺序必须先归档 `shot-performance-direction`，再归档本变更；后者只把总图作为新增能力，旧逐情绪要求保留为兼容路径。若主 specs 已出现重复的表情能力，归档前先同步并合并 Purpose/Requirements，不直接覆盖。

## Risks / Trade-offs

- **总图模型不按 4×2 排布或画风漂移** → 生成成功后立即显示大图预览并进入可用状态；不合格可立即重生成或上传替换。裁剪失败会回退文字表演，不把整图发出去。
- **单格分辨率不足** → 使用当前可用的最高 view 模型/2K 输出；4×2/16:9 每格接近方形；低于可接受分辨率时在 UI 提示，不静默使用模糊格。
- **浏览器裁剪被跨域污染** → 总图和上传图都保存到项目媒体目录；失败时提示重新上传或后续接服务端裁剪，不把整图发出去。
- **身份漂移** → 有身份图时强制作为 `refImage`；没有身份图时明确标注，不用“同一人”承诺掩盖。
- **默认关闭视频表情让表情约束变弱** → 关键帧已承载表情，提示词仍写表演；需要更强约束时逐镜开关，面板显示占用。
- **身份图超过 4 张被阻止** → 这是比静默丢弃更安全的行为；面板列出超限角色，用户可减少 cast 或拆镜。
- **旧数据/归档冲突** → 保留 `expressions` 回退；先归档 `shot-performance-direction`，再处理本变更的主 spec 合并。
- **一张总图承载八格，单格局部不满意** → 首版只支持整图重生成/上传；局部重绘列为后续，不扩大本次范围。

## Migration Plan

1. 数据层：新增 `expressionSheet` / `expression_sheet`、`useExpressionRef` / `use_expression_ref`；旧字段保留，读取优先级总图 > 旧单图 > 文字。
2. 生成层：实现 4×2 单图生成、身份图参考、上传替换、原子替换和成本显示。
3. 裁剪与参考：实现格子坐标、裁剪缓存、`collectShotReferences` 总图优先/旧图回退、画布 `expression-sheet` 资产。
4. 画布：实现按角色 upsert 发布、更新/改名同步、连线不整图发送。
5. 视频：实现默认关闭、说话角色单格、4 张分配和提交前槽位预览。
6. 角色卡 UI：主图页签、摘要、单一主操作、编辑抽屉、44px 表情格、成本/预算 chip、空状态和窄屏。
7. 回归与证据：纯函数、裁剪、画布、视频请求、UI 截图；旧逐情绪项目回归；README/证据更新后按归档顺序处理。

回滚：关闭总图入口并继续读旧 `expressions`；已有总图/裁剪是可选字段，旧客户端忽略；视频 `useExpressionRef` 默认 false，回滚不会删除任何媒体。
