# Spec Delta

## ADDED Requirements

### Requirement: 聊天引擎可切换且可回退

3D 调度聊天 SHALL 通过稳定门面选择执行引擎，默认引擎 SHALL 为 pi，并 MUST 保留 LangGraph 作为可回退实现。当当前模型不具备原生工具调用能力时，系统 MUST 自动使用 LangGraph 并在界面与轨迹标明回退。切换或回退 MUST NOT 要求改动聊天 UI、工具定义或镜头数据，MUST NOT 改变工具的输入输出契约。

#### Scenario: 默认引擎

- **WHEN** 用户没有显式选择引擎，且当前模型具备原生工具调用能力
- **THEN** 聊天使用 pi 引擎运行

#### Scenario: 默认回退

- **WHEN** 用户没有显式选择引擎，且当前模型不具备原生工具调用能力
- **THEN** 聊天使用 LangGraph 运行，并在界面与轨迹标明回退原因

#### Scenario: 显式回退

- **WHEN** 用户在设置里选择 LangGraph
- **THEN** 即使模型支持原生工具调用，聊天也使用 LangGraph，不要求重建线程、不丢失已保存线程记录

#### Scenario: 引擎配置无效

- **WHEN** 配置指定的引擎不存在
- **THEN** 系统按默认规则解析，MUST NOT 静默改变用户可观察到的验收结论

### Requirement: 引擎必须满足模型工具能力前提

新引擎 SHALL 只在已声明支持原生工具调用的渠道/模型上启用。当前模型未声明支持时，系统 MUST 继续使用现有引擎的 JSON action 路径，MUST NOT 把 JSON action 结果翻译成工具调用来伪造原生能力。

#### Scenario: 能力表内模型

- **WHEN** 当前 3D 代码模型在原生工具能力表内
- **THEN** 新引擎可以运行，并在轨迹中标明使用的工具协议

#### Scenario: 能力表外模型

- **WHEN** 当前模型未声明原生工具调用
- **THEN** 聊天沿现有路径运行，不切换新引擎，也不报“模型不支持”而中断

#### Scenario: 显式强制新引擎

- **WHEN** 配置显式要求新引擎但当前模型不支持原生工具调用
- **THEN** 系统返回可读错误，说明需要更换模型或回退引擎，MUST NOT 伪装成运行成功

### Requirement: 引擎必须保持工具顺序与结束门禁

新引擎 MUST 按模型给出的顺序串行执行有状态工具，MUST NOT 并行执行提交代码、渲染试运行、抓帧、验收或结束中的任意组合。结束工具 MUST 作为终止信号，使本轮在工具结果落定后停止，MUST NOT 再追加一次无工具的模型请求。

#### Scenario: 有状态工具串行

- **WHEN** 模型在同一批里给出多个有状态工具调用
- **THEN** 引擎逐个执行，后一个工具看到前一个工具的结果

#### Scenario: 抓帧不早于试运行

- **WHEN** 模型同时请求渲染试运行与抓帧
- **THEN** 抓帧只在试运行成功之后执行

#### Scenario: 结束后停止

- **WHEN** 结束工具成功返回
- **THEN** 本轮不再发起新的模型请求，聊天给出最终摘要

#### Scenario: 结束门禁失败

- **WHEN** 结束工具因未试运行或未验收而失败
- **THEN** 引擎把失败作为工具结果交回模型继续修复，MUST NOT 直接结束为成功

### Requirement: 运行轨迹必须标明实际引擎

运行结果和事件流 SHALL 记录本轮实际使用的引擎标识与工具协议，使用户和测试能区分同一次会话里不同轮的引擎来源。MUST NOT 记录上游模型隐藏推理或渠道凭据。

#### Scenario: 成功轨迹

- **WHEN** 一轮运行以结束工具正常完成
- **THEN** 轨迹包含引擎标识、工具协议、工具顺序与最终摘要

#### Scenario: 失败轨迹

- **WHEN** 一轮运行因错误、取消或达到上限结束
- **THEN** 轨迹保留引擎标识和已发生的工具事件，不删除中间记录

#### Scenario: 回退轨迹

- **WHEN** 新引擎因前置条件不满足而回退
- **THEN** 轨迹标明实际运行引擎，且不声称使用过新引擎

### Requirement: 引擎替换不得改变可观察行为

两个引擎对同一组输入 MUST 产生等价的可观察行为：相同的工具集合与参数校验、相同的试运行与验收门禁、相同的取消与超时结局、相同的事件分组与去重语义，以及相同的镜头隔离边界。事件顺序的差异 MUST 只允许出现在不影响用户判断的位置。

#### Scenario: mock 输入对齐

- **WHEN** 用同一组 mock 模型响应、mock 渲染和 mock 视觉分别运行两个引擎
- **THEN** 两者产出的工具顺序、代码草稿、帧结果、验收结论和取消结局一致

#### Scenario: 门禁失败对齐

- **WHEN** 试运行失败或视觉验收未通过
- **THEN** 两个引擎都不把代码写入项目，并给出等价的失败原因

#### Scenario: 取消对齐

- **WHEN** 用户在工具执行中取消
- **THEN** 两个引擎都停止后续工具与增量、终止上游请求、保留上一版有效代码

#### Scenario: 镜头隔离对齐

- **WHEN** 任一引擎运行结束
- **THEN** 其他镜头的代码、参考选择和视频状态都不变

### Requirement: 引擎依赖必须集中隔离

新引擎的上游依赖 MUST 只出现在单一适配目录中，MUST 使用精确版本锁定。工作台、工具实现、事件归约器和项目数据层 MUST NOT 直接引用上游类型。移除该依赖 MUST 只影响该适配目录和引擎选择逻辑。

#### Scenario: 依赖边界

- **WHEN** 检查聊天 UI、工具实现和事件归约器的 import
- **THEN** 它们不引用新引擎的上游包

#### Scenario: 上游升级

- **WHEN** 上游发布不兼容变更
- **THEN** 只需修改适配目录并运行对齐验收，不修改工具语义或工作台

#### Scenario: 移除依赖

- **WHEN** 决定回到单引擎实现
- **THEN** 删除适配目录与引擎选择即可，现有线程、镜头数据和验收流程不受影响
