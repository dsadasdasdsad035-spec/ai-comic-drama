# Proposal

## Why

场景三维的视角控制完全依赖鼠标：`ArcRotateCamera.attachControl` 提供拖拽旋转与滚轮缩放，界面上唯一的说明是一行「左键旋转 · 滚轮缩放 · 点选对象后 Gizmo 移动」。由此产生四个具体问题：

1. **量程是写死的，与户型脱节**：`lowerRadiusLimit = 2` / `upperRadiusLimit = 40` 是常量，而现有五套预设的对角线从 10.8m（一室一厅）到 15.6m（餐厅）不等。近距离想看清一张桌子时已贴到桌边，远距离又滚出房间外只剩一个小方块。
2. **套用预设后看不到全貌**：相机停在上一次的值（初始是 `radius=10 / target=(0,1,0)`），不随户型尺寸与位置调整。用户必须手动点「户型俯视」机位才能看到整个房间。
3. **触控板几乎不可用**：`wheelPrecision = 40` 按鼠标滚轮标定，触控板双指滑动的 delta 小得多，体验是「滚很久没反应然后突然跳一下」。
4. **没有复位入口**：改坏了视角只能重新点机位书签，空场景时无书签可点，只能刷新页面。

## What Changes

- 「分镜」页签内新增**视角控制**区块，位于「预览环境」与「机位书签」之间，提供六条参数滑杆与三个动作按钮。
- 六条滑杆：方位角、仰角、距离、目标 X/Y/Z。全部双向绑定当前 Babylon 相机。
- 三个动作：适应视图（按场景包围盒自动取景）、俯视、正视。
- 相机数据流由单向（鼠标 → 相机）改为双向（鼠标 ↔ 相机 ↔ React 状态），并引入「谁在控制」标记避免拖动滑杆与相机输入互相回写。
- 相机半径限制从固定常量改为按场景包围盒浮动，使近距与远距在不同户型下都可用。
- 滚轮灵敏度按输入设备区分：鼠标滚轮沿用现值，触控板降低精度。
- 平移操作补进画布提示行（Babylon 默认支持中键拖拽与 Ctrl+左键，但从未告知）。
- 预设套用后自动适应视图，不再需要手动点俯视机位。

明确不做：

- 不改 ArcRotateCamera 的类型，不引入自由飞行相机或第一人称相机。
- 不做相机关键帧动画（机位之间平滑过渡）。
- 不做视角锁定、网格对齐、正交投影切换。
- 不改机位书签的保存/恢复语义与导出格式。
- 不把三维工作台整体 spec 化：本变更只覆盖视角控制这一个能力。

## Capabilities

### New Capabilities

- `material3d-orbit-controls`: 场景三维的轨道相机控制系统——参数面板与滑杆的读写语义、双向绑定的仲裁规则、适应视图的取景算法、快捷视角、输入设备分级与指针隔离。

### Modified Capabilities

（无）

## Impact

- **前端**：`src/material3d/Material3dCameraPanel.tsx`（新增视角控制区块）、`Material3dShotPanel.tsx`（透传 props）、`Material3dWorkbench.tsx`（相机状态订阅与写回、滑动隔离、套用预设后 fit）、`createEngine.ts`（半径上下限改为可变、滚轮精度分级）、`material3dTypes.ts`（若需要，新增相机参数的视图类型）。
- **样式**：`theme.css` 复用现有 `.m3d-env-row` 的行式滑杆布局，必要时补一条分组标题样式。
- **数据**：相机参数不进入项目存档。视角只在保存机位时 `snapshotCamera` 落盘，本次不改该路径。
- **性能**：`onBeforeRender` 每帧读相机值，需以 epsilon 阈值抑制无变化时的 setState；拖动滑杆期间跳过回写。三维场景的渲染循环已在运行，不新增渲染开销。
- **回归**：现有 `verify-material-3d-studio.mjs`（8 项）覆盖 Tab/新建/书签/持久化，需确认未被打断；`verify-m3d-presets.mjs`（结构+资产+真跑五套预设）需确认套用预设后的自动取景不影响对象数断言。
