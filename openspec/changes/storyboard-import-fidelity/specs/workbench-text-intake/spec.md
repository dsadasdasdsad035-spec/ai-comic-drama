# Spec Delta

## MODIFIED Requirements

### Requirement: 表格按表头别名映射字段

系统 SHALL 支持 Markdown 表格、CSV 与 TSV，并按中英文表头别名识别字段，至少覆盖镜号、时长、景别、机位、运镜、画面描述、台词/声音、首帧提示词、视频提示词，以及选角、表演、运镜参照、参考。缺少镜号列时 MUST 拒绝导入并说明原因；其余列缺失时 MUST 只留空对应字段，MUST NOT 用默认值冒充用户内容。

#### Scenario: 中文表头

- **WHEN** 表格表头为「镜号 / 秒 / 景别 / 运镜 / 描述 / 台词」
- **THEN** 各列分别映射到对应字段并进入预览

#### Scenario: 英文表头

- **WHEN** 表格表头为 `shot / seconds / size / move / description / dialogue`
- **THEN** 各列按别名映射，行为与中文表头一致

#### Scenario: 缺少镜号列

- **WHEN** 表格没有任何可识别为镜号的列
- **THEN** 系统拒绝导入并说明必须有镜号列，不生成任何草稿

#### Scenario: 只有提示词列

- **WHEN** 表格只有镜号与首帧提示词两列
- **THEN** 导入只更新首帧提示词，不把视频提示词写成空值

#### Scenario: 制作方式等无对应字段的列

- **WHEN** 表格含「制作方式」这类在镜头数据里没有对应字段的列
- **THEN** 该列被忽略并计入预览的「忽略列」清单，不塞进画面描述或任意其他字段

#### Scenario: 选角与表演列被识别

- **WHEN** 表格含「选角 / 表演 / 运镜参照 / 参考」四列
- **THEN** 这四列被识别为对应字段，不出现在「忽略列」清单

### Requirement: 台词列分离台词、旁白与音效

台词/声音列 MUST 区分三类内容：带说话人的台词、旁白、以及音效/音乐等非语言声。只有前两类 MUST 进入镜头台词；音效与音乐 MUST NOT 进入台词，MUST 被保留为声音说明。旁白 MUST 标记为非角色说话人，MUST NOT 被当作出场角色。同一单元格里混排的多段内容 MUST 被拆成多条。单元格内的 `<br>`、`<br/>` 与 `<br />` MUST 先归一化为换行再切分，使被 Markdown 表格挤成一行的多段台词能恢复原有分段。

台词标注 MUST 只解析说话人之后、首个冒号之前的部分，形如 `角色[情绪/强度/语速/音量]{强调}：台词`；冒号之后的文本 MUST 逐字进入台词，MUST NOT 参与标注解析。标注 MUST 写入该行的台词表演，MUST NOT 进入台词文本。台词被写入时，该镜台词表演 MUST 按文件整体重建，MUST NOT 沿用旧值。

#### Scenario: 旁白

- **WHEN** 台词列为「旁白：那天晚上，我以为自己活不过去了。」
- **THEN** 生成一条说话人为旁白的台词，且该镜出场角色不含旁白

#### Scenario: 纯音效

- **WHEN** 台词列为「雨声、远处车声。」
- **THEN** 该镜不产生台词，这段文字作为声音说明保留

#### Scenario: 混合内容

- **WHEN** 台词列为「脚步声停止。人类轻声：小家伙，你怎么在这里？」
- **THEN** 拆成一条声音说明与一条说话人为人类的台词

#### Scenario: 音乐提示

- **WHEN** 台词列为「音乐由紧张转柔和」
- **THEN** 不产生台词，作为声音说明保留

#### Scenario: 单元格用 br 分隔多段台词

- **WHEN** 台词列为「陈默：又是这里。<br>林小雨：你认得这条路？」
- **THEN** 拆成两条台词，说话人分别为陈默与林小雨，不被合并成一条

#### Scenario: br 写法变体

- **WHEN** 台词列同时出现 `<br>` 与 `<br />` 两种写法
- **THEN** 两者都被当作换行处理，分段结果一致

#### Scenario: 带台词表演的台词

- **WHEN** 台词列为「陈默[angry/4/slow/soft]{又是这里}：又是这里。」
- **THEN** 台词文本为「又是这里。」，台词表演为情绪 angry、强度 4、语速 slow、音量 soft、强调「又是这里」

#### Scenario: 部分空槽

- **WHEN** 台词列为「林小雨[sad//fast/]：你认得这条路？」
- **THEN** 台词表演只设置情绪 sad 与语速 fast，强度与音量留空

#### Scenario: 空槽不等同零值

- **WHEN** 标注为 `陈默[/4///]`
- **THEN** 强度为 4，情绪、语速、音量与强调保持未设置，MUST NOT 写成默认值

#### Scenario: 无标注台词

- **WHEN** 台词列为「陈默：又是这里。」
- **THEN** 台词文本为「又是这里。」，该行台词表演为空，不产生默认情绪

#### Scenario: 冒号后的方括号

- **WHEN** 台词列为「陈默：[系统]警告：电池耗尽」
- **THEN** 台词文本为「[系统]警告：电池耗尽」，冒号后的方括号不被当作标注

#### Scenario: 重写台词时重算表演

- **WHEN** 某镜原有两条带台词表演的台词，导入文件给了一条无标注的台词
- **THEN** 该镜台词表演按文件重建为空，不沿用旧的两条

### Requirement: 系统补的默认值必须可见

当表格缺少某个必填字段的列（如运镜）而项目结构要求该字段有值时，系统 MAY 填入默认值，但 MUST 在预览中把这类填充单列为「默认补全」并计数。用户 MUST 能看出哪些值是自己的原文、哪些是系统补的。

表演的默认补全 MUST 与其余默认值分开计数并显式命名为表演补全，MUST NOT 与用户文件里的表演混为一处。文件为该镜的说话角色都给出了表演条目时，该镜 MUST NOT 产生表演补全计数；某个说话角色的表演单元格为空时，系统补的仍 MUST 计入补全。

#### Scenario: 缺运镜列

- **WHEN** 表格没有运镜列
- **THEN** 所有镜头运镜为固定，预览显示「运镜默认补全 12 镜」

#### Scenario: 有运镜列

- **WHEN** 表格有运镜列
- **THEN** 预览不出现默认补全计数，运镜全部取自表格

#### Scenario: 说话角色缺表演

- **WHEN** 表格有台词列但没有表演列，某镜有两位说话角色
- **THEN** 预览单独显示该镜补了两条默认表演，并说明这些表演不是文件内容

#### Scenario: 文件已给表演

- **WHEN** 表格有表演列，某镜两位说话角色都有表演条目
- **THEN** 预览不产生表演补全计数

### Requirement: 导入先预览后应用

任何导入 MUST 先展示差异预览，再等待用户确认应用。预览 MUST 显示新增、更新、保留与跳过的数量，并 MUST 显式列出需要人判断的项，包括场次号未匹配、镜号未匹配与解析失败的条目。

参考与运镜参照无法解析时，预览 MUST 逐条列出镜号与被引用的名字，并说明该字段将被跳过；MUST NOT 静默忽略，MUST NOT 用相近名字顶替。

#### Scenario: 预览计数

- **WHEN** 导入 12 行，其中 3 行是新镜号
- **THEN** 预览显示新增 3、更新 9 与保留的镜数，应用前不修改任何数据

#### Scenario: 场次号对不上

- **WHEN** 表格里的场次号在当前集场次中不存在
- **THEN** 预览显式列出受影响的镜数与回退到的场次，而不是静默归类

#### Scenario: 取消导入

- **WHEN** 用户在预览阶段取消
- **THEN** 项目数据、工作台草稿与脏状态都保持导入前的样子

#### Scenario: 素材参考对不上

- **WHEN** 参考列写了「素材:会议室全景」，当前项目没有这个标题的素材卡
- **THEN** 预览列出该镜号与「会议室全景」并说明未解析，应用后该镜不新增这条参考

#### Scenario: 运镜参照对不上

- **WHEN** 运镜参照列写了「推镜头」，当前镜头语言库没有该条目
- **THEN** 预览列出该镜号与该名字并说明未解析，应用后该镜不写入运镜参照

## ADDED Requirements

### Requirement: 参考列按名字解析为镜头参考连线

参考列形如 `角色:名字列表;素材:标题列表` 时，系统 MUST 按名字解析为当前项目的参考连线：角色按角色名匹配角色卡，素材按标题匹配画布素材卡。解析成功的目标 MUST 以增补方式写入该镜参考连线，MUST NOT 移除文件未提到的既有连线。某一类缺失时 MUST 视为该类未给值。

#### Scenario: 角色与素材都解析成功

- **WHEN** 参考列为「角色:陈默、林小雨;素材:会议室全景」，三项都存在于当前项目
- **THEN** 该镜参考连线包含这三张卡，既有其他连线保留

#### Scenario: 只有角色

- **WHEN** 参考列为「角色:陈默」
- **THEN** 只处理角色，素材连线保持原样

#### Scenario: 同一条重复出现

- **WHEN** 参考列重复写同一个角色名
- **THEN** 该角色只被连一次，不产生重复项

#### Scenario: 没有参考列

- **WHEN** 文件不含参考列
- **THEN** 该镜参考连线保持不变

### Requirement: 运镜参照列只写条目标识

运镜参照列 SHALL 按镜头语言条目的中文名或条目 `key` 解析为条目标识，并只写入该标识。导入 MUST NOT 复制或导入条目视频文件，MUST NOT 为解析失败的行写入任何标识。

#### Scenario: 按中文名解析

- **WHEN** 运镜参照列为「推镜头」，镜头语言库有该中文名的条目
- **THEN** 该镜写入对应条目标识

#### Scenario: 按 key 解析

- **WHEN** 运镜参照列为 `01_dolly_in`
- **THEN** 该镜写入该条目标识

#### Scenario: 不导入视频文件

- **WHEN** 某行成功解析出条目
- **THEN** 项目媒体目录不因这次导入新增视频文件

#### Scenario: 名称有歧义

- **WHEN** 运镜参照列的写法匹配到多个条目
- **THEN** 该行视为未解析，预览列出候选，不猜测其中一个

### Requirement: 选角与表演列写入镜头字段

选角列 SHALL 以 `、` 分隔的角色名写入该镜出场角色。表演列 SHALL 按 `角色:情绪/强度/动作/视线/是否说话` 逐条写入表演，槽位固定、缺项留空，是否说话接受 `说` 与 `不说` 两种写法。两条列都 MUST NOT 影响台词。

#### Scenario: 选角写入

- **WHEN** 选角列为「陈默、林小雨」
- **THEN** 该镜出场角色为这两个名字

#### Scenario: 表演写入

- **WHEN** 表演列为「陈默:angry/4/拍桌/盯镜头/说」
- **THEN** 该镜表演包含一条情绪 angry、强度 4、动作「拍桌」、视线「盯镜头」、说话的角色表演

#### Scenario: 多条表演

- **WHEN** 表演列用 `<br>` 分隔两条
- **THEN** 该镜表演包含两条，不被合并

#### Scenario: 缺项留空

- **WHEN** 表演列为「林小雨:calm/2//」
- **THEN** 该条表演只有情绪与强度，动作、视线与是否说话保持未设置

#### Scenario: 没有这两列

- **WHEN** 文件不含选角列与表演列
- **THEN** 该镜的出场角色与表演保持不变
