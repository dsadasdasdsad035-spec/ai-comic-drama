# Spec Delta

## Purpose

定义创意会话这一独立于项目的创作单元：它可以没有项目、可以有多条对话、可以把源视频与分析结果沉淀为可复用产物，并在用户明确要求时才写入项目。

## ADDED Requirements

### Requirement: 创意会话独立于项目

系统 SHALL 允许在未选择任何项目时创建、打开和继续创意会话。创意会话 MUST 只属于自己的持久化记录，MUST NOT 因为切换全局项目而改变内容或消失。

#### Scenario: 没有项目也能开始

- **WHEN** 系统里没有任何项目，用户打开创意视图并发送第一条消息
- **THEN** 会话正常创建并保留，不提示先建项目，也不自动创建项目

#### Scenario: 切换项目不影响创意

- **WHEN** 用户在一个创意会话中切换到另一个项目
- **THEN** 会话消息、源视频和产物保持不变，不重新加载为空

#### Scenario: 会话不写项目

- **WHEN** 用户在创意会话中进行任意分析或生成
- **THEN** 直到用户显式执行「晋升项目」，项目数据不被修改

### Requirement: 多条会话可命名、可恢复

系统 SHALL 为每个工作区保存多条创意会话，并按最近更新时间列出。每条会话 MUST 有可编辑标题；标题为空时 MUST 用首条用户消息生成可读标题。重新打开会话 MUST 恢复消息、模式与产物引用。

#### Scenario: 新建第二条会话

- **WHEN** 用户在已有会话的创意视图点「新会话」
- **THEN** 创建一条空会话并切换过去，旧会话仍出现在列表中

#### Scenario: 自动标题

- **WHEN** 用户发送第一条消息且会话还没有标题
- **THEN** 会话标题取自该消息的可读摘要，之后用户可手动改名

#### Scenario: 恢复会话

- **WHEN** 用户从列表选择一条历史会话
- **THEN** 消息顺序、当前模式、源视频卡片和产物卡片都恢复，已删除的源文件标注为缺失

#### Scenario: 删除会话

- **WHEN** 用户删除一条会话并确认
- **THEN** 该会话从列表消失，其独占的源文件与产物被清理，其他会话不受影响

### Requirement: 会话消息只保存引用

系统 SHALL 在会话消息中只保存文本、工具名、结果摘要和产物引用。视频、证据帧、音频 MUST NOT 以二进制或 base64 写入消息记录。单个会话记录 MUST 有体积上限，超限时 MUST 返回可读错误而不是静默截断。

#### Scenario: 引用而非内联

- **WHEN** 一次反推完成并写入消息
- **THEN** 消息里只有源视频 ID、镜头数与提示词包引用，没有视频或帧图字节

#### Scenario: 会话过大

- **WHEN** 单条会话记录超过体积上限
- **THEN** 系统提示用户新建会话或清理旧轮次，已有内容不被丢弃

### Requirement: 产物以卡片沉淀

系统 SHALL 把源视频、镜头分析、提示词包和生成结果呈现为会话内卡片。每张卡片 MUST 提供可执行动作（查看证据、复制提示词、换模型重试、导出、晋升），且 MUST NOT 要求用户回到其他工作台才能完成这些动作。

#### Scenario: 提示词包卡片

- **WHEN** 反推完成
- **THEN** 会话中出现提示词包卡片，显示镜头数、总时长、模型与生成时间，并提供复制全文、下载 JSON、晋升

#### Scenario: 生成结果卡片

- **WHEN** 一次生图或生视频成功
- **THEN** 会话中出现结果卡片，显示所用模型、耗时、费用估算与文件位置，并提供重试和替换参考

### Requirement: 导出提示词包

系统 SHALL 支持把一份反推结果导出为可复制的文本和可下载的 JSON。导出的 JSON MUST 通过 `reverse-v1` 契约校验；文本 MUST 包含每镜时间范围、画面提示词与运动提示词。

#### Scenario: 导出为 JSON

- **WHEN** 用户点「下载 JSON」
- **THEN** 系统下载一份通过契约校验的 `reverse-v1` 文件，文件名包含会话标题与时间戳

#### Scenario: 导出为文本

- **WHEN** 用户点「复制提示词」
- **THEN** 剪贴板得到按镜分组的可读文本，不包含内部 ID 与文件路径

### Requirement: 晋升到项目是显式动作

系统 SHALL 只在用户点击「晋升项目」并确认后写入项目。晋升 MUST 允许新建项目或写入现有项目，MUST 保留来源链接、源视频引用与证据帧引用；MUST NOT 覆盖目标项目已有的手改字段。

#### Scenario: 晋升为新项目

- **WHEN** 用户选择「新建项目」并填写名称
- **THEN** 系统创建项目，写入分集、镜头与两段提示词，并在结果中给出项目位置

#### Scenario: 晋升到现有项目

- **WHEN** 用户选择已有项目并确认
- **THEN** 系统只追加或更新镜头表，保留已有镜头的手改提示词与参考

#### Scenario: 取消晋升

- **WHEN** 用户在确认框选择取消
- **THEN** 不产生任何项目写入，会话内容保持不变

### Requirement: 模式切换保留上下文

系统 SHALL 允许同一创意会话在「策划」「反推」「复刻」模式间显式切换。切换 MUST 保留消息历史、源视频与产物；界面 MUST 显示当前模式，并只启用该模式的写工具。

#### Scenario: 从反推切到复刻

- **WHEN** 用户在已有反推结果后切到复刻模式
- **THEN** 历史与提示词包保留，输入区与可用动作切换为复刻相关能力

#### Scenario: 只读引用其他模式产物

- **WHEN** 当前模式需要读取其他模式产出的镜头或提示词
- **THEN** 通过只读工具读取，不修改原产物

### Requirement: 失败与取消可恢复

系统 SHALL 在摄取、分析、生成任一阶段支持取消，并把取消与失败区分为不同状态。失败 MUST 保留已完成的中间结果，并允许从失败步骤重试，不要求用户重新摄取源视频。

#### Scenario: 分析中途取消

- **WHEN** 用户在逐镜分析进行中点击取消
- **THEN** 已完成的镜头分析保留，未完成部分标记为未分析，可直接续跑

#### Scenario: 下载失败后重试

- **WHEN** 源视频下载失败并返回可读原因
- **THEN** 用户可更换链接或改用本地上传重试，不需要重建会话
