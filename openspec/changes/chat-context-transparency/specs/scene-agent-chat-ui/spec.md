# Spec Delta

## MODIFIED Requirements

### Requirement: 现有参考内容与输入框保持可用

聊天 SHALL 以附件栏展示当前镜头的显式附件（媒体、文本、媒体 brief），每个附件 MUST 可移除；输入框 MUST 默认空，MUST NOT 自动预填镜头文本或其他未附加内容。发送前 MUST 显示「本次上下文 N 项」和「查看将发送」入口；展开后 MUST 显示系统提示、镜头元数据、每个附件的缩略图或全文、brief 原文与预计字符数/图片数。

#### Scenario: 已选 chips

- **WHEN** 用户打开聊天
- **THEN** 当前显式附件以 chips 显示，每个附件可单独移除

#### Scenario: 发送前移除

- **WHEN** 用户移除一个附件后发送
- **THEN** 本次 agent 上下文不包含该素材或文本

#### Scenario: 输入框

- **WHEN** agent 未运行
- **THEN** 输入框默认为空，用户可输入并发送，支持键盘快捷键

#### Scenario: 不自动预填

- **WHEN** 用户打开一个有画面提示词、台词和 cast 的镜头
- **THEN** 输入框保持为空，这些文本只出现在可添加的附件列表里

#### Scenario: 查看将发送

- **WHEN** 用户点击「查看将发送」
- **THEN** 展开面板显示系统提示、镜号/时长/画幅、所有附件的缩略图或全文、brief 原文和预计大小

## ADDED Requirements

### Requirement: 每轮模型调用的上下文必须可审计

每次模型调用 SHALL 在聊天中产生一张可折叠的「本轮上下文」卡，记录本轮实际发送的附件标识与数量、镜头元数据摘要和工具上下文摘要。卡片 MUST NOT 展示图片字节、模型 Key、鉴权头或隐藏推理；它只用于让用户核对这一轮到底发送了什么。

#### Scenario: 首轮上下文

- **WHEN** agent 发起第一次模型调用
- **THEN** 聊天出现「本轮上下文」卡，列出本次附件和元数据

#### Scenario: 工具追加上下文

- **WHEN** 工具返回结果并被加入下一轮模型输入
- **THEN** 对应轮次的上下文卡标明工具结果已追加，并显示摘要

#### Scenario: 不含推理与密钥

- **WHEN** 用户展开上下文卡
- **THEN** 看不到图片字节、模型 Key、鉴权头或模型隐藏推理
