# Proposal

## Why

「清空画布」当前是纯本地动作：只删画布节点与连线，`project.json` 里的镜头一个字节都不动。这带来三个层面的一致性问题。

第一层是**跨入口不一致**：清空后画布是空的，但 `read_shots` 照样读得到该集全部分镜，导出的 Markdown 照样有内容，集目录照样写着「N 镜」。用户看到的是"我清空了"，系统回答的是"数据还在，只是没给你看"。

第二层是**持久性分裂**：空/非空状态存在浏览器 `localStorage`（`cleared` 标记），而数据在服务端 SQLite。于是重启服务回不来、刷新回不来，但换浏览器、换设备、清站点数据，卡片全回来了。用户无法预测这个按钮到底做了什么。

第三层是**上一轮补救带来的复杂度**：为了让"投影级清空"站得住，加了 `canvasClearedRef` 显式标记、三处水合拦截、存档 `cleared` 语义，以及「重建本集卡片」入口。这些机制全部是为"数据还在但不能显示"服务的，读者必须理解两层状态才能看懂代码。

用户的预期是"清空就是把这一集的分镜去掉"。本次把语义改成真删，让四个消费面（画布、agent 读工具、Markdown 导出、集目录计数）一起对齐，并同时砍掉上面那套补丁。

## What Changes

- **清空 = 删除当前集镜头**：走既有的 `mergeProjectShots(..., deleteShotIds)` 通道，按镜头 id 显式删除；其他集、角色、素材、设定卡一律不动，素材卡（画布节点）保留。
- **跨面一致**：删除后 `read_shots` 不再返回该集镜头，单集与「导出全部」的 Markdown 不再含该集内容，集目录计数归零，刷新页面与重启服务都保持删除后的状态。
- **二次确认 + 服务端快照**：确认不再用 `window.confirm`（Electron 无 `prompt`，也不足以表达不可恢复），改为复用 `PromptDialog` 要求手打当前集号（如 `E01`）。服务端在 `deleteShotIds` 分支先落快照，快照写不进去就拒绝删除（fail-closed），与项目删除的既有先例一致。
- **退休投影级清空的补丁**：删除 `canvasClearedRef` 与存档 `cleared` 的写入/读取，「重建本集卡片」入口（菜单项与空状态按钮）一并移除，`focusEpisode` 去掉清空守卫。代码量净减少。
- **空状态改成实话**：本集在项目里没有镜头时提示"这一集还没有镜头"，给导入分镜表与新建镜头入口；不再提供无法生效的重建按钮。其他集镜数仍从 `projectShots` 统计，作为切集线索。
- **措辞按范围区分**：`删除选中`（N 张，可能含素材卡）与 `清空本集`（当前集全部 M 镜）都是真删，文案必须各自写明范围与集号，`MUST NOT` 用同一句话描述两者。

明确不做：

- 不加镜头级 undo 栈（与「删除选中」「Inspector 删单镜」保持一致：都不可撤销，靠快照兜底）。
- 不清理媒体文件：`keyframe` / `clip` 指向的图片视频不随镜头删除而删除。项目内媒体可能被角色卡、素材卡或其他镜头引用，当前没有引用计数，删文件不可逆。
- 不清理镜头对话线程：`chat_threads` 以 `(project, surface, episode, shot_id)` 为键，删镜后该键的历史会留下。清理属于独立改动。
- 不扩展到其他集或整个项目：按钮长在单集画布里，范围就是当前集。
- 不改 `删除选中`、`Inspector 删单镜`、`delete_shots` 工具的行为。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `canvas-shots-workbench`：「画布增删插为正式镜头」补充真删动作的范围区分（删除选中 vs 清空本集）；新增「清空画布删除本集镜头」要求，规定删除通道、保留范围、跨入口一致与持久性；新增「清空画布需二次确认与服务端快照」要求；新增「清空后的空状态」要求，替代上一轮的「清空只影响画布投影」「画布清空可重建」「空画布给出恢复引导」三条。

## Impact

- 画布交互与状态：`src/App.tsx`（`clearCanvas` 改真删、移除 `canvasClearedRef` 与重建动作、`focusEpisode` 去掉守卫、空状态提示改文案、手打集号确认的状态机）。
- 操作菜单：`src/BoardMenu.tsx`（移除重建项，清空项改为表达范围与不可恢复）。
- 服务端：`server/app.ts` 的 `deleteShotIds` 分支增加删除前快照；快照函数参照 `server/project-lifecycle.mjs` 的写法（临时文件 + rename，失败即拒绝）。
- 存档：不再写入 `cleared`；旧存档里的 `cleared` 一律忽略（数据仍在，进集应正常显示卡片）。存档结构保持向后兼容。
- 回归脚本：`verify-canvas-clear-restore.mjs` 由"投影级"断言改写为真删断言（读工具、导出、刷新、重启、快照、其他集不变、边界转场）；新增服务端快照的接口级验收；`verify-boardmenu.mjs`、`verify-creative-export.mjs`、`verify-storyboard-md-export.mjs` 作为连带回归。
- 无新增依赖，无数据模型变更（复用 `shots` 表的既有删除路径）。
