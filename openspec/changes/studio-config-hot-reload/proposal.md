# Proposal

## Why

设置页维护的三类对象（技能、专家、工具）进入宿主的方式不一致，而表现形式统一为"改了不生效"：

- 技能正文靠宿主的文件监听本来就是热的，但技能**增删**不触发专家技能根重建，新装技能即使重启宿主也不会出现，必须再保存一次设置才生效。
- 专家变更判据只拼「对象个数」（`id:工具数:技能数:是否通配`），改 `soul`、换一个同数量工具、换一个同数量技能都不会触发重同步，宿主继续跑旧 persona。
- 工具清单在宿主插件激活时只拉一次，改 schema 必须重建 bundle 并重启宿主。

同时 `dsh-tool-bridge` 已经声明「技能包新增、修改或删除后无需重启即可反映到可用技能列表」，当前实现没有满足该要求。

## What Changes

- **修三个静默失效**
  - 专家变更判据由个数拼接改为完整内容指纹（`soul`、名称、描述、工具与技能白名单的**内容**），改 persona 必定触发重同步。
  - 技能上传、上传 zip、卸载、覆盖重置后触发专家技能根同步，但**不重启宿主**（技能靠文件监听生效，重启没有收益）。
  - 技能根重建改为增量：只补缺失软链、只删多余软链，先以临时名建好再原子改名，避免监听器观察到整棵子树消失再出现。
- **工具清单版本化热更新**：`/api/studio/tools` 返回清单版本；宿主工具桥在工具调用前比对版本，变化则注销并重新注册全部工具，无需重启宿主。刷新只在没有在途工具调用时进行。
- **工具实现热更新（可选）**：`server-build/studio-tools.mjs` 按 mtime 重新导入，使重建产物后无需重启宿主。该步可独立延后。
- **把"必须重启"变成显式约束**：专家 preset 由启动期 `--patch` 叠加，改动仍需重启；本变更把这个边界写进设计，而不是留成隐含行为。降低重启感知的工作属于 `studio-host-prewarm-keepalive`。
- **BREAKING**（内部契约）：`/api/studio/tools` 响应新增 `version` 字段；宿主插件依赖该字段，应用与插件必须同版本部署。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `dsh-tool-bridge`: 既有「技能从文件系统包发现并可热加载」补充技能根重建与增量同步要求；新增「工具清单变更无需重启即可生效」要求。
- `creative-experts`: 新增「专家变更生效判据必须覆盖 `soul` 与白名单内容」与「技能集合变更后专家技能根自动同步」两项要求；既有的专家目录、技能白名单通配、运行时约束不变。

## Impact

- 代码：`server/app.ts`（设置变更通知携带原因、技能路由触发同步、工具清单版本）、`server/index.mjs`（同步策略按原因区分、签名落地）、`server/dsh-experts.mjs`（内容指纹、增量软链）、`server/dsh-plugins/creative-tools/index.js`（工具注册刷新）、`server/studio-tool-bridge.mjs`（版本与模块重载）。
- 测试：`tests/studio-*` 新增三例（专家指纹、技能热同步、工具清单刷新）。
- 非目标：不修改 `deepseek-harness` 子模块；不实现专家无重启热换；不改变技能包的安装、目录优先级与卸载语义；不把 MCP 接入创意链路。
