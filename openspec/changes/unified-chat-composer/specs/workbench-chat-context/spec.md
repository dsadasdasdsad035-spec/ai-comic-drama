# Spec Delta

## MODIFIED Requirements

### Requirement: 附件清单是模型输入的唯一来源

工作台聊天送给模型的上下文 MUST 只由显式加入的附件与用户本轮输入产生，MUST NOT 额外附加界面状态、未选中的素材或隐藏的默认值。清单 MUST 至少包含元数据与附件两项；每个附件 MUST 带可用于展示的标签与类型。

#### Scenario: 只有显式附件进入上下文
- **WHEN** 用户在聊天里只加入了角色「陈默」的一张参考图
- **THEN** 本次对话的上下文只包含该图，不包含项目里其他角色的图片或未加入的素材

#### Scenario: 没有附件
- **WHEN** 用户没有加入任何附件就发送消息
- **THEN** 模型只收到元数据与该轮用户输入，界面不出现空附件占位

#### Scenario: 元数据范围
- **WHEN** 聊天处于角色工作台
- **THEN** 元数据只描述本次编辑范围（项目、集号或角色范围），不伪造镜头号、时长或画幅

#### Scenario: 附件随用户消息进入本轮
- **WHEN** 用户带着附件发送一轮消息
- **THEN** 附件内容随该轮用户输入进入模型上下文，不需要技能模板声明额外的附件占位符

### Requirement: 附件在发送前可见且可移除

系统 MUST 在输入框上方、输入区内列出本次对话的全部附件，逐项显示标签、类型与（图片的）缩略图；用户 MUST 能在发送前移除任意附件或清空全部。附件 MUST 跨轮保留到被移除或清空为止，MUST NOT 在发送成功后自动清空。移除 MUST 立即反映到后续消息的发送内容。

#### Scenario: 移除图片附件
- **WHEN** 用户从附件栏移除一张图片
- **THEN** 该图不再出现在上下文，后续消息也不包含它

#### Scenario: 清空附件
- **WHEN** 用户点清空
- **THEN** 附件栏变空，元数据与输入框内容保留

#### Scenario: 发送前检查
- **WHEN** 用户点开「查看将发送」
- **THEN** 能看到元数据、每个附件的缩略图或全文、文本附件字符数与图片数量，并能从检查器里排除某项

#### Scenario: 连续两轮沿用附件
- **WHEN** 用户带着附件发送一轮，随后发送第二轮
- **THEN** 两轮都包含该附件，附件栏在发送后不清空

### Requirement: 视觉理解必须先于同步渲染算好

视觉理解是异步操作，而聊天在渲染期同步读取上下文。系统 MUST 在附件变化时预计算视觉理解并缓存结果，渲染期 MUST 只读缓存。MUST NOT 在渲染过程中发起视觉请求，MUST NOT 因重复渲染而重复计费。理解进行中 MUST NOT 禁用文本输入框。

#### Scenario: 同一附件不重复理解
- **WHEN** 用户加入一张图并触发多次渲染
- **THEN** 视觉模型只被调用一次，后续渲染命中缓存

#### Scenario: 附件变化后重算
- **WHEN** 用户移除一张图或加入新图
- **THEN** 缓存按新的附件集合重新计算，旧结果不再被使用

#### Scenario: 理解未完成时不阻塞界面
- **WHEN** 视觉理解仍在进行中
- **THEN** 附件栏显示该图正在理解，用户仍能继续输入文字

#### Scenario: 理解中发送不静默丢弃
- **WHEN** 用户在理解仍未完成时点发送
- **THEN** 系统要么按已就绪的上下文发送，要么给出可读提示说明需要等待，MUST NOT 出现无任何反应的点击
