# Spec Delta

## Purpose

定义应用内所有聊天共用的输入区：附件条的位置与结构、附件类型模型、上传与从素材库选的入口、附件写入各面正式数据的去向，以及仅附件发送与跨轮保留语义。

## ADDED Requirements

### Requirement: 所有聊天共用一个输入区

应用内每个聊天面板 SHALL 用同一个输入区组件承载文本输入与发送操作。接受附件的聊天面板 MUST 用同一个输入区承载附件条。任一聊天 MUST NOT 在输入区之外另建一套附件入口。聊天特有控件（查看将发送、brief 排除开关、上传条、检查器入口）MUST 作为该输入区的可选槽位出现，MUST NOT 改变输入区的整体结构。

#### Scenario: 各聊天面结构一致
- **WHEN** 用户依次打开技能聊天、3D 调度聊天与创意会话
- **THEN** 三处的附件条、文本输入与发送操作处于同一相对位置，外观与交互一致

#### Scenario: 不接收附件的面
- **WHEN** 用户打开不声明任何附件来源的聊天面板
- **THEN** 它仍使用同一输入区，但不显示空的附件条或占位

#### Scenario: 不存在第二套附件入口
- **WHEN** 检查任一聊天面板
- **THEN** 面板内只有输入区一处可以加入附件，面板其他区域不出现独立的附件栏或参考清单

### Requirement: 附件条位于输入区内

附件条 MUST 位于输入框上方，并与发送操作同属一个视觉整体。它 MUST 逐项显示附件类型与标签：图片显示缩略图，视频显示可辨认的封面或类型标记，文档显示文件名。附件条 MUST 提供单项移除与全部清空。

#### Scenario: 加入附件后的位置
- **WHEN** 用户加入一张图片
- **THEN** 该图片以带缩略图的条目出现在输入框上方，而不是面板顶部或消息区

#### Scenario: 类型可辨认
- **WHEN** 同一轮同时带图片、视频与文档
- **THEN** 每个条目的类型标签各不相同，用户无需打开就能区分

#### Scenario: 移除与清空
- **WHEN** 用户移除一个附件或点清空
- **THEN** 对应条目立即消失，输入框文字保留，后续发送不再包含被移除的附件

### Requirement: 附件类型由来源决定

每个附件 MUST 带 kind：`image`、`video`、`doc` 或 `text`。文件类附件（image / video / doc）的 kind MUST 由文件内容与扩展名推断，MUST NOT 由入口、面板或上传控件决定；text 表示从项目数据派生的文本项，由来源数据决定。面板不接受某类型时，该类型 MUST 在该面板的上传与素材入口就被排除或禁用，MUST NOT 在用户选择完成后再以错误文案拒绝。

#### Scenario: 只收图片的面板
- **WHEN** 用户在只接收图片的聊天里打开素材入口
- **THEN** 视频与音频条目不可选或不出现在可选范围内，用户不会选完之后才被告知不支持

#### Scenario: 上传时识别类型
- **WHEN** 用户上传一个视频文件
- **THEN** 该附件被标记为 video，并在附件条上以视频样式呈现

#### Scenario: 不静默改类型
- **WHEN** 上传的文件类型无法识别
- **THEN** 系统拒绝并说明原因，不把未知文件当作图片或文档加入附件

### Requirement: 入口按面声明的来源提供

聊天面 MUST 声明自己接受的附件类型与可用入口，并只提供声明过的入口：声明上传的提供「上传本地文件」，声明素材来源的提供「从当前项目素材里选」；两种都声明时两个入口 MUST 同时存在。素材入口 MUST 复用项目既有的缩略图选择器，只列出当前项目内已有媒体。取消选择 MUST NOT 改变附件集合。

#### Scenario: 上传本地文件
- **WHEN** 用户从输入区上传一张本地图片
- **THEN** 图片落成项目媒体文件并作为附件加入本次对话

#### Scenario: 从项目素材选
- **WHEN** 用户在声明了素材来源的聊天里点「从素材选」
- **THEN** 打开既有缩略图选择器，确认后该媒体加入附件，取消则附件集合保持不变

#### Scenario: 不声明就不出现
- **WHEN** 某个聊天面没有声明素材来源
- **THEN** 输入区不出现「从素材选」按钮，而不是出现一个点了会报错的入口

#### Scenario: 上传结果可再次被选中
- **WHEN** 用户上传的图片已成为项目媒体文件
- **THEN** 之后在任意聊天的素材入口里都能选到它，无需重新上传

### Requirement: 附件写入各面已有的正式数据

附件进入聊天后 MUST 写入该聊天面已有的正式数据：工作台技能聊天写入本轮用户消息与视觉摘要，3D 调度写入该镜头持久化的镜头上下文。系统 MUST NOT 在聊天面板内维护与正式数据并行的第二份参考来源。

#### Scenario: 3D 的附件写回镜头上下文
- **WHEN** 用户在 3D 调度聊天里加入一张图片
- **THEN** 该图片进入当前镜头的持久化上下文，代码生成与预览使用的参考素材随之包含它

#### Scenario: 工作台附件不写卡片
- **WHEN** 用户在角色聊天里加入图片并产出角色
- **THEN** 这些图片只进入本次对话，不写入任何角色的参考图列表

#### Scenario: 重新打开仍然可见
- **WHEN** 用户关闭并重新打开 3D 工作台
- **THEN** 之前加入的图片仍在附件条里，因为它来自持久化的镜头上下文

### Requirement: 只带附件也能发送

用户在没有任何文字时带附件发送 SHALL 成功发起本轮。发送 MUST NOT 静默失败，用户消息 MUST 带一句可读的占位说明，使历史记录与重试有可读内容。既无文字也无附件时 MUST 保持不可发送。

#### Scenario: 传图后直接点发送
- **WHEN** 用户只加入一张图片，没有输入任何文字，然后点发送
- **THEN** 本轮正常开始，聊天里出现一条带占位说明的用户消息

#### Scenario: 空输入不可发送
- **WHEN** 输入框为空且没有任何附件
- **THEN** 发送操作不可用

### Requirement: 附件在对话内跨轮保留

已加入的附件 MUST 在后续轮次继续可用，直到用户移除或清空。MUST NOT 在发送成功后自动清空附件。项目、集或镜头发生变化时 MUST 清空附件，避免把上一处上下文带进新一处。

#### Scenario: 第二轮沿用同一附件
- **WHEN** 用户带着一张图发送一轮，然后直接发送第二轮
- **THEN** 第二轮仍包含该图，用户不需要重新添加

#### Scenario: 切换集后清空
- **WHEN** 用户从第 1 集切到第 2 集后继续聊天
- **THEN** 附件集合为空，第 1 集的附件不会出现在第 2 集

### Requirement: 附件上限与就地上限提示

每个聊天面 MUST 声明单次附件上限，所有类型共享同一计数。达到上限后 MUST 拒绝继续添加附件并就地说明原因，已有附件 MUST NOT 受影响。

#### Scenario: 到达上限
- **WHEN** 当前附件数量已达到该聊天面的上限
- **THEN** 新增入口禁用或提示已达上限，已有附件保持不动

#### Scenario: 不同类型共享计数
- **WHEN** 用户已加入三张图片，而上限为四
- **THEN** 再加入一个文档即达到上限，不会因为类型不同而单独计数
