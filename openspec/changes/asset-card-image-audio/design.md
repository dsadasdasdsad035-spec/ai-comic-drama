# Design

## Context

见 `proposal.md`。镜头工位存在 `shots.prod_kind`（缺省时由静帧或成片推断）。素材卡是 `assets` 行加画布节点，列只有类型、标题、地址、备注、标签和 `canvas_id`，没有提示词，也没有自己的参考名单。参考连线只写在目标镜头的 `refIds`。出图走现有图片接口，音频合成走现有 `/api/voice`。`assets` 整表替换，未知字段今天不会落库。

## Goals / Non-Goals

**Goals:**

- 图片卡和音频卡用同一套素材节点生成文件，结果写回本卡。
- 图片卡能记住参考连线，出图时带上这些图。
- 打开项目时一次性迁走标明生图的镜头，并留下可重入的标记。

**Non-Goals:**

- 不接 Suno、Lyria 等尚未接入的音乐模型。
- 不把音频做成时间线音轨，也不改出片请求里音频参考的条数。
- 不重排留下的镜号，不改未写明工位的旧镜头。

## Decisions

### 继续用素材卡，不新做节点类型

图片生成卡的 `kind` 为 `image`，音频生成卡为 `audio`。空地址允许存在。提示词和参考 id 放进素材的 JSON 扩展，而不是再做一种画布节点。

备选是第三种 `prodKind`。那会继续占镜号，和已确认的决定相反。

### 素材表增加 extra，项目表记录迁移标记

`assets` 目前没有 `shots.extra` 那种兜底列。增加 `assets.extra`，读写时展开。提示词用 `prompt`，参考名单用 `refIds`。项目增加 `projects.extra`，写入 `imageShotsToAssetCards: true`。标记和删镜、建卡放在同一次项目写回里。没有这个标记时，即使当时没有生图镜，也要写上，避免以后每次打开都扫描。

备选是把提示词塞进 `note`。备注已经要承接迁出的台词，混在一起会分不清。

### 参考连线可以指向图片素材卡

连到图片素材卡时，把来源 id 写进该卡的 `refIds`，画布边仍由名单派生。出图只解析角色、场景、道具和图片素材。`shot-prev`、`shot-next` 和相邻镜头不进入请求。音频卡生成只把 `prompt` 当作合成文本交给已接入的音频模型，不读取 `refIds`。

### 迁移映射

只处理 `prod_kind === 'image'`。`keyframe_prompt`（空则 `desc`）成为卡的 `prompt`，`keyframe` 成为 `url`。该镜 `refIds` 里的角色和素材 id 改记到新卡；邻镜 token 丢掉。其他镜头 `refIds` 里若出现这张镜的节点 id，改写成新卡 id。台词整理成文本写入 `note`。候选图、秒数、运镜不复制。删除该镜时清掉指向它的 `transition_out`，不改其他镜的镜号，不把新卡连到相邻出片镜。画布位置沿用原镜头坐标。

### 镜头创建与 Agent

新增和插入固定写 `video`，界面不再提供生图选项。Agent 若再提交 `prod_kind: image`，拒绝该字段，不创建生图镜。

## Risks / Trade-offs

- [与 `shot-outgoing-slots-only` 同时改 Inspector] → 本变更只删生图页和类型切换，不恢复音画页或元数据页。
- [迁移写到一半失败] → 同一次写回里先确保新素材已在 `assets` 中，再删镜头并写标记；失败则整次不标完成，下次打开重试。已存在相同 `canvasId` 的卡不重复创建。
- [旧客户端打开已迁移项目] → 生图镜已不在序列里，只剩素材卡。不提供自动回滚。
- [音频模型仍是语音合成] → 音乐模型保持目录中的未接入状态，卡片先拒绝提交。

## Migration Plan

1. 给 `assets` 和 `projects` 增加 `extra`，读路径对旧库补列。
2. 打开项目时若标记未置位，执行上面的映射并写回。
3. 服务端改动后重建 `server-build/app.mjs`，否则桌面端仍跑旧库结构。

## Open Questions

无。未接入音乐模型的具体供应商留到该模型接入时再定，不影响本卡的提示词和写回。
