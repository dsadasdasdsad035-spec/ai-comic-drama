# Spec Delta

## ADDED Requirements

### Requirement: 历史工具结果按预算指针化

重建模型历史时，最近若干轮的工具结果 SHALL 原样保留完整内容。超出预算的更早工具结果 MUST 替换为一行指针 stub，指明原始工具名、原始规模与可重取的读工具；stub MUST NOT 改写或摘要原文本身。界面可见的工具卡片 MUST 继续显示完整结果，与模型看到的历史可以不同。

#### Scenario: 最近轮次保持原文

- **WHEN** 模型在最近两轮读过技能全文与一条角色记录
- **THEN** 下一轮重建的历史仍逐字包含这两份正文，不含 stub

#### Scenario: 早期工具结果指针化

- **WHEN** 第 1 轮读过一份长技能全文，会话推进到第 20 轮且历史超出预算
- **THEN** 该轮工具结果变为一行 stub，写明工具名与用 `read_skill` 重取，且不出现被改写过的正文片段

#### Scenario: 界面不受指针化影响

- **WHEN** 某条工具结果已指针化后用户回看该轮
- **THEN** 工具卡片仍显示当时的完整结果

### Requirement: 历史仅在超预算时压缩且压缩必须可见

历史 SHALL 随会话增长，MUST NOT 仅因轮数增加而丢弃消息。仅当重建后的历史超过预算时，系统 SHALL 依次采用：指针化更早工具结果、摘要化更早轮次、拒绝发送并给出可操作出路。压缩事实 MUST 可观测，MUST 在会话诊断信息中报告本轮送入规模与被压缩条数。

#### Scenario: 超过预算先指针化

- **WHEN** 重建后的历史超过预算
- **THEN** 系统优先指针化更早工具结果，用户与助手的正文消息不因此被删除

#### Scenario: 指针化后仍超预算

- **WHEN** 指针化之后历史仍超过预算
- **THEN** 系统摘要化更早轮次并在诊断信息中标注摘要范围，最近轮次仍保持原文

#### Scenario: 压缩规模可观测

- **WHEN** 某一轮发生了压缩
- **THEN** 会话检查器显示本轮送入的字符规模、指针化的条数与摘要化的轮数

## MODIFIED Requirements

### Requirement: 系统提示与历史可用性一致

system 中若声明「已读过的技能全文可不再重复读取」，则该技能正文 MUST 在同一轮送入模型的历史中真实存在。当历史已发生指针化或摘要化时，system MUST NOT 继续声明省读能力，MUST 改为指示模型用相应读工具重新取。

#### Scenario: 指针化生效的轮次

- **WHEN** 第 1 轮读过的技能正文已指针化，第 20 轮构造 system
- **THEN** system 不含「已读过可不再重复读取」，而是指示需要时用 `read_skill` 重取

#### Scenario: 第二轮检查承诺与历史

- **WHEN** 第 1 轮读过技能全文，第 2 轮的 system 含「已读过可不再重复读取」
- **THEN** 第 2 轮送入模型的历史包含该技能完整正文

### Requirement: 上下文超限必须给出可操作出路

上游因上下文长度拒绝请求时，系统 SHALL 先按当前预算策略压缩历史后重试一次，MUST NOT 直接结束会话。重试仍被拒绝时，系统 MUST 以可读中文说明本次会话上下文已满、已尝试压缩，并建议新建会话；MUST NOT 只把渠道原始报文原样呈现，MUST NOT 静默丢弃历史后继续。

#### Scenario: 上游返回上下文超限

- **WHEN** 送模型的请求超过渠道上下文窗口，渠道返回错误
- **THEN** 系统先在压缩后重试一次，而不是直接把原始报文呈现给用户

#### Scenario: 压缩重试成功

- **WHEN** 首次请求因上下文超限被拒绝，压缩后的历史可以送入
- **THEN** 本轮继续完成，界面提示发生了上下文压缩，用户不需要新建会话

#### Scenario: 压缩后仍超限

- **WHEN** 压缩后的历史仍超过渠道上下文窗口
- **THEN** 界面显示可读说明，指出已尝试压缩并建议新建会话，同时说明历史仍保留在侧栏

#### Scenario: 超限后用户新建会话

- **WHEN** 用户在提示后新建一个会话
- **THEN** 新会话从空历史开始，原会话的消息在侧栏仍可打开与阅读

## REMOVED Requirements

### Requirement: 历史工具结果不做长度裁剪

**Reason**: 全量原文重放会让长会话稳定撞上渠道上下文窗口，而这正是本变更要消除的失败。改为「最近轮次保真 + 更早工具结果指针化」，原文不被改写且可重取。

**Migration**: 需要逐字保留的近期内容仍在最近轮次原文中；更早内容由 stub 指明读工具，模型按需重取。界面历史与持久化内容不变。

### Requirement: 历史不按轮次或总量丢弃

**Reason**: 与「超预算必须压缩」的新策略冲突；旧要求不允许任何折叠，导致超限只能靠用户新建会话。

**Migration**: 历史仍随会话增长且不按轮数丢弃；仅在超过预算时按「指针化 → 摘要化 → 拒绝发送」的顺序压缩，并在诊断信息中报告压缩范围。
