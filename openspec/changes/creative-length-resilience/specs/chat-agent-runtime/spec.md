# Spec Delta

## ADDED Requirements

### Requirement: 输出长度上限必须续写而不是终止

模型调用因输出长度上限结束时，运行时 SHALL 保留已生成的正文并在同一运行内继续，MUST NOT 直接把该轮当作失败。无工具调用的续写 MUST 追加一条「从断点继续、不要重复已写内容」的推动消息后重新请求。续写次数 MUST 有上限，并 MUST 与普通轮次共享总时长与内部步数安全阀。

#### Scenario: 正文被截断后续写

- **WHEN** 模型在写到一半时因长度上限结束，且没有工具调用
- **THEN** 已生成正文保留在界面与历史中，运行自动继续，后续正文不重复前文，最终内容首尾相接

#### Scenario: 续写达到次数上限

- **WHEN** 同一轮连续续写达到次数上限后仍因长度上限结束
- **THEN** 运行以可读错误结束，说明已保留生成部分的位置，并提示可让模型继续往下写或缩小单次产出

#### Scenario: 续写期间用户取消

- **WHEN** 用户在续写过程中取消
- **THEN** 不再发起新的模型请求，已生成内容保留，运行以已取消结束

### Requirement: 工具参数被截断必须重新请求而不是执行半截参数

当结束原因为输出长度上限且响应同时包含工具调用时，运行时 MUST NOT 执行这些调用，MUST NOT 把不完整参数当作模型错误呈现。运行时 SHALL 向模型发出可执行指令（缩小单次输出或改用分批写入）后重新请求，并向界面发出可见提示。

#### Scenario: 半截工具参数不执行

- **WHEN** 一次模型响应因长度上限结束，且带有一个参数不完整的工具调用
- **THEN** 该工具不执行，不产生工具卡片结果，也不写入任何数据

#### Scenario: 重新请求时给出拆批指令

- **WHEN** 运行时对上述响应发起重新请求
- **THEN** 推动消息明确要求缩小单次 payload 或使用写入工具的分批参数，而不是只要求「重试」

#### Scenario: 重试成功后只留一条工具回执

- **WHEN** 重新请求返回完整工具调用并成功执行
- **THEN** 界面只显示一条对应工具卡片，不残留被截断那次调用的卡片

### Requirement: 续写与截断必须对用户可见

续写与工具参数截断重试 SHALL 在本次运行的可见提示与线程记录中留下说明，MUST NOT 静默发生。该说明 MUST NOT 以用户消息气泡的形式伪装成用户输入。

#### Scenario: 界面提示续写

- **WHEN** 运行时发起一次续写
- **THEN** 界面出现一条说明「模型输出达到长度上限，正在继续」的提示，且不新增用户消息气泡

#### Scenario: 重新打开线程

- **WHEN** 用户重新打开发生过续写的线程
- **THEN** 续写提示仍在时间线上，历史消息顺序与最终内容可读

## MODIFIED Requirements

### Requirement: 运行上限与取消必须由运行时统一实现

每次聊天运行 SHALL 受总时长上限约束；超时 MUST 终止上游请求与进行中的工具。用户取消 MUST 立即停止产生新事件，MUST NOT 继续执行后续工具。运行时 MUST 自身响应取消信号，MUST NOT 依赖底层只中止当前请求就假定循环已停止。工具轮次上限 MUST 只作为内部安全阀，MUST NOT 作为用户可配置的产品设置。长度上限触发的续写 MUST 计入同一次运行的总时长与内部步数安全阀，MUST NOT 绕过或重置这些上限。

#### Scenario: 运行超时

- **WHEN** 运行超过总时长上限
- **THEN** 上游请求与进行中的工具被终止，运行以超时错误结束

#### Scenario: 用户取消

- **WHEN** 用户在模型流或工具执行中取消
- **THEN** 后续工具不再执行，不再产生新的文本或工具事件

#### Scenario: 底层只中止当前请求

- **WHEN** 底层中止能力只覆盖当前模型流
- **THEN** 运行时自身保证循环退出，不继续调度下一轮

#### Scenario: 续写不延长总时长

- **WHEN** 一次运行因多次续写接近总时长上限
- **THEN** 运行仍按原总时长上限结束，续写不获得额外时间
