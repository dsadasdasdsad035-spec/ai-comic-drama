# Spec Delta

## ADDED Requirements

### Requirement: 外部工具可用性可探测

系统 SHALL 在发起拆解前探测 `rea-video` 可执行文件是否存在并可执行，并报告其可用状态。不可用时 MUST 返回可读原因与安装命令，MUST NOT 自动安装依赖，也 MUST NOT 用其他能力冒充拆解结果。

#### Scenario: 未安装给出安装指引

- **WHEN** 用户点击反推但系统找不到 `rea-video` 可执行文件
- **THEN** 界面显示未安装原因与可复制的安装命令，反推不启动

#### Scenario: 已安装显示可用

- **WHEN** 可执行文件存在且 `--help` 成功返回
- **THEN** 探测结果为可用，反推入口可发起

### Requirement: 拆解是后台作业

拆解 MUST 以异步作业执行，创建后立即返回作业标识。作业状态 MUST 可通过轮询查询，至少区分运行中、完成、失败与已取消，并包含已运行时长与失败原因。同一作业 MUST NOT 在完成后被再次执行。

#### Scenario: 创建后立即返回

- **WHEN** 用户对一条视频发起拆解
- **THEN** 系统返回作业标识，界面进入运行中状态并持续展示进度

#### Scenario: 失败可读

- **WHEN** 拆解子进程以非零状态退出
- **THEN** 作业状态为失败，原因包含子进程输出的末段可读信息，MUST NOT 写入案例

### Requirement: 作业有超时、停滞检测与取消

拆解作业 MUST 有总超时与无输出停滞上限，超限 MUST 终止子进程并标记失败。用户 MUST 能取消运行中的作业；取消 MUST 终止子进程，且 MUST NOT 留下案例记录或半份产物。

#### Scenario: 停滞被终止

- **WHEN** 子进程在约定时间内没有任何新输出
- **THEN** 系统终止该作业并标记失败，提示本次未产出

#### Scenario: 取消不落库

- **WHEN** 用户在运行中取消作业
- **THEN** 作业标记为已取消，案例库不新增该作业的记录

### Requirement: 拆解档位映射为显式参数

系统 SHALL 提供至少两档拆解深度，并把它映射为明确的命令行参数集合。默认档位 MUST 关闭需要额外模型下载的步骤，并在发起前显示本次会触发哪些下载与预计额外耗时。

#### Scenario: 快速档不触发模型下载

- **WHEN** 用户以默认档位发起拆解
- **THEN** 命令行参数关闭音轨分离、本地语音识别、说话人分离、包装层与特殊时刻分析

#### Scenario: 发起前显示下载影响

- **WHEN** 用户切换到完整档位
- **THEN** 界面列出会触发的模型下载与预计体积，用户可切回快速档再发起

### Requirement: 视觉模型配置从应用设置注入

拆解 MUST 能从应用已有的视觉模型设置自动注入模型地址、密钥与模型名，用户无需在别处重复配置。密钥 MUST NOT 出现在作业列表、日志或界面返回值中。视觉模型不可用或不支持视频输入时 MUST 降级为仅关键帧判定，并在结果中标注降级原因。

#### Scenario: 自动注入视觉模型

- **WHEN** 应用已配置视觉模型且用户未单独填写拆解模型设置
- **THEN** 作业使用应用设置中的视觉模型发起，界面不显示密钥

#### Scenario: 视觉模型不可用

- **WHEN** 视觉模型未配置或全部调用失败
- **THEN** 拆解仍完成，结果标注视觉判定未生效并说明原因

### Requirement: 拆解产物的逐镜结构与两段提示词

作业成功后系统 SHALL 解析拆解产物，生成逐镜结构：时间范围、制作方式、置信度、判定依据与两段提示词。制作方式 MUST 取值于固定分类集合。缺少提示词的镜头 MUST 明确标注为缺失，MUST NOT 用空字符串冒充。

#### Scenario: 逐镜字段齐全

- **WHEN** 一条视频拆解成功
- **THEN** 每镜包含时间范围、制作方式与置信度，并标明两段提示词是否存在

#### Scenario: 制作方式超出分类集合

- **WHEN** 产物给出不在固定分类集合内的制作方式
- **THEN** 系统按未知处理并保留原始值供查看，MUST NOT 静默映射为相近分类

### Requirement: 拆解证据帧可查看

系统 SHALL 把拆解产出的关键帧与总览图复制到应用可读的媒体位置并返回站内地址。证据帧 MUST 按镜头可定位；复制失败 MUST 只影响该镜的证据展示，MUST NOT 使整个作业失败。

#### Scenario: 证据帧可打开

- **WHEN** 用户展开某镜的证据
- **THEN** 界面显示该镜的关键帧与总览图，地址为站内可读地址

#### Scenario: 证据复制失败

- **WHEN** 某些证据帧复制失败
- **THEN** 作业仍标记成功，失败镜头标注证据缺失

### Requirement: 拆解报告以禁脚本沙箱预览

系统 SHALL 允许在界面内预览拆解生成的 HTML 报告，但 MUST 在禁脚本的沙箱 iframe 中呈现（`sandbox` 不含 `allow-scripts`），MUST NOT 让报告脚本在应用源下执行。报告 MUST 只加载随产物复制的同目录资源，MUST NOT 允许外部网络请求。报告资源复制失败时 MUST 保留结构化详情并标注报告不可预览。

#### Scenario: 报告在沙箱内预览

- **WHEN** 拆解完成且报告已复制到可读目录
- **THEN** 界面在沙箱 iframe 中展示报告，图片与音频从同目录相对路径加载

#### Scenario: 报告含脚本时不执行

- **WHEN** 报告 HTML 内含 `<script>` 或内联事件处理器
- **THEN** 沙箱阻止其执行，页面结构与样式仍可见

#### Scenario: 报告资源缺失

- **WHEN** 报告或其引用资源复制失败
- **THEN** 界面仍展示逐镜结构化详情，并标注该作业的报告不可预览

### Requirement: 并发与磁盘约束

系统 MUST 限制同时运行的拆解作业数量，超出的作业 MUST 排队而不是并发执行。单作业产物 MUST 有体积上限，超限 MUST 终止并失败。作业目录 MUST 落在可写状态根下，MUST NOT 写入随代码分发的只读目录。

#### Scenario: 排队而非并发

- **WHEN** 用户连续发起超过并发上限的作业
- **THEN** 超出部分显示排队状态，运行中的作业数量不超过上限

#### Scenario: 产物超限

- **WHEN** 单作业产物体积超过上限
- **THEN** 作业失败并提示体积超限，MUST NOT 写入案例
