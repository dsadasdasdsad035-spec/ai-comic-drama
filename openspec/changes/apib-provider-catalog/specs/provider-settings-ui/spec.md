# Spec Delta

## Purpose

让设置页按渠道、模型与默认路由组织配置，减少重复的渠道卡和模型行，并让目录同步、缺 Key、余额不足与失效默认模型都能被直接看见和处理。

## ADDED Requirements

### Requirement: 设置页按渠道、模型、默认路由分组

系统 SHALL 在设置页提供“渠道、模型、默认路由”三个主分组，并把 Agent 上限、计价、技能与数据存储放入“高级”分组；窄屏 MUST 折叠为可横向滚动的标签栏。

#### Scenario: 桌面端切换分组

- **WHEN** 用户在设置页点击左侧“模型”
- **THEN** 右侧只显示模型库，不显示渠道卡或默认路由

#### Scenario: 窄屏

- **WHEN** 视口宽度不足以容纳左侧导航
- **THEN** 分组切换变为横向标签栏，内容仍可访问

### Requirement: 每个渠道只呈现一张渠道卡

系统 SHALL 为每个渠道只渲染一张卡，卡内同时显示该渠道的全部用途、Base URL、Key 状态、模型数量、测试与目录同步入口。用户移除某个用途时 MUST 提示受影响的模型数量。

#### Scenario: 多渠道用途

- **WHEN** 一个渠道同时承接文本、图像与视频
- **THEN** 该渠道只出现一张卡，三个用途以标签形式同时显示

#### Scenario: 移除用途

- **WHEN** 用户取消一个仍有模型的渠道用途
- **THEN** 系统提示该用途下有 N 个模型将不可选，并由用户确认

#### Scenario: 删除渠道

- **WHEN** 用户删除一个仍有模型的渠道
- **THEN** 系统提示引用该渠道的模型数量，并由用户确认

### Requirement: 添加渠道先选预设

系统 SHALL 在新增渠道时先提供预设选择，至少包含 APIMart、字节方舟、Agent Plan、MiniMax、DeepSeek、OpenAI 兼容、ElevenLabs、火山 TTS 与自定义；选择预设 MUST 自动填充渠道类型、Base URL、用途与 Key 占位提示。

#### Scenario: 选择 APIMart

- **WHEN** 用户选择 APIMart 预设
- **THEN** 新渠道的类型为 APIMart、Base URL 为 APIMart 网关、用途为文本/图像/视频/音频

#### Scenario: 自定义渠道

- **WHEN** 用户选择自定义
- **THEN** 系统创建空白渠道，由用户填写类型、Base URL 与用途

#### Scenario: 已存在同名预设

- **WHEN** 用户再次添加一个已存在的预设渠道
- **THEN** 系统提示已存在，不创建重复渠道

### Requirement: 模型库一行一个模型

系统 SHALL 在模型库中每个模型只显示一行，行内展示显示名、模型 ID、渠道、能力标签、来源与运行状态；MUST 支持按显示名或模型 ID 搜索、按渠道与能力筛选、编辑能力、删除。

#### Scenario: 多能力模型

- **WHEN** 一个模型同时声明文本、高质量文本与视觉
- **THEN** 模型库只显示一行，行内显示三个能力标签

#### Scenario: 搜索

- **WHEN** 用户输入模型 ID 的一部分
- **THEN** 列表只保留匹配的模型

#### Scenario: 按能力筛选

- **WHEN** 用户选择“视觉”筛选
- **THEN** 列表只显示声明了视觉能力的模型

#### Scenario: 目录未接入模型

- **WHEN** 一个模型存在于目录但未接入运行时
- **THEN** 行内显示“未接入运行时”，且该模型不出现在默认路由的可选列表中

### Requirement: 默认路由使用渠道到模型的两级选择

系统 SHALL 为每个能力提供先选渠道、再选该渠道下支持该能力的模型的两级选择；切换渠道 MUST 把模型重置为该渠道的第一个可用模型或空值；没有可用模型的渠道 MUST 禁用。

#### Scenario: 选择渠道后收窄模型

- **WHEN** 用户在“图像”能力选择 APIMart 渠道
- **THEN** 模型下拉只列出 APIMart 下支持图像能力的模型

#### Scenario: 渠道没有可用模型

- **WHEN** 某渠道没有支持当前能力的模型
- **THEN** 该渠道在下拉中禁用，并提示没有可用模型

#### Scenario: 环节跟随文本默认

- **WHEN** 用户没有为某个文本环节单独指定模型
- **THEN** 该环节显示“跟随文本默认”，并展示当前解析到的模型

#### Scenario: 默认模型失效

- **WHEN** 某能力的默认模型已被删除或未接入运行时
- **THEN** 该行显示失效警告，生成前必须重新选择

### Requirement: 目录同步弹窗可预览与选择

系统 SHALL 在目录同步弹窗中按分类展示数量、已存在与新增标记、搜索与全选；同步前 MUST 展示能力映射预览，同步后 MUST 显示新增、更新、跳过与失败数量。

#### Scenario: 首次同步

- **WHEN** 用户打开一个尚未同步过的渠道目录
- **THEN** 弹窗列出全部目录条目，并标记哪些将被新增

#### Scenario: 已存在模型

- **WHEN** 目录条目已经存在于模型库
- **THEN** 弹窗标记为已存在，并允许用户仍然选择更新

#### Scenario: 余额不足

- **WHEN** 目录请求返回 402
- **THEN** 弹窗显示余额不足与充值提示，不展示空的“成功”状态

#### Scenario: 部分失败

- **WHEN** 同步中部分条目失败
- **THEN** 弹窗分别显示成功与失败数量，并列出失败模型 ID

### Requirement: 设置页显示失效状态并固定保存

系统 SHALL 在设置页顶部显示缺 Key 渠道、余额不足渠道与失效默认模型的数量与入口；有未保存修改时 MUST 显示提示，保存操作 MUST 固定在可视区域。

#### Scenario: 缺 Key

- **WHEN** 某个渠道没有 Key 且没有可用的环境变量 Key
- **THEN** 状态条显示缺 Key 渠道数量，点击后定位到该渠道卡

#### Scenario: 失效默认模型

- **WHEN** 某能力的默认模型不存在或不可运行
- **THEN** 状态条显示失效数量，点击后定位到该能力的默认路由行

#### Scenario: 未保存修改

- **WHEN** 用户修改任意渠道或模型但尚未保存
- **THEN** 顶部显示“未保存”，保存按钮保持可见

#### Scenario: 保存成功

- **WHEN** 用户点击保存且服务端返回成功
- **THEN** 未保存提示消失，状态条按新设置重新计算

### Requirement: 旧设置加载后不重复

系统 SHALL 在加载旧设置时兼容缺少用途的渠道与单能力模型；新增 APIMart 预置 MUST NOT 改变已有默认模型；同一渠道 MUST NOT 因多个用途被重复渲染。

#### Scenario: 旧渠道缺少用途

- **WHEN** 旧设置中的渠道没有用途字段
- **THEN** 系统按渠道类型推断用途，并只渲染一张渠道卡

#### Scenario: 已有默认模型

- **WHEN** 旧设置中已保存文本或图像默认模型
- **THEN** 升级后继续使用已保存的默认值，不被 APIMart 预置覆盖

#### Scenario: 预置只合并一次

- **WHEN** 用户删除 APIMart 预置后重新启动
- **THEN** 系统不反复把已删除的预置加回来

### Requirement: 设置页沿用现有主题与键盘可达

系统 SHALL 使用现有 Cinema Dark 设计 token 与焦点环；新增控件 MUST 有可见标签并可通过键盘操作；MUST NOT 引入与现有主题冲突的全局颜色变量。

#### Scenario: 键盘操作

- **WHEN** 用户使用 Tab 与方向键操作渠道卡和模型库
- **THEN** 焦点可见，控件可按键盘完成选择与提交

#### Scenario: 主题切换

- **WHEN** 用户在浅色与深色主题之间切换
- **THEN** 设置页文字、边框与状态色保持可读，不出现硬编码背景

#### Scenario: 对比度

- **WHEN** 设置页显示辅助说明与状态文字
- **THEN** 正文与辅助文字满足现有风格指南的对比度基线
