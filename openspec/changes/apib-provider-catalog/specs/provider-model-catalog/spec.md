# Spec Delta

## Purpose

让设置页能从渠道动态拉取模型目录，把分类与能力标签映射成本地模型表条目，并在重复同步时保持幂等、不产生重复行。

## ADDED Requirements

### Requirement: 从渠道读取模型目录

系统 SHALL 通过渠道配置的 Base URL 与 Key 请求 `GET /models?expand=category`，并把返回的 `data` 数组作为目录条目；条目 MUST 至少包含模型 ID，MAY 包含分类、能力标签与支持的端点类型。

#### Scenario: 读取成功

- **WHEN** 渠道返回 200 且 `data` 是数组
- **THEN** 系统返回目录条目，并保留模型 ID、分类与能力标签

#### Scenario: 目录为空

- **WHEN** 渠道返回 200 但 `data` 是空数组
- **THEN** 系统提示该渠道没有可用模型，且不写入任何模型

#### Scenario: 响应不可解析

- **WHEN** 渠道返回非 JSON 或缺少 `data` 数组
- **THEN** 系统返回可读的目录格式错误，且不写入任何模型

### Requirement: 目录分类映射到能力

系统 SHALL 把 chat 映射为文本与高质量文本，把带视觉标签的 chat 额外映射为视觉；把 image 映射为图像与三视图；把 video 映射为视频；把 TTS 类 audio 映射为配音。无法映射的条目 MUST 标记为未接入，MUST NOT 静默丢弃。

#### Scenario: 对话模型带视觉标签

- **WHEN** 目录条目分类为 chat 且能力标签包含视觉
- **THEN** 同步候选同时提供文本、高质量文本与视觉三个能力

#### Scenario: 图像模型

- **WHEN** 目录条目分类为 image
- **THEN** 同步候选提供图像与三视图能力

#### Scenario: 视频模型

- **WHEN** 目录条目分类为 video
- **THEN** 同步候选提供视频能力，并保留参考视频能力标记

#### Scenario: 配音模型

- **WHEN** 目录条目分类为 audio 且属于 TTS 模型
- **THEN** 同步候选提供配音能力

#### Scenario: 转写模型

- **WHEN** 目录条目分类为 audio 但属于转写模型
- **THEN** 同步候选把它标记为未接入，不提供任何可运行能力

### Requirement: 幂等合并且不删除未选模型

系统 SHALL 以“渠道 + 模型 ID”作为稳定标识合并目录条目；重复同步 MUST NOT 产生重复行，MUST 保留用户已修改的显示名、备注与高级参数，MUST NOT 删除用户本次未勾选的已有模型。

#### Scenario: 首次同步

- **WHEN** 模型表中没有该渠道的目录条目
- **THEN** 系统按用户勾选新增模型，每个模型只新增一行

#### Scenario: 重复同步

- **WHEN** 用户对同一批模型再次执行同步
- **THEN** 系统更新已有行的能力与标签，不新增重复行

#### Scenario: 保留用户修改

- **WHEN** 用户已修改某个模型的显示名或备注后再次同步
- **THEN** 系统保留这些修改，只更新目录提供的字段

#### Scenario: 未勾选的已有模型

- **WHEN** 用户本次只勾选目录中的一部分模型
- **THEN** 系统保留模型表中未勾选的已有模型，不执行删除

### Requirement: 目录错误可读且不落半成品

系统 SHALL 区分 402 余额不足、401/403 鉴权失败、网络失败与目录格式错误；任一失败 MUST NOT 写入部分模型。

#### Scenario: 余额不足

- **WHEN** 渠道返回 402
- **THEN** 系统提示“余额不足，充值后可同步”，且不写入模型

#### Scenario: 鉴权失败

- **WHEN** 渠道返回 401 或 403
- **THEN** 系统提示 Key 无效或无权限，且不写入模型

#### Scenario: 网络失败

- **WHEN** 请求超时或连接失败
- **THEN** 系统提示无法连接渠道，且不写入模型

#### Scenario: 部分条目缺字段

- **WHEN** 响应中部分条目缺少模型 ID
- **THEN** 系统跳过这些条目并报告跳过数量，其余合法条目仍可同步

### Requirement: 同步结果可核对

系统 SHALL 返回新增、更新、跳过与失败的数量，并按模型 ID 给出失败原因；设置页 MUST 能显示这些结果。

#### Scenario: 混合结果

- **WHEN** 一次同步中同时有新增、已存在和失败条目
- **THEN** 系统分别显示新增、更新、跳过与失败的数量

#### Scenario: 全部失败

- **WHEN** 所有条目都因缺少模型 ID 或渠道错误失败
- **THEN** 系统显示失败总数与首个可读原因，且不写入任何模型
