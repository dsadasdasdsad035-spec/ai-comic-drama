# Design

## Context

见 [proposal.md](proposal.md)。当前事实：

- `runStageAgent` 的默认 `maxSteps` 是 16，且生产调用点只有创意工作室；3D 走 `engine.ts`，使用 512 的独立轮次计数。
- 工作台聊天已在 `0f21f45` 移除，16 这个值没有随消费者变化调整。
- 创意运行的总时长是 `stageRunner` 内硬编码的 180 秒；设置页的 `agentLimits.totalSeconds` 只被 `engine.ts` 读取。
- `finishTurn` 在工具结果落定之后调用，因此第 16 轮工具会执行，但下一轮模型请求被 `{ action: 'end' }` 掐掉，模型没有机会总结。
- 创意历史按 Pi 原文全量送入、不折叠；`contextWindow` 为 0，没有主动裁剪。
- pi-agent-core 自身没有轮次上限；3D 的 512 是应用层计数器。

## Goals / Non-Goals

**Goals:**

- 生产路径不再存在默认的工具轮次预算，也不再出现「工具循环达到 N 步上限」。
- 创意会话与 3D 共用设置页的总时长预算，默认 300 秒、范围 60–1800。
- 保留显式工具轮次上限的能力，供测试或将来需要主动保护的面使用。
- 超时仍是可靠退出路径：渠道挂住不 settle 时，运行器必须能按时结束。

**Non-Goals:**

- 不引入循环检测、重复调用检测或"无进展"判定。
- 不改变工具粒度，也不把 `read_asset_detail` 改成批量读。
- 不做历史折叠、上下文裁剪或 token 预算。
- 不新增设置项、接口或数据库字段。
- 不改变专家白名单、技能正文或写回契约。

## Decisions

### 1. 默认不设步数上限，保留显式 `maxSteps`

`maxSteps` 保持可选参数；未传时不让步数参与终止判断。`finishTurn` 仍计数 `steps`，用于 `RunStageAgentResult.steps` 与事件诊断。显式传入 `maxSteps` 时保留原有的 `{ action: 'end' }` 与「工具循环达到 N 步上限」错误，供 `tests/stage-agent.ts` 覆盖上限路径；生产调用点不传该参数，因此该错误不会出现在用户界面。

备选：

- **提高到 64 / 512**：能缓解误杀，但仍是任意数字，且继续把内部计数包装成产品预算；不选。
- **彻底删除 `maxSteps`**：API 更干净，但 `tests/stage-agent.ts` 已用 8 和 2 覆盖上限路径，删除会丢掉一块测试能力；不选。
- **保留 16 但在到点时先让模型总结**：交互更好，但仍会把长任务截在 16 轮；用户的目标是去掉上限，不是改善截断文案；不选。

### 2. 创意总时长从设置读取

`CreativeStudio` 已持有 `settings`，在发送时调用 `resolveAgentLimits(settings)` 得到 `totalMs` 并传给 `runStageAgent`。未加载或未配置时自然回落到默认 300 秒。`agentLimits` 的数据形状、范围校验和服务端持久化不变，只把注释与适用范围从「3D agent」改为「所有聊天」。

备选：

- **保持 180 秒硬编码**：去掉步数后，超过 3 分钟的专家任务会立刻变成超时失败；不选。
- **固定改成 300 秒**：能对齐默认值，但用户在设置页改 600 或 900 时创意仍不生效，预算口径继续分裂；不选。
- **完全去掉总时长**：`setTimeout` 是渠道挂住时唯一的退出保证，去掉会让运行永久悬挂；不选。

### 3. 超时文案说明可继续，但不自动续跑

`timeoutMessage` 改为说明「已完成部分保留，可回复继续」。不自动追加内部"继续"消息：

- 自动续跑会掩盖真实的长耗时任务，也让一轮费用翻倍；
- 创意的历史保存了已完成的工具结果，用户手动发一句即可在新的时间窗内继续；
- 保持"一次用户消息 = 一个时间窗"的简单心智模型。

### 4. `steps` 仅作为诊断数据

`RunStageAgentResult.steps` 与 `progress.turn` 继续工作，便于以后判断模型是否在空转。它不参与任何终止判断。

## Risks / Trade-offs

- **[症状转移]** 任务若本来超过总时长，报错从「16 步上限」变成「运行超时」。→ 错误文案说明可调设置与继续；设置范围上限 1800 秒足以覆盖长任务。
- **[成本与上下文膨胀]** 去掉步数上限后，快速读工具可能在 300 秒内跑几十轮，每轮都重发历史与工具结果。→ 时间上限兜底；工具结果已有 `boundJson` 一类的体积约束；上下文裁剪与无进展检测留给后续变更。
- **[重复调用直到超时]** 模型可能反复读同一张表。→ 本次不做检测；超时文案与 `steps` 诊断可帮助定位；后续可加连续相同 `(tool, args)` 检测。
- **[测试语义变化]** 默认不再截断，依赖 16 的隐式断言会失效。→ 保留显式 `maxSteps` 用例，新增超过 16 轮仍收尾的用例；全量跑 `tests/stage-agent.ts`。
- **[设置来源误解]** 用户可能以为「Agent 运行上限」只影响 3D。→ 同步 `docs/scene-agent-engine.md` 与设置页说明，明确所有聊天共用。

## Migration Plan

1. 运行时先改为默认无步数上限，保留显式参数；此时创意仍用 180 秒，行为可回滚。
2. 创意接入 `resolveAgentLimits`，默认值变为 300 秒。
3. 更新文案、文档与测试。
4. 回滚：恢复默认 16 与硬编码 180 即可；无数据迁移，设置中的 `totalSeconds` 始终兼容。

## Open Questions

- 是否在后续变更中加入「连续相同工具调用」检测，以替代已删除的硬步数保护？该问题不影响本次实现；创意继续与 3D 共用默认 300 秒，用户可在设置页调到 1800 秒。
