# Proposal

## Why

创意工作室的通用 Pi 运行器仍保留 16 步的工具轮次上限。该数字来自已移除的工作台聊天，对专家模式这种「先读项目表、读技能、再逐条校验写回」的多产物流程明显过低：模型在第 16 轮工具结果落定后直接结束，连最终总结都没有机会生成，用户看到「工具循环达到 16 步上限」。步数不是用户能理解的预算；同一仓库的 3D 运行器已改为由总时长约束，并用高值内部安全阀兜底。

创意会话的总时长还硬编码为 180 秒，设置页「Agent 运行上限」（默认 300 秒、范围 60–1800）实际只作用于 3D。去掉步数上限后，若不接管时间预算，问题只会从「步数不够」变成「运行超时」。

## What Changes

- 通用运行器 `runStageAgent` 默认不再设置工具轮次上限；`maxSteps` 保留为显式可选参数，仅供测试或需要主动保护的面使用，生产调用点不再传。
- 删除生产默认的 16 步终止与用户可见的「工具循环达到 N 步上限」；显式 `maxSteps` 仍可触发该错误，但只用于测试与诊断，不作为产品行为。
- `steps` 计数保留，仅用于事件与诊断。
- 创意会话从设置读取 `agentLimits.totalSeconds` 并换算为 `totalMs` 传给运行器，不再硬编码 180 秒；未配置时沿用既有默认值 300 秒。
- 超时错误补充可操作说明：已完成部分保留，可回复「继续」接着做。
- 同步 `docs/scene-agent-engine.md` 中「工作台 16、3D 512」的过时描述。
- 运行循环的终止条件收敛为：模型不再返回工具调用、用户取消、总时长到点、渠道错误。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `chat-agent-runtime`: 「运行上限与取消必须由运行时统一实现」改为以总时长与取消作为唯一产品预算；移除默认工具轮次上限及其面向用户的错误，内部如保留安全阀不得作为步骤预算展示。

## Impact

- 运行时：`src/agent/pi/stageRunner.ts`（默认预算、终止分支、超时文案）。
- 创意会话：`src/creative/CreativeStudio.tsx`（读取设置并把 `totalMs` 传入）。
- 设置口径：`src/agent/agentLimits.ts` 的注释与适用范围由「3D agent」扩展为所有聊天；数据形状与范围不变，设置页无需新增控件。
- 测试：`tests/stage-agent.ts` 保留显式 `maxSteps` 用例，新增「超过 16 轮工具调用仍能收尾」用例。
- 文档：`docs/scene-agent-engine.md`；`openspec/specs/chat-agent-runtime/spec.md` 随 delta 归档更新。
- 不新增依赖、数据库表或接口；不改动模型、工具 schema 或项目数据。
- 本次不引入循环/无进展检测，也不改变技能正文或专家白名单。
