# Spec Delta

## MODIFIED Requirements

### Requirement: 封面按比例准备

系统 SHALL 允许从成片抽帧或上传图片准备封面，并按 9:16、16:9、3:4、4:3 四档比例分组保存；同一比例只需准备一次并供所有需要的平台复用；所需比例缺失时 MUST 在预检中报告。

无论来源是抽帧还是上传，写入配置的封面 MUST 是服务端可解析的文件引用；MUST NOT 写入只在当前浏览器内存中有效的内联图片数据。配置保存并重新读取后，已准备的封面 MUST 仍指向可读取的文件。

#### Scenario: 从成片选帧

- **WHEN** 用户为 9:16 选择一帧成片画面
- **THEN** 该封面保存为 9:16 分组，需要竖屏封面的平台直接复用

#### Scenario: 上传封面

- **WHEN** 用户上传一张图片作为 16:9 封面
- **THEN** 该封面进入 16:9 分组，替换原封面

#### Scenario: 缺少所需比例

- **WHEN** 已选平台需要 9:16 封面但用户只准备了 16:9
- **THEN** 预检报告缺少竖屏封面，并定位到封面区块

#### Scenario: 新增三比四比例

- **WHEN** 用户为 3:4 上传或选帧封面
- **THEN** 该封面独立成为 3:4 分组，与 9:16 分别保存互不覆盖

#### Scenario: 抽帧封面持久化

- **WHEN** 用户从成片抽帧选为封面，随后刷新页面或重新打开发布台
- **THEN** 该比例仍显示已准备的封面且可预览，预检不报告该比例缺失

#### Scenario: 抽帧按目标比例输出

- **WHEN** 用户为某个比例抽帧，而成片本身是另一种画幅
- **THEN** 保存的封面图片符合所选比例，而不是沿用成片的原始画幅

#### Scenario: 内联图片数据不得进入配置

- **WHEN** 某个封面写入请求携带的是内联图片数据而非文件引用
- **THEN** 系统不把它当作已准备的封面，预检按该比例缺失处理

## ADDED Requirements

### Requirement: 封面比例四档可持久化

发布配置 MUST 能保存并读回 9:16、16:9、3:4、4:3 四档封面；任何一档在保存时 MUST NOT 被静默丢弃。保存与读取使用的比例集合 MUST 与平台能力表声明及封面选择器呈现的比例一致。

#### Scenario: 四档同时保存

- **WHEN** 用户为四档比例分别准备了封面并保存
- **THEN** 重新读取配置时四档全部存在，不出现某一档消失

#### Scenario: 平台只要求非主流比例

- **WHEN** 用户选择的平台只需要 3:4 或 4:3 封面
- **THEN** 该比例能保存成功，预检据此判定通过，而不是始终报告缺失
