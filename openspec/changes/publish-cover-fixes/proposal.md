# Proposal

## Why

完整跑通发布流程后确认：用户在发布台准备的封面，无论在自动草稿还是发布包里，都没有真正到达平台后台。三个断点互相掩盖，现有验收全部使用预置的 9:16 文件路径，因此测试全绿而症状持续：抽帧封面从未落盘、3:4 / 4:3 在保存时被服务端丢弃、适配器执行时根本拿不到封面。用户在平台后台看到的封面只能是平台从视频里自动截的帧，于是反复反馈「视频封面不对」。

## What Changes

- **封面比例白名单前后端统一为四档**：服务端配置规范化目前只接受 `9:16` 与 `16:9`，导致小红书（3:4）与视频号的 3:4 / 4:3 封面在写入与读取时被静默丢弃；改为与前端枚举同源，四档都能持久化。
- **封面产物必须是服务端可解析的文件引用**：
  - 「从成片抽帧」不再把 canvas dataURL 直接写进配置，改为先经 `/api/save-image` 落盘再写入 URL；
  - 助手 `set_cover(source=frame)` 走同一条落盘路径；
  - 抽帧按目标比例裁切，不再总是输出视频原始比例。
- **自动流程必须把已准备的封面上传到平台**：发布队列把按平台的封面路径传给适配器；适配器在保存草稿前完成封面上传或选择；平台不支持自定义封面或选择器未验证时，任务必须明确报告封面未上传，不得把阶段文案写成「填写文案与封面」却只填文案。
- **修正会误导用户的文案与注释**：适配器注释、任务阶段消息、助手回执都不得在封面未实际生效时声称封面已备好或已填写。
- **补齐针对性验证**：四档封面保存/回读、抽帧封面落盘后预检通过、适配器上下文中包含封面、辅助路径与手动路径一致。真实平台选择器仍需登录态人工核对，自动化测试只覆盖到适配器收到的输入与步骤声明。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `publish-workbench`：封面按比例准备的既有要求需要明确「抽帧与上传得到的封面都必须是刷新后仍可用的服务端文件引用」，且四档比例都必须真正持久化，而不只是界面分组。
- `publish-assistant`：配置写工具里的 `set_cover` 需要明确「写入的封面地址必须是服务端可解析、与预检使用同一判定」的地址；助手不得在封面未生效时回执「已准备」。
- `platform-publishing`：新增「自动流程投递已准备封面」的行为要求，并明确无法投递时必须如实报告，不能只上传视频与文案就宣称完成草稿。

## Impact

- 服务端：`server/deliverables.mjs`（封面比例白名单）、`server/publish-queue.mjs`（任务上下文）、`server/publish-adapters.mjs`（封面步骤与 `verified` 状态）、`server/publish-preflight.mjs`（封面可用性判定保持一致）。
- 前端：`src/publish/CoverPicker.tsx`（抽帧落盘、按比例裁切、上传参数）、`src/publish/frames.ts`（裁切能力）、`src/publish/publishTools.ts`（助手抽帧写回）、`src/publish/types.ts`（比例常量单一来源）。
- 数据：无新表、无迁移；已存在的配置里原本就没有 3:4 / 4:3（被丢弃），不需要回填。
- 验证：`verify-publish-*.mjs` 与 `tests/publish-chat.ts` 增加四档持久化、抽帧落盘、适配器上下文断言；真实平台封面上传选择器需要登录态人工验收，且当前 7 个适配器均为 `verified: false`，不应在本变更里擅自标记为已验证。
- 文档：`README.md` 发布台章节与 `docs/creative-studio.md` 的封面说明需要与实现口径一致。
