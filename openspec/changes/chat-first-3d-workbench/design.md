# Design

## Context

当前工作台首次打开镜头时，`buildShot3DContextCatalog` 计算 `catalog.defaults`（首帧/候选图、cast 角色、场景卡、道具、关联素材、文本全开），`SceneCodeWorkbench` 在没有保存选择时直接使用它；同一个 `selectedItems` 同时喂给左侧选择器、聊天 chips 和 `prepareAgent()`。`init()` 在没有代码时会自动调用一次 `generateCode(true)`。画布「一键出片」在没有保存选择时也回落到 `catalog.defaults`（`App.tsx`）。

关键约束：生成代码按稳定素材键（`character:*`、`image:*` 等）取图，键来自 `prepareSceneCodeContext(context)`；预览、试运行、保存、渲染、画布出片都会用同一份工作台 `context` 重新 prepare。因此聊天参考不能是完全独立的第二套素材，否则会出现代码引用的键在后续预览/保存时不存在。See `proposal.md` for motivation.

## Goals / Non-Goals

**Goals:**

- 首次打开无保存选择的镜头时，参考内容从 0 项开始；用户从左侧手工加入。
- 镜头文本进入聊天输入框作为可编辑草稿，不自动发送、不计入参考选择。
- 打开无代码镜头不自动调用代码模型；空状态等待显式生成或聊天。
- 保持一份清单：左侧勾选 = 聊天参考，chip 移除只取消勾选。
- 更新验收脚本覆盖新流程。

**Non-Goals:**

- 不改画布「一键出片」的 `catalog.defaults` 回落；它是显式出片动作。
- 不改 legacy 结构化镜头的只读预览和显式转换。
- 不改 agent 工具集、运行时循环、视频验收和保存协议。
- 不持久化聊天草稿或聊天历史；草稿只在本次工作台会话内存在。
- 不改媒体数量/尺寸限制。

## Decisions

### 1. 一份清单，而不是独立聊天参考

左侧选择就是聊天参考，chips 镜像同一份。独立聊天清单看似更贴合“只给 agent 我加的”，但代码资产键必须在预览/试运行/保存/渲染时都能解析；独立清单需要额外的“沙箱超集/子集合并”规则，复杂且容易在保存后出现缺素材。一份清单让选择、指纹、预览和保存始终一致。

### 2. 工作台初始上下文为空，`catalog.defaults` 留给画布

新增一个“空的初始上下文”（媒体、文本、场次键全空，保留当前镜头的 `dialogueHash` 以便后续台词选择和沿用逻辑），只在工作台没有保存过 `shot3DContext` 时使用。`catalog.defaults` 保持原样，继续服务画布一键出片和既有验收脚本。这样不用改动画布出片质量，也不会让 `verify-3d-context.mjs` 的默认选择断言失效。

### 3. 镜头文本预填输入框

在工作台侧把 `catalog.text` 组合成草稿，通过新 prop 传给 `SceneAgentChat`：

```text
画面：<prompt>
运动：<videoPrompt>
出场角色：<cast>
台词：
<speaker>：<text>
标注：<marks>
```

只包含非空项；`景别/运镜/秒数` 不重复（`get_shot_context` 的 `【镜头】` 元数据行已经有）。已经被选进参考的文本项不预填，避免“上下文一份、输入框又一份”。挂载时若 composer 为空且没有消息，用 `useAui().composer.setText(draft)` 写入一次；不调用 send。用一个 ref 记录已预填，用户清空或发送后不重新填充；切换聊天/代码页签不重复写入。

替代方案是渲染一个受控 textarea；会丢掉 assistant-ui 的自动高度、IME、键盘提交和可访问性，不采用。

### 4. 首次打开不自动生成代码

删除 `init()` 里“无代码且非 legacy 时 `generateCode(true)`”的分支；保留有代码时的基线、试运行和预览。空预览已有「还没有代码」状态和「生成 3D 代码」按钮，直接作为新的首开状态。legacy 分支不变。

替代方案是保留自动生成但改成“只带文本”；仍会在用户开口前花一次模型调用，也和“聊天创建”的主动权冲突，不采用。空预览的「生成 3D 代码」按钮只在已选至少一项参考时出现（预览头部按钮同样在无参考时禁用）；无参考时提示先选择或聊天，避免和“生成前至少选择一项”的守卫冲突。

### 5. 聊天参考条的空状态与文本可见性

chips 继续显示 `selectedItems`，为空时显示“从左侧添加参考”的引导，不显示任何占位素材。文本不作为 chip 展示，因为它不是媒体参考、也不在 `selectedItems` 里；它的可见性由输入框草稿保证。

### 6. `get_shot_context` 描述与 agent 文本来源

默认文本开关全关后，`get_shot_context` 不再返回镜头 prompt/台词；这些内容通过用户发送的聊天消息进入对话。工具描述从“读取当前镜头的文本、参考内容和当前代码摘要”改为“读取当前镜头的元数据、已选参考和当前代码摘要”，避免模型误以为文本会自动出现。

### 7. 验收策略

- 更新 `verify-code-auto-legacy.mjs`：空镜头首次打开断言 0 次代码模型调用、显示空状态；点击「生成 3D 代码」后才产生一次调用并出代码；legacy 转换路径不变。
- 更新 `verify-code-workbench.mjs`：打开工作台后不再无限等待“代码运行中”，先断言空状态，再触发显式生成或使用已有代码。
- 新增 `verify-chat-first-3d.mjs`：首次打开 0 项参考、输入框含镜头文本、无模型调用；勾选一个媒体后聊天 chips 出现；发送后 agent 上下文只含该媒体；移除 chip 后左侧取消勾选。
- 新增 `verify-canvas-code-fallback.mjs`：画布右键“生成调度视频（3D）”在没有保存选择时仍用 `catalog.defaults` 生成代码并渲染，证明本次改动没有影响画布路径。
- 保留 `verify-3d-context.mjs` 对 `catalog.defaults` 的断言，因为画布路径仍使用它。

## Risks / Trade-offs

- [首开体验变化] 不再有自动生成的一版场景，用户需要先选参考或先说话。→ 空状态给出「生成 3D 代码」和聊天两个明确入口，「沿用上一镜」「全选本类」仍可用。
- [老镜头重复文本] 已保存的 `shot3DContext` 文本开关为开时，不预填输入框，避免重复；用户仍可在左侧取消文本选择。
- [沿用上一镜后重复] “沿用上一镜”仍会复制上一镜的文本开关；如果输入框已经预填，同一段文本可能既在参考上下文又在草稿里。→ 保留现有沿用语义（这是用户显式动作），用户可删除草稿或取消对应文本项；预填只在挂载时发生一次。
- [长提示词撑高输入框] 预填可能很长。→ 输入框保持可 resize，并给一个最大高度/滚动；不截断文本，避免丢 brief。
- [清空后误重新填充] 用一次性 ref + 空 composer 条件，发送或清空后不再写回。
- [画布路径不一致] 画布一键出片仍自动选默认素材。→ 明确为本次非目标；如果以后要统一，另开变更。
- [保存后的指纹] 选择、预览、保存仍共用一份 `context`，不会出现聊天用一套、保存用另一套的指纹漂移。

## Migration Plan

无数据迁移。已有 `shot3DContext` 按原样恢复；只有“没有保存选择”的镜头走新的空初始上下文。回滚时恢复 `init()` 的自动生成分支和工作台的 `catalog.defaults` 初始值即可；spec delta 可通过归档回滚。上线前跑更新后的 `verify-code-auto-legacy.mjs`、`verify-code-workbench.mjs`、`verify-chat-first-3d.mjs` 和现有聊天验收脚本。
