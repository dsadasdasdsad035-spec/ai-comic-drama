# Proposal

## Why

角色卡已经积累了做"角色一眼印象"的全部原料：三视图、8 格表情总图、绑定音色与试音样本。但这些资产分散在「三视图 / 表情 / 音色」三个页签里，没有任何地方把它们合成一个可看的整体，也没有任何形态能交付给导演、客户或配音演员。于是角色卡目前只能用于生产，不能用于沟通。

预览不需要新的生成能力，只需要把已有资产按展示目的重新组装；而"能转起来"的 3D 观感，可以用一张八角度总图在纯 CSS 里做到，不必引入真正的 3D 几何。

## What Changes

- 角色卡新增第四页签「预览」，与现有三视图 / 表情 / 音色并列，不替换任何现有页签。
- 新增角色转盘总图（4 列 × 2 行、八个角度）：一次生图得到可插值的角度帧，栅格裁切复用表情总图的归一化坐标机制，失效判定沿用身份锚点指纹语义。
- 新增预览快照派生层：从角色卡生成只读的展示快照，带 `schemaVersion` 与生成时间，不携带任何业务逻辑。
- 新增单一 viewer 实现：一份纯字符串构造的 HTML，应用内以沙箱 iframe 渲染，导出时写成同一个字符串，保证两种形态永不漂移。
- 新增单文件 `.html` 导出：图片压成 WebP 内联，导出的文件断网可直接打开。
- 新增降级链：有转盘总图就转，没有就是静态合成卡；没有试音就不显示播放入口。
- 预览只做展示，不做隐形花费：页签本身 MUST NOT 触发生成或计费，转盘总图只在用户显式点击生成且看到标价后才提交。
- **不做**：真 3D 网格（GLB）、骨骼绑定、AR、预览内的换装或改脸，以及从单图自动建立可动角色。快照中保留 `glbUrl` 位置以便后续增量扩展，但本变更不消费它。

## Capabilities

### New Capabilities
- `character-preview`: 角色卡预览页签、预览快照、八角度转盘、降级链与转盘失效标记
- `character-card-export`: 单文件 HTML 角色卡导出与离线可用性

### Modified Capabilities
（无）

## Impact

- 前端：`src/CharacterCard.tsx`（第四页签与页签栏）、`src/characters.ts`（转盘总图类型与失效函数）、`src/charMap.ts`（持久化字段）、新增 `src/characterPreview/`（快照与 viewer 构建）
- 复用而不改动：`src/expressionCrop.ts` 的归一化栅格裁切逻辑；表情总图线上行为 MUST 保持逐字节等价
- 服务端：无新增接口；`/project-assets/...` 静态托管沿用现状，已有的 `.glb` / `.gltf` MIME 本变更不使用
- 依赖：不新增 npm 依赖；WebP 压缩走浏览器 canvas
- 验收：新增 `verify-character-preview.mjs`（playwright-core），覆盖页签、转盘拖动、试音播放、导出文件离线打开与失效标记
