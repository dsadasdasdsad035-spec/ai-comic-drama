# Design

## Context

动机见 `proposal.md - Why`，行为契约见 `spec.md`。这里只记录会影响实现的结构性事实：

- `CharacterSheet`（`src/characters.ts:106`）已含 `image`（三视图）、`expressionSheet`（4×2 八格，归一化坐标）、`voiceSample`、以及由 `lookEn / palette / keywords` 组成的身份指纹语义。
- **三视图是一张整图**（`TURNAROUND_SUFFIX` 要求三个角度并排），仓库里没有把它切成独立角度帧的能力；直接等分裁切会切到人物。
- 表情总图已经建立了一套可复用的模式：固定栅格 + 0..1 归一化格子坐标 + 生成时记录指纹 + 变化后标 `stale`。
- 前端没有 three.js 依赖；`src/SceneCodeWorkbench.tsx` 里出现的 `THREE.` 只是历史代码字符串。
- 角色卡页签为 `type Tab = 'turnaround' | 'sheet' | 'voice'`（`src/CharacterCard.tsx:74`），页签栏在 1115–1142 行。
- 站内资产以 `/project-assets/...` 路径托管；`fflate` 已用于 zip 导出（`src/creative/expertExport.ts`），但本变更不需要 zip。
- 验收脚本惯例为根目录 `verify-*.mjs` + playwright-core。

## Goals / Non-Goals

**Goals:**

- 预览页签的**唯一数据来源**是一份从角色卡派生的只读快照，快照可被序列化、可版本化。
- 页内预览与导出文件由**同一份 HTML 构造逻辑**产出，避免两套排版。
- 转盘观感来自一张八角度总图，复用既有栅格与失效语义，不新增数据模型范式。
- 预览链路零新增依赖、零隐式花费。

**Non-Goals:**

- 真正的三维几何、骨骼、绑定、AR，以及从单图自动生成可动角色。
- 转盘总图进入分镜参考预算或参与出片。
- 预览内编辑角色（改脸、换装、改文案）；预览只读。
- 服务端新增接口或离线渲染。

## Decisions

### 1. 用「八角度总图」而不是真 3D、视频或三视图硬切

**选择**：一次生图得到 4×2 八角度总图，按归一化格子裁成八帧，预览按角度插值。

**理由**：

- 三视图硬切不可行——三视图是并排整图，等分会切到人物；且只有 0/90/180 三个关键角度，转动必跳帧。
- 环绕视频（现有 Seedance 能力）只能播放，不能拖动；改外观后要重新出视频，成本高于出图。
- image-to-3D 出 GLB 需要新增依赖与生成管线，且自动生成的拓扑与绑定质量不足以进生产（真正的资产仍要 Blender 人工修）。

**备选**：深度视差（单图 + 深度模型）观感更好但依赖额外模型，且头发/轮廓易穿帮，留作后续可选增强。

### 2. 转盘总图作为 `CharacterSheet` 的可选字段

**选择**：新增 `orbitSheet`（8 帧 + 归一化坐标 + `fingerprint` + `stale` + `createdAt`），与 `expressionSheet` 同构，随项目保存。

**理由**：复用现成的持久化、切换项目隔离与失效判定；不必为预览引入新的资产登记体系。旧项目缺该字段时按"无转盘"降级，不需要迁移。

**备选**：生成后只把八张裁好的图塞进通用素材库——会丢失指纹与角度语义，预览无法判断是否过期。

### 3. 栅格裁切新增独立函数，不改 `expressionCrop.ts`

**选择**：把"按归一化坐标从一张总图裁出 N 格"抽成新函数（供转盘使用），`expressionCrop.ts` 保持不动。

**理由**：表情总图线上在用，任何行为变化都是回归风险。宁可短期重复十几行，也不把两个功能的裁切路径绑死。

**备选**：重构出通用 grid-crop 让两者共用——收益是少一份代码，代价是同时改两条线上路径，当前不值。

### 4. Viewer 是纯字符串构造器，不是 React 组件

**选择**：`buildPreviewHtml(snapshot, resolveAsset) => string`。应用内把它塞进 `<iframe sandbox="allow-scripts" srcdoc={...}>`；导出把同一个字符串写成文件。

**理由**：这是"页内与导出永不漂移"的唯一低成本保证。React 组件方案要么在导出时引入服务端渲染（Node 依赖、打包体积、导出需要服务端），要么维护第二套静态排版（必然漂移）。

**代价**：预览内部交互不参与宿主 React 状态，需要通信时只能走 `postMessage`；当前需求不需要。

**安全约束**：沙箱**不加** `allow-same-origin`，否则用户文本等于接管宿主页面。

### 5. 资产解析用注入点区分在线与离线

**选择**：`resolveAsset(url)` 作为唯一差异点——应用内直连同源 URL；导出时 `fetch` 后经 canvas 转 WebP 再内联为 data URL。

**理由**：快照与排版代码完全共用；导出体积只在真正导出时支付，应用内不做无谓的 base64 转换。

**备选**：一律内联（应用内浪费内存与启动时间）、一律相对路径（导出后必然裂图）。

### 6. 导出压缩走浏览器 canvas，不引入 zip

**选择**：转盘帧按较小边长导出、统一转 WebP（`toDataURL('image/webp')`，不支持时回退 JPEG），合并进单个 `.html`。

**理由**：单文件是用户选定的形态；zip 需要额外解压步骤，违背"双击即看"。`fflate` 保持不用。

### 7. 拖动映射与停手行为

**选择**：水平拖动距离映射到 360°，角度循环；松手即停，不做惯性或自动旋转；触屏用 pointer 事件统一处理。

**理由**：自动旋转会让人无法看清静止造型，且与"预览是审阅工具"的定位冲突；惯性会让角度不可复现。

### 8. 失效判定沿用身份锚点

**选择**：`orbitSheet.fingerprint` 由外观锚点、配色、关键词与三视图 URL 组成；参考图变化**不**触发失效（与 `character-appearance` 既有语义一致）。

**理由**：转盘锁的是"这个人长什么样"，参考图只是生成输入；否则每加一张参考图预览就全红，用户会学会忽略失效标记。

### 9. 文案注入做两层转义

**选择**：快照以 `JSON.stringify` 注入，并把 `<` 转成 `\u003c`；所有用户文本在拼 HTML 时走统一 `escapeHtml`。

**理由**：`lookCn`、角色名都是自由文本；只做其中一层，仍可能被 `</script>` 或属性逃逸穿透。

## Risks / Trade-offs

- **八角度身份漂移**（最大风险）→ 生成时带上三视图与参考图，提示词显式要求同一人物、同一服装、纯色背景、单格居中；预览标注"由生成图合成"，允许重复生成；必要时把角度帧降到 6 帧以降低一致性压力。
- **等分裁切切到人物** → 沿用表情总图的构图约束（单格居中、留边），并在裁切后做一次可见性自检；不合格时退回到"静态合成卡 + 提示重生成"而不是展示半个人。
- **单文件体积膨胀** → 转盘帧限宽、WebP 质量 0.8、导出前估算体积并提示确认；超阈值不静默写出。
- **沙箱 iframe 的拖拽手感** → 预览区固定高度、`touch-action: none`、拖动时阻止页面滚动；触屏场景纳入验收脚本。
- **WebP 编码不可用**（部分运行环境）→ 回退 JPEG 并保留体积提示，功能不因此失效。
- **导出文件的 schema 演进** → 内嵌 `schemaVersion`，viewer 对未知字段容错、对缺失字段降级，旧文件永不变白屏。
- **角色名作文件名含非法字符** → 统一 sanitize 为安全字符，保留可读性。

## Migration Plan

- 无数据库迁移：`orbitSheet` 为可选字段，旧项目读取时为 undefined，直接走静态合成卡降级。
- 上线顺序：快照 + 静态卡 + 导出（不生成、不花钱）→ 转盘生成与裁切 → 拖动交互。每一步都可独立回滚，回滚只影响预览页签，不触碰既有生成链路。
- 导出文件不依赖服务端，回滚应用不导致已导出的文件失效。

## Open Questions

- 导出体积阈值与转盘帧目标分辨率的具体数值（实现时以 5MB 软上限、512px 边长起调）。
- 是否提供"自动缓慢旋转"作为可选开关（默认关闭）。
- 导出是否需要可选水印（默认不加）。
- 八帧是否足够顺滑，还是需要 12 帧（待真实生成结果验证后再定，不影响本轮接口）。
