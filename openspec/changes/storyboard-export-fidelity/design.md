# Design

## Context

`src/storyboardMarkdown.ts` 是一个纯函数渲染器：输入 `StoryboardSource`（项目元数据 + 分集 + 镜头），输出单集 md 文本。它刻意不接受画布节点，也不做任何 IO。导入侧则通过表头别名识别列，不依赖列位置。

三个约束决定了实现形状：

1. **列位置不能变**。导入按表头名认列，但用户手写的旧文件按顺序理解；既有九列必须原样在前，新列只能追加在末尾。
2. **参考连线存的是节点 id**。`refIds` 里是 `char-<角色 id>` 与 `asset-<随机 uid>`；后者离开当前画布状态就无法还原成可读名字。
3. **镜头语言绑定目前不落库**。`lexiconRefKey` / `lexiconRefUrl` / `motionLexiconAsRef` 只存在于画布节点，`nodeToShot` / `shotToData` / `bizSignature` 都没有它们，所以 `运镜参照` 列读不到任何真实数据。

## Goals / Non-Goals

**Goals:**

- 让导出文件成为分镜的完整真相源：表演、台词表演、选角、参考、运镜参照都能在文件里读到。
- 把单元格语法集中到一处，供 `storyboard-import-fidelity` 直接复用，避免两侧各写一套解析。
- 让 `运镜参照` 列在本次交付后就有真实数据，而不是一个永远空的占位列。

**Non-Goals:**

- 不实现导入侧解析（属于 `storyboard-import-fidelity`）。
- 不导出 `refExtras`、产线产物、画布工程态。
- 不改变既有九列的名称、顺序与内容语义。

## Decisions

### D1 新增共享语法模块，本次只落渲染侧

新建 `src/shotCellSyntax.ts`，只放纯函数：单元格 → 字段（渲染）与字段 → 单元格（解析）。本次实现渲染侧，导出模块从这里取格式化逻辑。

**为什么**：语法一旦分散在导出与导入两处，任何一方微调都会静默破坏往返。渲染与解析放在同一文件里，改动时能同时看到两侧。

**替代方案**：把格式化内联在 `storyboardMarkdown.ts`。被否——导入侧将无法复用，必然出现两份近似但不一致的解析。

### D2 四个新列追加在末尾，不做列位置识别

`SHOT_TABLE_HEADER` 从九列扩到十三列：选角、表演、运镜参照、参考依次追加。

**为什么**：导入按表头名认列，追加不影响旧文件；插入中间会让手写文件的列语义整体错位。

**代价**：新列离表头右侧较远，宽表阅读体验差。接受——表格是给人和模型读的，完整性优先于紧凑。

### D3 参考解析保持渲染器纯净：调用方传索引

`StoryboardSource` 增加可选的 `refIndex`：素材节点 id → 标题，以及已知角色 id 集合。渲染器只做查表，不接触画布。

**为什么**：模块目前零依赖、可在 Node 里直接测。让它去读 localStorage 会毁掉这个性质，也会把「导出不依赖画布」的约束彻底打破。调用方（画布层）本来就有节点，构索引是顺手的事。

**替代方案**：渲染器接收 `nodes` 数组自己遍历。被否——等于把画布结构泄露进导出模块，且无法在无浏览器环境测试。

### D4 台词标注只解析冒号之前，因此不需要转义

内联语法是 `角色[情绪/强度/语速/音量]{强调}：台词原文`。解析范围限定为「说话人之后、首个冒号之前」，冒号之后的原文逐字保留。

**为什么**：避免为台词里的 `[` `{` 设计转义规则。转义是往返最容易出错的地方，限定解析窗口可以让它完全不存在。代价是说话人名里不能含方括号——实际不可能。

**替代方案**：发明 `\[` 转义。被否——手写表格的用户不会记得转义，一个漏转义就会把台词切坏。

### D5 镜头语言三字段随镜头落库，归入本次

`ProjectShot` 增加 `lexicon_ref_key` / `lexicon_ref_url` / `motion_lexicon_as_ref`，并补 `nodeToShot`、`shotToData`、`bizSignature` 三处映射。服务端无需建列，`shots.extra` 的既有兜底会原样收下。

**为什么**：`运镜参照` 列必须读到真实绑定才有意义。把这步留到 `pi-agent-material-tools`，本次交付的就是一个永远为空的列，既不可验证也没价值。绑定能落库之后，画布上的 Inspector 选择也会在刷新后保留，这本身是个 bug 修复。

**影响**：`pi-agent-material-tools` 的范围相应缩小为「只加 agent 工具与条目导入」，不再重复声明字段。

### D6 未解析的参考写附注，不写占位符

指不到角色的 `char-*` 与指不到素材的 `asset-*` 从参考列剔除，在表格外附注里列出镜号与目标。

**为什么**：参考列必须始终是可重新解析的名字集合；写 `asset-9f2a` 既不可读，也会在导入时被当成一个不存在的素材名。

**代价**：信息在表格与附注之间分成了两处，读者要往下翻才能看到失效引用。接受——失效引用本来就是需要人处理的问题，不该静默藏进单元格。

### D7 表演列的报告式槽位

`角色:情绪/强度/动作/视线/是否说话`，固定五槽，缺项留空，是否说话写 `说` / `不说`。

**为什么**：固定槽位让解析无需猜顺序，空槽保留位置使「没填」与「填了空值」可区分。`speaks` 未定义时留空而不是写「不说」，否则往返一次就把「未设置」固化成了「不说话」。

**替代方案**：`key=value` 形式。被否——中文动作描述里出现 `=` 的概率虽低，但一旦出现就需要转义。

## Risks / Trade-offs

- **[过渡期列不识别]** 导入侧尚未认识四个新列时，用户把自己的导出文件导回来会看到「未识别列」提示 → 提示只警告不写错，且 `storyboard-import-fidelity` 紧随其后落地。
- **[缺少索引导致素材参考全部失效]** 调用方未传 `refIndex` 时，所有素材参考都会进附注 → 渲染器对缺失索引的行为定为「按未解析处理」而不是猜测，并在附注里给出提示文案；画布入口必须始终传入索引。
- **[宽表可读性]** 十三列在窄屏需要横向滚动 → 属可接受代价，md 阅读器普遍支持横向滚动；不引入折行表格，那会破坏导入识别。
- **[旧文件回灌仍丢表演]** 用户拿旧版导出的九列文件回灌，表演会被系统补成占位值 → 由 `storyboard-import-fidelity` 的预览提示处理，本次不做额外兼容。

## Migration Plan

- 无数据迁移：三个新字段是可选字段，缺失即按「未绑定」处理。
- 回滚：撤回列定义即可恢复九列输出；已落库的 `lexicon_*` 字段会留在 `shots.extra` 里，不影响旧代码读取。
