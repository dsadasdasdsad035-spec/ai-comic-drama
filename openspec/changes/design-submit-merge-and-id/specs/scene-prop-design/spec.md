# Spec Delta

## MODIFIED Requirements

### Requirement: 重复拆解合并且保护手改

系统 SHALL 按类型和规范化名称合并设定卡，无论来源是人工拆解还是聊天写回；同名卡 MUST 合并关联镜号并只补空字段，已有非空生图锚点、当前图和候选图 MUST 保留；MUST NOT 删除未参与本次操作的设定卡。

#### Scenario: 重复拆同一批素材

- **WHEN** 用户对同一集连续拆两次
- **THEN** 已有场景/道具卡不重复新增，关联镜号取并集

#### Scenario: 已有手改锚点

- **WHEN** 某张场景卡已经有用户改过的英文锚点
- **THEN** 再次拆解保留该锚点，只补充空字段或新增其他卡

#### Scenario: 本次没有出现旧卡

- **WHEN** 本次拆解没有返回某张旧场景/道具卡
- **THEN** 旧卡仍保留，不被删除

#### Scenario: 聊天写回同名卡

- **WHEN** agent 通过聊天写回提交一张与项目已有卡同类型同名的场景卡
- **THEN** 该卡不重复新增，已有的当前图、候选图与手工锚点保留，只补充空字段

#### Scenario: 聊天写回未包含旧卡

- **WHEN** agent 通过聊天写回只提交了本次新拆出的道具卡，项目里还有别的场景卡
- **THEN** 未出现在本次写回里的场景卡仍然保留

## ADDED Requirements

### Requirement: 设定卡标识稳定且非空

系统 SHALL 为每张设定卡维护项目内唯一的非空标识，并在卡的生命周期内保持不变。标识 MUST NOT 由名称派生，改名 MUST NOT 改变标识。历史数据中标识为空的设定卡 MUST 在下次写入前补齐，MUST NOT 因标识为空被丢弃或与另一张卡冲突。

#### Scenario: 新建卡获得标识

- **WHEN** 用户或 agent 新建一张场景卡并写回项目
- **THEN** 该卡获得一个非空标识，且读取工具能按该标识列出这张卡

#### Scenario: 改名不换标识

- **WHEN** 某张设定卡被改名后再次写回
- **THEN** 该卡沿用原标识，引用它的素材仍然指向同一张卡

#### Scenario: 历史空标识被补齐

- **WHEN** 项目里存在标识为空的设定卡，随后发生一次设定写回
- **THEN** 该卡获得非空标识，不再从读取工具的列表中消失

#### Scenario: 连续写入多张新卡

- **WHEN** 一次写回提交了两张此前都不存在的设定卡
- **THEN** 两张卡都成功落库，各自拥有不同标识，不触发唯一性冲突

### Requirement: 设定写回原子且失败可见

系统 SHALL 把一次设定卡写回作为原子操作提交。任一条目失败时 MUST 回滚，MUST NOT 留下部分写入的结果。写回失败时 MUST 向调用方返回失败，MUST NOT 在落库完成前报告成功。

#### Scenario: 条目冲突时回滚

- **WHEN** 一次设定写回中某个条目无法落库
- **THEN** 本次写回整体不生效，项目里原有的设定卡保持提交前的内容

#### Scenario: 服务端拒绝时调用方收到失败

- **WHEN** 服务端以错误状态拒绝一次设定写回
- **THEN** 发起写回的调用方收到失败结果，MUST NOT 收到成功摘要，后续读取也不应看到未落库的内容
