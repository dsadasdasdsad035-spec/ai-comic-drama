# Spec Delta

## MODIFIED Requirements

### Requirement: 角色聊天可选择参考图

角色工作台聊天 SHALL 允许用户在本轮对话中附加图片作为模型的参考内容，MUST NOT 要求先选中某个角色。附件来源 MUST 至少包含两种入口：上传本地图片、从当前项目已有的图片中选择。附件 MUST 在发送前显示并可移除。聊天里的附件 MUST NOT 写入任何角色的参考图列表——角色参考图是角色卡上的独立能力，两者互不影响。

#### Scenario: 不选角色也能加图
- **WHEN** 用户打开角色聊天但还没有选中任何角色卡
- **THEN** 附件入口仍然可用，能上传图片或从项目里选图并加入本轮上下文

#### Scenario: 上传本地图片
- **WHEN** 用户在聊天里上传一张本地图片
- **THEN** 图片落成项目媒体文件并进入本轮上下文，聊天结束后不写进任何角色的参考图列表

#### Scenario: 从项目里选图
- **WHEN** 用户在聊天里点「从项目选」
- **THEN** 能从当前项目的已有图片中选择一张并加入本轮上下文，取消选择则不改变上下文

#### Scenario: 移除与清空
- **WHEN** 用户从附件栏移除一张图，或点清空
- **THEN** 该图（或全部图）不再出现在本轮上下文，后续消息也不包含它们

#### Scenario: 与角色参考图互不影响
- **WHEN** 用户在聊天里带了图并产出角色
- **THEN** 该角色的参考图列表保持不变；反过来，角色卡上已有的参考图也不会自动进入聊天上下文

#### Scenario: 从已有参考图选择
- **WHEN** 用户在聊天里需要复用项目里已有的图片
- **THEN** 能通过「从项目选」把它们加入本轮上下文，这些图不因为来自某个角色而与该角色绑定

#### Scenario: 聊天里上传新图
- **WHEN** 用户在聊天里上传一张本地图片
- **THEN** 图片落成项目媒体文件并进入本轮上下文，不写入任何角色的参考图列表

#### Scenario: 参考图上限
- **WHEN** 本轮附件数量已达到上限
- **THEN** 系统拒绝继续添加并说明上限，已有附件不受影响

#### Scenario: 切换角色不串图
- **WHEN** 用户切换选中的角色卡
- **THEN** 聊天记录与附件保持不变；不再存在「按角色分开的会话」，因此不会出现把 A 的图带进 B 的会话这种情况

## ADDED Requirements

### Requirement: 聊天用过的图不进入出图请求

「用它生成三视图」的请求 MUST NOT 包含当轮聊天里附加的图片。出图使用的参考图 MUST 只来自目标角色在角色卡上已有的参考图；没有参考图时 MUST 以纯文字锚点出图，不得回退去取聊天附件。

#### Scenario: 聊天带图后出图
- **WHEN** 用户带着两张图产出角色锚点，然后点「用它生成三视图」
- **THEN** 出图请求的参考图只包含该角色卡片上的参考图（可能为空），不包含刚才上传的那两张

#### Scenario: 角色卡有参考图时
- **WHEN** 目标角色在角色卡上已经挂了两张参考图
- **THEN** 出图使用这两张，与聊天里是否带图无关

#### Scenario: 都没有参考图
- **WHEN** 角色卡没有参考图，聊天里带过图
- **THEN** 出图不传参考图，只用英文锚点与三视图提示词

### Requirement: 聊天上下文不绑定当前角色

角色聊天 MUST 以整板（当前项目与集）为会话范围，MUST NOT 因为选中某张角色卡而切换会话或限制可附加的内容。选中角色卡片 MUST NOT 改变聊天发送给模型的范围。

#### Scenario: 切换选中不换会话
- **WHEN** 用户在同一个项目里切换选中的角色卡
- **THEN** 聊天记录与已有附件保持不变，不切换到另一条会话

#### Scenario: 消息范围是整板
- **WHEN** 用户没有选中任何角色就发送消息
- **THEN** 模型仍然收到当前集的范围描述与本轮附件，正常产出角色

#### Scenario: 旧的分角色会话不再出现
- **WHEN** 用户此前用过按角色分会话的版本，进入角色聊天
- **THEN** 聊天只读取整板会话，不加载任何按角色分开的旧记录，也不把其他角色的会话混进来

（说明：本版不额外提示旧记录已不可见——当前没有「列举聊天线程」的接口，前端无法判断旧记录是否存在；加探测接口超出本次范围。）
