# Spec Delta

## Purpose

约束平台内置工具（读 / 写 / 校验 / 动作四类）的冒烟与回归：每个工具都必须被逐个调用、调用必须声明期望结果、业务失败必须区分「设计上的 fail-closed」与「真实回归」，并保证工具清单、运行时注册与默认专家白名单三者一致。

## ADDED Requirements

### Requirement: 逐个调用全部内置工具

验收套件 SHALL 对平台内置工具清单里的每个工具各调用一次，且每轮运行的调用数 MUST 等于清单长度。调用表缺少某个工具、或清单列出而运行时未注册时，验收 MUST 失败并点名该工具。

#### Scenario: 调用表覆盖全部工具

- **WHEN** 验收套件运行完毕
- **THEN** 每个内置工具都有一次实际调用，且被调用的工具数等于清单长度

#### Scenario: 调用表漏了工具

- **WHEN** 某个内置工具在调用表里没有参数
- **THEN** 验收失败并点名该工具缺少验收参数，不得静默跳过

### Requirement: 每次调用必须声明期望结果

调用表 SHALL 为每个工具声明期望结果，取值至少区分「预期成功」与「预期业务失败」。验收 MUST 比较实际结果与声明值，不一致即判失败。

#### Scenario: 预期成功却失败

- **WHEN** 某工具声明为预期成功，实际返回失败
- **THEN** 验收失败，并输出该工具名称与实际错误信息

#### Scenario: 预期失败却成功

- **WHEN** 某工具声明为预期失败（例如没有确认通道时必须拒绝），实际却返回成功
- **THEN** 验收失败；该调用可能已经落库或产生费用

### Requirement: 预期失败必须带理由并与意外失败区分

声明为预期失败的工具 SHALL 附带理由（缺少确认通道、缺少成本确认通道、镜号工位不支持、目标不存在等）。验收 MUST 校验实际错误信息与声明理由相符；理由不符或工具未声明却失败，MUST 判为意外失败而不是通过。

#### Scenario: 缺确认通道的拒绝算预期

- **WHEN** 会话没有确认通道，破坏性工具拒绝执行
- **THEN** 该调用记为预期失败并通过，输出里标明「预期拒绝」

#### Scenario: 未声明的失败算回归

- **WHEN** 某工具声明为预期成功，实际返回依赖服务不可用（例如代理返回非 JSON 的 404）
- **THEN** 该调用判为意外失败，不得计入通过

### Requirement: 每个工具至少一项内容级断言

除「不抛异常」之外，每个内置工具 SHALL 至少有一项对其返回内容或副作用的断言：读取工具断言返回结构与非空数据，写回工具断言项目数据确实改变，动作工具断言写入后的字段取值。仅有「调用没有异常」的断言 MUST NOT 视为已覆盖。

#### Scenario: 读取工具断言内容

- **WHEN** 读取运镜库、专家目录或技能正文
- **THEN** 断言返回条目非空且形状符合预期，而不是只断言返回对象存在

#### Scenario: 写回工具断言落库

- **WHEN** 提交提示词、镜间接缝或素材卡
- **THEN** 重新读取项目，断言对应字段确实被写入，而不是只断言工具返回成功

### Requirement: 清单、注册与默认专家白名单三方一致

工具名清单、运行时注册的工具、默认专家白名单三者 SHALL 互相一致。任一方向出现差异时，一致性校验 MUST 失败并列出差异名字；该校验 MUST 有直接的否定用例，证明少一个名字或多一个名字都会被拦下。

#### Scenario: 三者一致

- **WHEN** 校验真实工具集
- **THEN** 不报差异

#### Scenario: 清单有而注册无

- **WHEN** 从注册集合里删掉某个工具名
- **THEN** 校验失败并指出「清单有但未注册」及该名字

### Requirement: 验收脚本不得引用不存在的工具名

验收脚本 SHALL 只引用当前注册的工具。脚本引用了已移除或改名的工具时，MUST 以可读错误失败，或该脚本被删除并说明覆盖由谁接管；MUST NOT 留下运行即抛异常的脚本。

#### Scenario: 脚本引用了已移除的工具

- **WHEN** 脚本查找的工具名不在注册集合里
- **THEN** 脚本给出「该工具不存在，脚本已过期」一类可读错误并失败，而不是对空值取属性

### Requirement: 需要运行中服务的脚本使用统一地址

需要运行中服务的验收脚本 SHALL 从同一个环境变量解析服务地址，并 MUST 在服务不可达时给出可读错误。批量入口 SHALL 注入该地址或让各脚本自起服务并在结束时清理，使批量运行不因端口约定不同而整体失败。

#### Scenario: 批量运行继承同一地址

- **WHEN** 通过批量入口运行一组验收脚本
- **THEN** 各脚本访问同一服务地址，不会因为默认端口不同而连不上

#### Scenario: 服务不可达

- **WHEN** 目标地址没有运行中的服务
- **THEN** 脚本输出可读的「服务未启动」提示并失败，而不是抛连接栈

### Requirement: 依赖外部服务或凭据的断言必须可识别

依赖真实模型或第三方服务的断言 SHALL 在缺少凭据时标记为跳过并说明原因。跳过 MUST 与通过区分开，MUST NOT 把未执行的断言记为通过，也 MUST NOT 把凭据缺失记为产品缺陷。

#### Scenario: 没有凭据

- **WHEN** 验收运行环境未配置所需凭据
- **THEN** 依赖真实服务的断言记为跳过并说明缺少什么，汇总里单列跳过数

#### Scenario: 有凭据但返回异常结构

- **WHEN** 凭据可用，真实服务返回的结构不符合预期
- **THEN** 该断言判为失败，而不是跳过
