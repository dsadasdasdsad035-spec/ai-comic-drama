# Acceptance：首尾帧只从两镜成片抽取

## 抽取语义

- [ ] 点「抽取两镜成片帧」一次填好两侧：首帧 = 上镜成片尾帧，尾帧 = 下镜成片首帧
- [ ] 两槽同时出现缩略图，来源标签为「上镜尾帧」「下镜首帧」
- [ ] 上镜有成片、下镜没有：首帧正常填入，尾帧保持空并在面板提示「下镜还没有成片」
- [ ] 上镜抽帧失败、下镜成功：首帧保持抽取前的值，尾帧更新，面板提示失败原因
- [ ] 任何一侧没有成片时，不会用静帧、候选图或 `refImage` 顶上

## 弹窗

- [ ] 首尾帧页只有两个预览槽、「抽取两镜成片帧」、「打开上镜 / 打开下镜」与单侧「清除」
- [ ] 不存在候选网格、媒体库入口、手填地址输入框
- [ ] 空态下表头显示「首尾帧 0/2（未齐不能生成）」
- [ ] 清除某一侧后该侧回到「未选择」，另一侧不受影响

## 生成路径

- [ ] 两帧都就绪时底栏生成可用，请求 `transition.boundaryOut/boundaryIn` 与槽位一致
- [ ] 缺任一帧时 blocking，文案指向「抽取两镜成片帧」，不提示刷新或点选候选
- [ ] 生成过程不触发任何隐式抽帧（`extractFrames` 只在点击抽取时调用）
- [ ] 服务端缺边界 400 文案同样指向抽取

## 旧数据

- [ ] 旧项目已保存的边界（含 `library` / `manual` 等历史来源）继续展示与生成
- [ ] 历史来源标签保持原值，不被改写成抽帧
- [ ] 无来源字段的旧边界显示中性「已选画面」

## 自动化

```bash
node verify-transitions.mjs
npx tsc --noEmit
npx vite build
```

覆盖：无成片不回退静帧、抽帧失败不回退、真实成片可抽出两帧、抽取即写入两侧来源、弹窗无候选/媒体库、面板两槽结构、服务端文案指向抽取。
