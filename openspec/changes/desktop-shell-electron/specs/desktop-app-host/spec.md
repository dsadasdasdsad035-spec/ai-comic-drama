# Spec Delta

## Purpose

把已可独立启动的 HTTP 服务包装成一个双击即可运行的桌面应用：主进程负责拉起服务进程、等待其就绪、把窗口指向该地址，并在退出时保证不留下孤儿进程，使用户无需安装 Node 或打开终端。

## ADDED Requirements

### Requirement: 单实例运行

应用 SHALL 同一时刻只允许一个实例持有本地服务。用户重复启动时，新进程 MUST 退出并把已有窗口带到前台，MUST NOT 再启动第二个服务进程。

#### Scenario: 重复启动聚焦已有窗口

- **WHEN** 应用已在运行且用户再次打开应用
- **THEN** 新实例立即退出，已有窗口被显示并获得焦点，本地服务端口与数据保持不变

#### Scenario: 第二个实例不写数据

- **WHEN** 用户在应用运行期间第二次启动
- **THEN** MUST NOT 存在第二个进程同时持有项目数据库，避免并发写入

### Requirement: 服务进程启动与端口握手

主进程 SHALL 以系统分配端口的模式拉起本地服务，并从其标准输出解析实际监听端口。握手成功前 MUST NOT 把窗口指向服务地址；握手 MUST 有超时上限。

#### Scenario: 握手成功后加载界面

- **WHEN** 主进程拉起本地服务进程
- **THEN** 解析到端口握手行后，窗口加载该端口对应的地址并显示应用界面

#### Scenario: 未占用的固定端口不被占用

- **WHEN** 用户机器上已有其它程序占用默认端口
- **THEN** 应用仍能正常启动，不与既有程序冲突

#### Scenario: 握手超时

- **WHEN** 服务进程在超时上限内未输出握手行
- **THEN** 主进程按启动失败处理，不显示白屏

### Requirement: 启动失败的可读反馈

当本地服务无法启动或握手失败时，应用 SHALL 在窗口内展示失败原因并提供重试入口。MUST NOT 停留在空白页面或只给出无信息的错误码。

#### Scenario: 服务启动失败

- **WHEN** 服务进程启动即失败（例如缺少构建产物或二进制不可执行）
- **THEN** 窗口展示失败摘要与服务进程输出的最后若干行，并提供可点击的重试

#### Scenario: 重试可恢复

- **WHEN** 用户修复问题后点击重试
- **THEN** 应用重新拉起服务进程，成功则进入正常界面

### Requirement: 服务进程异常退出的恢复

本地服务在运行中退出时，应用 SHALL 保留窗口并提示服务已断开，提供重启入口。MUST NOT 静默关闭窗口或假装服务仍在。

#### Scenario: 运行中服务崩溃

- **WHEN** 服务进程在应用运行期间以非零状态退出
- **THEN** 窗口显示服务已断开的提示与重启按钮，并保留用户当前所在的前端路由

#### Scenario: 用户主动重启服务

- **WHEN** 用户在断连提示中点击重启
- **THEN** 应用重新拉起服务进程并在握手成功后重新加载界面

### Requirement: 退出顺序与孤儿进程

应用退出时 SHALL 先请求本地服务终止并等待其结束，超时后强制结束。应用退出后 MUST NOT 残留继续监听端口的服务进程。

#### Scenario: 关闭窗口后退出

- **WHEN** 用户关闭最后一个窗口并确认退出
- **THEN** 本地服务收到终止信号并在超时上限内结束，应用随后退出

#### Scenario: 应用被强杀

- **WHEN** 主进程被系统强制结束
- **THEN** 本地服务 MUST NOT 长期继续监听端口，下次启动仍能正常分配端口

### Requirement: 窗口导航仅在本地服务内

窗口 SHALL 只在本地服务地址内导航。指向外部站点的链接 MUST 交给系统默认浏览器打开，MUST NOT 在应用窗口内加载。

#### Scenario: 点击外部链接

- **WHEN** 用户在界面中点击一个非本地服务地址的链接
- **THEN** 该链接在系统默认浏览器中打开，应用窗口地址不变

#### Scenario: 尝试跳出服务地址

- **WHEN** 页面发起指向本地服务之外的顶层导航
- **THEN** 该导航被阻止，应用窗口仍停留在本地服务内
