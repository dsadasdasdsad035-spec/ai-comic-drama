# Spec Delta

## Purpose

产出一个可被 macOS 用户正常安装、启动与升级的应用包：数据写入用户可预期且可备份的位置，安装包通过签名与公证以避开系统拦截，升级过程中不丢失用户项目与生成产物。

## ADDED Requirements

### Requirement: 应用数据根位于用户目录

应用 SHALL 把项目库、媒体产物与运行期状态（暂存、渲染作业、场景草稿、计费数据库）全部存放在用户目录下的应用数据目录，默认由主进程注入给本地服务。MUST NOT 写入应用包内部，以保证应用目录可被系统挂载为只读或重定位后仍可运行。

#### Scenario: 首次启动创建数据目录

- **WHEN** 用户首次启动应用且数据目录尚不存在
- **THEN** 应用自动创建项目库、媒体与运行期状态子目录，不要求用户手工建目录

#### Scenario: 运行期写入不落在应用包内

- **WHEN** 用户触发一次会写入暂存、渲染作业或登录态的操作
- **THEN** 写入落在用户数据目录内，应用包内部文件没有变化

#### Scenario: 应用从只读位置运行

- **WHEN** 应用被 macOS 重定位到随机只读路径后启动
- **THEN** 项目读写与媒体生成仍正常工作，产物落在用户数据目录内

#### Scenario: 用户自定义数据位置

- **WHEN** 用户显式配置了项目目录或媒体目录
- **THEN** 该配置优先于默认用户目录生效

### Requirement: 迁移与升级不丢数据

应用 SHALL 把用户数据与安装包版本解耦。升级或重装应用后，既有项目、项目数据库与生成产物 MUST 仍然可见可用。

#### Scenario: 覆盖安装新版本

- **WHEN** 用户用新版本替换旧版本应用
- **THEN** 升级后打开应用能看到升级前的全部项目与生成产物

#### Scenario: 卸载不静默删除数据

- **WHEN** 用户把应用拖入废纸篓
- **THEN** 用户数据目录 MUST NOT 被自动清空；文档说明清理方式与影响范围

### Requirement: macOS 安装包产物

应用 SHALL 产出可直接分发的 macOS 安装包，包含应用包本体与镜像安装方式。安装包 MUST 在未开启「任何来源」的默认安全设置下可以正常打开。

#### Scenario: 双击安装

- **WHEN** 用户下载安装包并双击打开
- **THEN** 系统未提示「无法验证开发者」或将其移入废纸篓，用户可完成拖入应用程序目录的安装

#### Scenario: 首次启动可用

- **WHEN** 用户从应用程序目录首次启动应用
- **THEN** 应用正常显示界面，本地服务就绪，无需用户执行任何终端命令

### Requirement: 签名与公证覆盖嵌套可执行文件

应用包内所有 Mach-O 可执行文件与动态库 SHALL 被签名，应用本体 MUST 开启 Hardened Runtime 并通过公证。MUST NOT 依赖用户手工绕过 Gatekeeper 的做法。

#### Scenario: 公证校验通过

- **WHEN** 对产出的安装包执行系统公证校验
- **THEN** 校验通过，安装包已附加公证票据，离线状态下也能通过 Gatekeeper

#### Scenario: 嵌套二进制未被签名

- **WHEN** 打包产物中存在未签名的嵌套可执行文件
- **THEN** 构建流程 MUST 以失败结束并指明该文件，而不是产出一个只能靠绕过校验启动的包

### Requirement: 第三方组件说明

安装包 SHALL 附带第三方组件说明，列出随包分发的运行时与二进制的名称、版本、来源地址与许可证。对 GPL 许可的组件，MUST 同时提供获取对应源码的途径说明。

#### Scenario: 查看组件说明

- **WHEN** 用户或合规审查者在应用内或安装包中找到组件说明
- **THEN** 能读到每个随包组件的版本、来源与许可证，以及 GPL 组件的源码获取途径
