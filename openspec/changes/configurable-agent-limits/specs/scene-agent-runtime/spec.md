# Spec Delta

## MODIFIED Requirements

### Requirement: 修复与验收循环必须有上限

运行时 MUST 保留代码修复和视觉验收的轮次预算，并 MUST 对所有运行施加可配置的总运行时长；MUST NOT 再使用图执行步数作为用户可配置或面向用户的上限。达到总时长 MUST 停止运行并返回“运行超时”，MUST NOT 与用户取消混淆。

#### Scenario: 修复成功

- **WHEN** 沙箱返回错误且修复次数未超限
- **THEN** agent 可以提交新代码并再次试运行

#### Scenario: 达到修复上限

- **WHEN** 连续修复达到配置的代码修复预算仍未通过
- **THEN** 循环停止，显示失败原因和已尝试次数，不使用图步骤上限提前截断

#### Scenario: 长时间多轮执行

- **WHEN** 模型进行多次工具调用但未达到总运行时长
- **THEN** 运行继续，不会因图节点计数达到某个数字而报“步骤达到上限”

#### Scenario: 用户取消

- **WHEN** 用户在工具执行中取消
- **THEN** 后续工具不执行，旧代码和视频不被改动，状态显示为已取消

#### Scenario: 整体超时

- **WHEN** 整个 agent 运行超过设置中的总运行时长
- **THEN** 运行被终止并显示运行超时，不写入半成品，也不显示成用户取消
