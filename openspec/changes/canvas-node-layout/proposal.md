# Proposal

## Why

画布的节点位置由四段互不相识的代码各自决定：分镜在 `canvasShots.buildShotNodes`，角色在 `App.tsx` 的 `charPos`，素材卡在 `App.tsx` 三处内联坐标（手动添加、设定图发布、在线素材/表情总图、首次恢复）。每加一个入口就复制一次栅格常量，于是出现三类可复现的缺陷：

- **新增素材卡完全重合**：`addAsset` 固定写 `{ x: 120, y: 220 }`，连点三次就是三张叠在一起，用户以为只加了一张。
- **分镜列宽各算各的**：第 N 列的 x 用第 N 张卡自身宽度累加，`cardWidth` 随时长在 250~380 之间变化，宽卡后接窄卡会落进前一列内部（实测 8s/8s/8s/3s 时第 4 张与第 3 张重叠 274px）。
- **素材带压进分镜带**：首次恢复用 `y: 220`（分镜第一行在 y=0、第二行在 y=340），运行时新增却用 `y: -560`；同一批素材卡因来源不同落在两个不相容的区域。

另外镜头的落位下标来自写回数组顺序，而 `mergeShots` 的产出是「命中镜在前、其余在后」，一次单镜写回就会改变后续新镜头的占位次序；画布也缺少任何「整理」入口，摆歪之后只能逐张手拖。

## What Changes

- **统一布局模块**：新增一个按节点类型分区、共用栅格的落位实现，所有创建入口（手动加素材、设定图发布、在线素材、表情总图、首次恢复、分镜水合、角色上画布）都调它，不再各自内联坐标。
- **分区不重叠**：角色带、素材带、分镜带各自占据互不重叠的纵向区域；素材带统一在分镜带上方，首次恢复与运行时新增 MUST 落在同一区域。
- **统一列栅格**：分镜列宽 MUST 按已用宽度累加（或固定栅格），MUST NOT 用卡片自身宽度决定自身列偏移，保证时长差异下不重叠。
- **新节点找空位**：同类型新节点 MUST 落在第一个不与现有同类型节点重叠的槽位，MUST NOT 与已存在的卡完全重合。
- **分镜落位按镜号**：超出已有节点的新镜头 MUST 按镜号数值决定栅格顺序，MUST NOT 由写回数组下标决定，避免单镜写回导致落位漂移。已有节点保留用户拖放后的位置。
- **「整理画布」动作**：提供一个显式动作，按同一模块重排当前画布上的节点；MUST 只在用户点击时执行，MUST NOT 自动重排用户手工摆放的布局。
- **BREAKING（落位观感）**：分镜与素材卡的默认位置会变化；用户拖过的节点位置仍被保留，只有新增与整理受影响。

## Capabilities

### New Capabilities

- `canvas-node-layout`: 画布上分镜、角色、素材（含表情总图）四类节点的落位与整理规则：分区、栅格、避让、顺序依据与显式重排。

### Modified Capabilities

（无）

## Impact

- **前端**：新增布局模块；`src/canvasShots.ts`（`buildShotNodes` 的栅格与顺序）、`src/App.tsx`（`addAsset`、`syncAssetsFromDesigns`、`addAssetCardFromStock`、表情总图发布、首次恢复 `useEffect`、角色带坐标、工具条「整理画布」入口）。
- **不变**：`project.shots` / `project.assets` 的数据结构与顺序、`refIds` 语义、`read_shots` 的读出顺序、连线与转场规则、`asset-canvas-publishing` 的「重复发布保留画布位置」。
- **测试**：新增布局单测（覆盖宽窄混排不重叠、新卡避让、分区不交叉、镜号顺序不随写回漂移）；画布导入与素材发布验收补充「新增卡不重合」断言。
