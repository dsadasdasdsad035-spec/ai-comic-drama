# Spec Delta

## MODIFIED Requirements

### Requirement: 覆盖已有锚点需要明确要求

新增角色的锚点 MUST 直接写入。已有角色的锚点 MUST 只在用户明确要求修改该角色时才被覆盖；没有明确要求时 MUST 保留原锚点，只补空字段。覆盖 MUST 在结果里点名改了哪些角色。

「写入」MUST 指锚点真正存入当前项目、并能在随后的读取中取回同样的中文与英文外观锚点。提交成功但锚点落库为空 MUST NOT 视为写入成功，系统 MUST 让本次提交失败并说明锚点未保存，MUST NOT 回一个「成功」让用户以为已经保存。

#### Scenario: 新建角色
- **WHEN** 用户带图说「这是新角色小狸花」
- **THEN** 新建该角色并写入锚点，不修改其他角色

#### Scenario: 明确要求改已有角色
- **WHEN** 用户带图说「按这张改陈默的外观」
- **THEN** 覆盖陈默的锚点，并在结果里写明改写了陈默

#### Scenario: 没有明确要求
- **WHEN** 用户只带图说「拆一下角色」，而项目里已有同名角色且有锚点
- **THEN** 保留原锚点不覆盖，结果里说明跳过了哪些已有角色

#### Scenario: 覆盖后表情总图失效
- **WHEN** 已有角色的锚点被覆盖
- **THEN** 该角色的表情总图按既有规则标记为需要重生成

#### Scenario: 新增角色的锚点读回一致
- **WHEN** 助手提交了一个带中文与英文外观锚点的新角色，随后重新读取当前项目角色
- **THEN** 该角色的中英文外观锚点与提交内容一致，不为空

#### Scenario: 同名角色提交不报错
- **WHEN** 助手提交的角色名与当前项目已有角色重名
- **THEN** 提交按覆盖规则处理该角色，MUST NOT 因角色字段缺失而抛错或中断整次提交
