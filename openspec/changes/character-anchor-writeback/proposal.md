# Proposal

## Why

`submit_characters` 在真实会话里持续失败，报 `Cannot read properties of undefined (reading 'trim')`，且与提交内容无关（只提交 `{"name":"幼猫"}` 同样失败）。根因是角色数据在服务端契约（蛇形 `look_cn`/`look_en`）与界面模型（驼峰 `lookCn`/`lookEn`）之间存在断层，而多处代码直接把项目快照里的角色数组当成界面模型使用：同名角色命中时读 `old.lookEn.trim()` 直接抛错；提交成功的那一支又把驼峰对象写回服务端，服务端只认蛇形字段，新增角色的外观锚点被静默清成空串。

这不是单点事故：项目 `a` 中 `幼年白猫`/`成年白猫`/`新角色4` 的中英文锚点与配色全为空，但三视图、表情总图、音色都有值——锚点在创建时就被抹掉，之后用户在角色卡补的图反而保住了。同类断层还让提示词锚点展开永远「未解析」、三视图生图拿不到角色参考图、配音拿不到角色绑定音色。一次提交成功却把 AI 产出的锚点扔掉的路径，比崩溃更危险。

## What Changes

- 在角色数据的读写边界统一形状：读端一律从接口形状转成界面形状，写端一律转回接口形状再落库；内存快照始终保存接口形状，避免同一会话内出现混合形状。
- `toSheet` 同时接受蛇形与驼峰输入作为兜底，存量已不规范的对象不再被读成空锚点。
- 角色合并时对缺失字段做防御，「有无锚点」的判断不再因字段缺失抛错中断整次提交。
- 把同一形状边界用到其余消费点：提示词锚点展开、角色三视图/表情总图的参考图与锚点、台词配音的角色音色。
- 角色落库后做一次读回校验：锚点为空而提交内容非空时让本次提交失败并说明未保存，而不是回「成功」。
- 冒烟脚本补断言：同名角色重复提交不报错；新增角色提交后从数据库读回的锚点非空。
- 项目 `a` 已清空的锚点无法从历史记录恢复（库内不存在对应提交记录），不做自动回填，改由重新提交修复；文档说明这一限制。

## Capabilities

### New Capabilities

无。本变更修正既有行为，不引入新的系统能力。

### Modified Capabilities

- `character-appearance`: 「覆盖已有锚点需要明确要求」中「新增角色的锚点 MUST 直接写入」目前在助手写入与工具读取两条路径上都不成立——锚点写回时丢弃、读取时被当成缺失。要求补充为锚点必须真正落到项目数据、能原样读回，落库失败不得回报成功。
- `character-extraction`: 「角色合并只影响当前项目」只约束了合并阶段，未约束写回阶段。要求补充为合并结果落库后读回与合并结果一致，合并阶段保留的锚点不得在写入阶段丢失。

## Impact

- 代码：`src/charMap.ts`（双形状容错与统一读入口）、`src/platform/projectDraft.ts`（角色分支读写映射、快照形状、提示词锚点展开入参）、`src/charExtract.ts`（锚点判空防御）、`src/agent/materialTools.ts`（角色名册与角色图片落库）、`src/agent/builtinPlatformTools.ts`（配音取角色音色）。
- 数据：服务端 `characters` 表契约不变，本变更只保证客户端按契约发送、按契约读取。
- 测试：`verify-creative-builtin-tools.mjs` 增加角色写回与读回断言；`npm run build` 与既有冒烟套件作为回归门槛。
- 存量数据：项目 `a` 中已丢失的锚点不做自动回填，需用户重新提交。
