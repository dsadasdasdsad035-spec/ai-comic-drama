# Spec Delta

## Purpose

让角色三视图和场景/道具设定图这类长效参考图跟随项目存放，而不是散落在可被清理的公共产物目录；文件缺失时明确暴露，生成和上传的图片在刷新后仍然存在。

## ADDED Requirements

### Requirement: 参考图存入项目媒体目录

系统 SHALL 把角色三视图和场景/道具设定图存放在当前项目专属的媒体目录中，并在项目数据里用项目级 URL 引用；镜头首帧、调度帧、视频等可重生成产物 MUST 继续留在公共产物目录。

#### Scenario: 生成角色三视图
- **WHEN** 用户在当前项目对角色生成三视图
- **THEN** 生成文件写入该项目的媒体目录，角色卡引用项目级 URL，而不是公共产物路径

#### Scenario: 生成场景或道具设定图
- **WHEN** 用户在当前项目对场景/道具卡生成设定图
- **THEN** 设定图写入该项目的媒体目录，设定卡和发布到画布的素材卡都引用项目级 URL

#### Scenario: 镜头产物保持原状
- **WHEN** 用户生成镜头首帧、调度帧或视频
- **THEN** 这些文件仍写入公共产物目录，不复制进项目媒体目录

### Requirement: 项目媒体可正常访问和引用

系统 SHALL 通过项目级 URL 提供项目媒体文件，使浏览器可以直接显示，也能作为生图/视频的参考图被服务端解析；URL MUST NOT 能访问项目媒体目录以外的文件。

#### Scenario: 浏览器加载项目图片
- **WHEN** 角色卡用项目级 URL 渲染 `<img>`
- **THEN** 请求返回 200 和正确的图片内容

#### Scenario: 作为生图参考图
- **WHEN** 镜头出图把角色的项目级图片 URL 作为参考图提交
- **THEN** 服务端能解析到对应文件并转换为模型可用的参考图，不报路径不存在

#### Scenario: 路径穿越被拒绝
- **WHEN** 请求的项目名或文件名包含 `..`、绝对路径或其他越界片段
- **THEN** 系统拒绝请求，不读取项目媒体目录以外的文件

### Requirement: 旧参考图幂等迁移

系统 SHALL 在打开项目时把仍存在于公共产物目录的旧角色/设定图复制进项目媒体目录并改写引用；已缺失的文件 MUST 保持原引用并标记为缺失，MUST NOT 改写为无效的新路径。

#### Scenario: 旧图文件仍在
- **WHEN** 项目里的角色图引用是旧公共路径且文件仍然存在
- **THEN** 系统把文件复制到项目媒体目录，角色卡改用项目级 URL，图片正常显示

#### Scenario: 旧图文件已缺失
- **WHEN** 项目里的角色图引用是旧公共路径但文件已经不存在
- **THEN** 引用保持原样并进入缺失状态，不生成指向不存在文件的新 URL

#### Scenario: 重复打开项目
- **WHEN** 用户多次打开同一个项目
- **THEN** 迁移只复制一次，不产生重复文件，也不重复改写引用

#### Scenario: 迁移失败不阻塞项目
- **WHEN** 迁移过程中某个文件复制失败
- **THEN** 项目仍正常打开，失败项进入缺失状态并给出可读提示，其他角色和设定不受影响

### Requirement: 缺失参考图必须可见

系统 SHALL 在角色或设定图文件缺失时显示明确的缺失状态，并提供重新生成或清除引用的入口；MUST NOT 只显示空白图框，也 MUST NOT 把缺失文件静默当作可用参考图。

#### Scenario: 角色图文件缺失
- **WHEN** 项目加载后某个角色的图片文件不存在
- **THEN** 该角色卡显示「图片文件缺失」和重新生成入口，而不是空白图框

#### Scenario: 缺失状态刷新后保持
- **WHEN** 用户在缺失状态下刷新页面
- **THEN** 缺失提示仍然可见，不会误显示为已生成

#### Scenario: 缺失图不参与出图
- **WHEN** 某个镜头的角色参考图文件缺失，用户仍然发起出图
- **THEN** 系统给出明确的缺失文件提示，不发出带无效参考图的请求

#### Scenario: 清除缺失引用
- **WHEN** 用户选择清除某个缺失的图片引用
- **THEN** 该角色的图片和候选图被清空并持久化，角色卡回到待生成状态

### Requirement: 角色图片变更即时持久化

角色图片生成或上传完成后，系统 SHALL 立即持久化新的图片引用；MUST NOT 只依赖防抖窗口，用户在这些操作后立即刷新时 MUST 仍能看到图片。保存失败 MUST 给出可见提示。

#### Scenario: 生成后立即刷新
- **WHEN** 角色三视图生成完成并出现在卡片上，用户在防抖窗口内立即刷新
- **THEN** 刷新后角色和图片仍然存在

#### Scenario: 上传后立即刷新
- **WHEN** 用户上传角色图片后立即刷新
- **THEN** 刷新后图片仍然存在

#### Scenario: 保存失败有提示
- **WHEN** 角色图片引用写入项目失败
- **THEN** 系统显示保存失败提示，用户能重新尝试，不静默显示为已保存

### Requirement: 上传图片落盘

系统 SHALL 把用户上传的角色图片写入项目媒体目录，并以文件 URL 持久化；MUST NOT 把 dataURL 作为项目里长期保存的图片形式。

#### Scenario: 上传角色图片
- **WHEN** 用户为角色上传一张图片
- **THEN** 系统保存图片文件到项目媒体目录，项目数据里记录项目级 URL

#### Scenario: 上传后重新打开项目
- **WHEN** 用户上传图片后刷新或重新打开项目
- **THEN** 上传的图片正常显示

#### Scenario: 上传失败
- **WHEN** 图片写入失败或格式不被支持
- **THEN** 系统给出明确错误，不覆盖已有图片

### Requirement: 项目媒体随项目目录保留

项目媒体文件 SHALL 位于项目数据所在的目录树下；清理公共产物目录或在新工作区只保留 `projects/` 目录后，角色和设定图 MUST 仍然可显示。

#### Scenario: 清理公共产物目录
- **WHEN** `public/generated/` 被清空后重新打开项目
- **THEN** 已存入项目媒体目录的角色和设定图仍然显示

#### Scenario: 新工作区保留项目目录
- **WHEN** 用户把整个 `projects/` 目录搬到新的工作区并启动应用
- **THEN** 项目里的角色和设定图引用无需手工修复即可显示
