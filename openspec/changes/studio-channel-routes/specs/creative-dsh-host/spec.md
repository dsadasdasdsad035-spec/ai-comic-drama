# Spec Delta

## MODIFIED Requirements

### Requirement: 创意模型调用必须经过应用代理与账本

宿主发起的每一次文本模型调用 MUST 经应用现有代理出口，MUST 使用应用解析出的当前模型与渠道，MUST 继续受预扣与结算约束。系统 MUST NOT 允许宿主直连上游渠道，MUST NOT 出现绕过账本的模型调用路径。宿主可见的模型提供者 MUST 按应用渠道拆分，每个提供者与每个模型的显示名 MUST 取自应用设置；默认模型 MUST 指向本次同步写入的渠道路由，MUST NOT 悬空到已退场的路由。代理不可用或余额不足时 MUST 以可读错误结束该轮。

#### Scenario: 正常一轮对话

- **WHEN** 操作员在创意会话发送一条消息
- **THEN** 该轮模型调用出现在应用账本中，并按既有规则预扣与结算

#### Scenario: 余额不足

- **WHEN** 账本余额不足以支撑该轮调用
- **THEN** 该轮以可读的余额不足说明结束，不产生上游扣费

#### Scenario: 代理不可用

- **WHEN** 应用代理进程不可用
- **THEN** 该轮以可读错误结束，界面提示可重试

#### Scenario: 模型选择器按渠道分组

- **WHEN** 应用设置里存在多个可用文本模型的渠道，操作员打开宿主的模型选择器
- **THEN** 每个渠道呈现为一个独立分组，分组显示名与设置页的渠道显示名一致

#### Scenario: 选择器显示应用侧模型名

- **WHEN** 应用里某个文本模型配置了中文显示名
- **THEN** 宿主模型选择器中该条目显示该名称，而不是渠道侧的技术模型 id

#### Scenario: 各渠道路由共用同一出口

- **WHEN** 检查宿主的模型提供者配置
- **THEN** 每个渠道路由都指向应用自己的兼容门面地址，没有任何路由指向上游渠道地址

#### Scenario: 渠道退场后路由随之消失

- **WHEN** 操作员在设置页删除某个渠道，或该渠道不再有可用文本模型
- **THEN** 宿主配置中该渠道对应的提供者被移除，其余渠道的提供者保持可用

#### Scenario: 默认模型不悬空

- **WHEN** 应用完成一次模型配置同步
- **THEN** 默认模型的提供者等于该模型所属渠道对应的提供者，不指向本次写入之外的任何提供者

#### Scenario: 旧版本路由退场

- **WHEN** 应用从旧的单一提供者配置升级到按渠道拆分
- **THEN** 旧提供者被移除，默认模型改记为模型所属渠道的提供者，模型本身不变

#### Scenario: 无可用模型时保留兜底

- **WHEN** 应用没有任何可用文本模型
- **THEN** 宿主仍存在一条仅含占位模型的提供者，模型调用以可读的未配置说明结束，不回落到宿主内置的官方路由
