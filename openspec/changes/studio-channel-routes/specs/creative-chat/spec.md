# Spec Delta

## MODIFIED Requirements

### Requirement: 创意会话模型由宿主设置解析

创意会话的文本模型 SHALL 在宿主设置中选择并持久化，发送下一轮对话前更换 MUST 从下一轮生效。解析顺序 MUST 为宿主显式选择 > 设置页 `stageModels.creative` > 「文本 · 常规」默认。宿主侧一旦存在用户的显式选择，应用 MUST NOT 用设置页默认覆盖它。模型选择器 MUST 按应用渠道分组，条目 MUST 显示应用侧的模型显示名。创意视图 MUST NOT 再提供独立的文本模型下拉。解析不到可用模型时 MUST 以可读错误提示去设置页绑定。

#### Scenario: 宿主内更换模型

- **WHEN** 操作员在宿主设置中选择另一文本模型并保存
- **THEN** 下一轮对话使用新模型，界面不再出现第二处模型选择入口

#### Scenario: 无可用模型

- **WHEN** 三层解析都得不到可用文本模型
- **THEN** 界面显示可读的未配置说明，发送入口保持禁用

#### Scenario: 默认跟随设置页

- **WHEN** 操作员在设置页把「创意（对话助手）」改绑到另一渠道的文本模型并保存，且宿主侧没有用户的显式选择
- **THEN** 创意会话的默认模型变为该模型，并显示在它所属渠道的分组下

#### Scenario: 显式选择不被覆盖

- **WHEN** 操作员在宿主选择器里选定某模型后，设置页的「创意（对话助手）」又被改成另一个模型
- **THEN** 创意会话继续使用操作员在宿主里的选择

#### Scenario: 显示名变化即时生效

- **WHEN** 操作员修改某文本模型的显示名并保存
- **THEN** 宿主选择器在不需要重启宿主的情况下显示新名称

#### Scenario: 渠道内选模型

- **WHEN** 操作员在模型选择器里从某个渠道分组下选择模型
- **THEN** 该轮请求经应用门面路由到该渠道的模型
