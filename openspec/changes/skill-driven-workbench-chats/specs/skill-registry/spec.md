# Spec Delta

## Purpose

让剧本、角色、素材、镜头表、提示词与 3D 场景的提示词成为可在运行时加载、编辑和审计的技能数据，而不是写死在源码里的字符串；同时用锁定契约保证输出格式和工具边界不会被误改。

## ADDED Requirements

### Requirement: 技能是运行时加载的数据文件

系统 SHALL 从技能目录加载每个技能的 `SKILL.md`，其中 frontmatter 声明名称、描述、环节、运行时 profile、工具、输入、输出契约和版本，正文为可编辑提示词；新增或修改技能文件后 MUST 无需重新构建即可生效。

#### Scenario: 加载内置技能

- **WHEN** 技能目录中存在 `script`、`character`、`asset`、`shotlist`、`prompt`、`scene3d` 六个技能文件
- **THEN** 技能注册表能列出全部技能及其描述、环节和版本

#### Scenario: 文件格式错误

- **WHEN** 某个技能文件缺少名称、描述或输出契约，或 frontmatter 无法解析
- **THEN** 该技能不进入可用列表，并返回包含文件路径和缺失字段的可读错误，其他技能仍可用

#### Scenario: 热更新

- **WHEN** 用户修改技能文件后重新打开工作台或刷新技能列表
- **THEN** 新内容生效，不要求重新构建应用

### Requirement: 技能正文与输入模板共同构成提示词

技能 SHALL 支持带占位符的输入模板，占位符 MUST 对应 frontmatter 声明的输入。一次性生成 SHALL 用工作台当前输入渲染模板；聊天 MUST 使用同一模板和同一组输入来源，大输入 MAY 通过读工具按范围读取，MUST NOT 使用与生成不同的提示词来源。必需输入缺失时 MUST 在发送前返回明确错误，MUST NOT 用空字符串静默渲染。

#### Scenario: 输入齐全

- **WHEN** 镜头表技能声明 `style`、`aspect`、`brief`、`target` 四个输入且工作台都有值
- **THEN** 生成按钮改用这些输入渲染模板，聊天使用同一组输入和同一份技能正文，两者不出现两套提示词

#### Scenario: 大输入按需读取

- **WHEN** 原著全文较长，用户在剧本聊天中要求改写某一集
- **THEN** 聊天不把全文重复塞进每轮上下文，模型通过读工具按集读取同一份原著输入

#### Scenario: 缺少必需输入

- **WHEN** 本集内容为空时用户从聊天触发镜头表技能
- **THEN** 发送前提示“本集内容为空”，不发起模型请求

#### Scenario: 模板占位符未声明

- **WHEN** 技能正文使用了 `{{unknown}}` 但 frontmatter 未声明该输入
- **THEN** 技能校验失败并指出未知占位符

### Requirement: 可编辑层与锁定契约分离

技能 SHALL 区分用户可编辑的角色/任务/约束/示例与运行时追加的锁定契约；锁定契约 MUST 由 `contracts` 声明的契约 id 解析，MUST NOT 允许用户通过编辑正文删除或改写输出 schema、工具 ABI、安全规则和 JSON 协议。

#### Scenario: 编辑正文不影响契约

- **WHEN** 用户改写 `scene3d` 技能的角色描述并保存
- **THEN** 下一次运行仍包含完整的代码 ABI、工具调用协议和安全限制

#### Scenario: 引用未知契约

- **WHEN** 技能 frontmatter 声明了运行时未注册的契约 id
- **THEN** 该技能加载失败并列出可用契约 id，MUST NOT 以缺失契约的方式继续运行

#### Scenario: 锁定段只读

- **WHEN** 用户在设置页查看 `scene3d` 技能
- **THEN** 可编辑正文可以修改，锁定契约段以只读方式展示，不能保存修改

### Requirement: 内置技能与用户覆盖分层

系统 SHALL 以技能目录中的内置文件为默认值，并允许设置页保存按技能 id 的用户覆盖；读取时 MUST 合并为“内置默认 + 用户覆盖”，恢复默认 MUST 删除覆盖而不修改内置文件。旧版按环节保存的规则包 MUST 迁移为对应技能的覆盖或迁移记录。

#### Scenario: 保存用户覆盖

- **WHEN** 用户修改剧本技能正文并保存
- **THEN** 后续渲染使用用户版本，设置页显示来源为“用户覆盖”

#### Scenario: 恢复默认

- **WHEN** 用户点击恢复默认
- **THEN** 删除该技能的覆盖，重新使用内置文件内容

#### Scenario: 内置文件升级

- **WHEN** 应用升级改动了内置技能文件且用户已有覆盖
- **THEN** 用户覆盖继续生效，设置页显示内置版本与用户版本的差异提示，不静默覆盖用户内容

#### Scenario: 迁移旧规则包

- **WHEN** 旧设置中存在 `rules.script` 等规则包
- **THEN** 迁移到对应技能的覆盖或迁移记录，原有文本、启用状态和用户改写不丢失

### Requirement: 两级加载控制提示词成本

技能注册表 SHALL 只常驻技能的 `name` 与 `description`；技能正文和工具 schema MUST 仅在技能被激活后注入；运行时 MUST 限制同一线程同时激活的技能数量，并对超出上限的加载请求返回可读提示。

#### Scenario: 初始加载

- **WHEN** 用户打开某个工作台聊天
- **THEN** 模型只看到可用技能的简短目录，而不是全部技能正文

#### Scenario: 激活技能

- **WHEN** 用户点选或确认加载某个技能
- **THEN** 该技能正文和声明的工具 schema 才进入本轮上下文

#### Scenario: 超过激活上限

- **WHEN** 线程已激活技能数量达到上限，用户再加载一个技能
- **THEN** 提示先卸载一个已激活技能，不静默丢弃或全部注入

### Requirement: 技能声明环节、工具与输出契约

技能 frontmatter 的 `stage` SHALL 决定该技能使用的模型环节，`tools` MUST 只能引用运行时已注册的工具 id，`output` MUST 引用已注册的输出契约；声明不合法时 MUST 拒绝加载该技能并保持其他技能可用。

#### Scenario: 合法声明

- **WHEN** 提示词技能声明 `stage: prompt`、`tools: [read_shots, read_characters, submit_prompts]`、`output: prompts-v1`
- **THEN** 加载后使用提示词环节模型，只绑定这三个工具

#### Scenario: 引用未注册工具

- **WHEN** 技能声明了不存在的工具 id
- **THEN** 加载失败并列出未知工具，不把该技能暴露给模型

#### Scenario: 输出契约缺失

- **WHEN** 技能声明的 `output` 不在已注册输出契约中
- **THEN** 加载失败并提示可用契约 id

### Requirement: 技能来源与版本可审计

每次运行 SHALL 记录本轮激活的技能 id、版本、来源（内置文件或用户覆盖）和输入的键；用户 MUST 能在发送前检查器和运行后的审计卡中看到这些信息。

#### Scenario: 使用内置技能

- **WHEN** 用户用默认剧本技能生成
- **THEN** 审计卡显示技能 `script`、内置版本和输入键

#### Scenario: 使用用户覆盖

- **WHEN** 用户使用改写过的提示词技能
- **THEN** 审计卡显示来源为“用户覆盖”及版本，能与内置版本区分

#### Scenario: 发送前查看

- **WHEN** 用户打开“查看将发送”
- **THEN** 能看到技能名称、来源、版本和本轮输入，而不只是最终提示词

### Requirement: 技能文件只作为数据执行

技能文件 MUST 只被当作提示词和声明数据读取，MUST NOT 被当作可执行脚本；服务端 MUST 只读取技能目录内符合命名规则的文件，拒绝路径穿越和超过大小上限的文件。

#### Scenario: 文件包含脚本

- **WHEN** 技能正文包含 `<script>`、可执行代码块或工具调用伪代码
- **THEN** 它们作为普通文本进入提示词，不被执行

#### Scenario: 路径穿越

- **WHEN** 请求的技能 id 包含 `../` 或绝对路径
- **THEN** 服务端拒绝读取并返回错误

#### Scenario: 超大文件

- **WHEN** 技能文件超过配置的大小上限
- **THEN** 该技能被拒绝加载并提示大小上限，其他技能不受影响

### Requirement: 新增只读技能不需要改代码

系统 SHALL 允许只声明读工具、输出文本建议的技能仅通过新增技能文件出现在技能目录中；需要写入新产物的技能 MUST 先在运行时注册对应写工具和输出契约，MUST NOT 仅靠技能文件获得写能力。

#### Scenario: 新增诊断技能

- **WHEN** 用户新增一个只声明读工具、无写工具的技能文件
- **THEN** 该技能出现在可加载列表，激活后可以读项目数据并给出建议，不能写任何产物

#### Scenario: 技能要求未注册的写能力

- **WHEN** 技能声明写工具但运行时没有注册该工具
- **THEN** 技能加载失败，提示先注册工具
