# Spec Delta

## MODIFIED Requirements

### Requirement: 运行轨迹必须可审计

运行时 MUST 记录每次模型调用、工具调用、工具结果、渲染作业标识、失败原因、修复次数，以及本轮使用的技能 id、来源与版本，并通过可消费的事件流逐步提供给聊天 UI；MUST NOT 暴露模型隐藏推理或 chain-of-thought，只展示可观察动作、参数摘要、面向用户的简短说明和结果。

#### Scenario: 成功轨迹

- **WHEN** agent 完成场景
- **THEN** 轨迹包含模型轮次、工具顺序、每次渲染结果和验收结论

#### Scenario: 失败轨迹

- **WHEN** agent 达到上限失败
- **THEN** 轨迹保留失败步骤和错误，不删除中间记录

#### Scenario: 不展示隐藏推理

- **WHEN** 聊天渲染轨迹
- **THEN** 只显示工具事件、模型面向用户的简短说明和摘要，不显示模型内部思维过程

#### Scenario: 模型轮次事件

- **WHEN** agent 调用一次模型
- **THEN** 事件流产生该轮开始和结束事件，结束事件包含可展示的简短说明或明确的空说明状态

#### Scenario: 事件去重

- **WHEN** 同一工具调用同时产生生命周期事件和领域结果
- **THEN** 事件带有稳定标识，消费方更新同一张卡片，不产生重复的孤立卡片

#### Scenario: 技能溯源

- **WHEN** 一轮运行使用了内置或用户覆盖的 `scene3d` 技能
- **THEN** 审计记录能区分技能来源与版本，用户能在发送前检查器和运行后审计中看到

## ADDED Requirements

### Requirement: 场景提示词由技能注册表提供

3D 运行时 SHALL 从 `scene3d` 技能加载可编辑的角色与任务描述，并在其后追加代码 ABI、工具调用协议和安全规则等锁定契约；MUST NOT 在技能正文之外注入与当前技能冲突的固定身份。用户覆盖技能 MUST NOT 改变锁定契约。

#### Scenario: 默认加载

- **WHEN** 用户打开 3D 聊天
- **THEN** 本轮系统提示由 `scene3d` 技能正文与完整的锁定契约组成，模型能看到 build/pose/dispose 与工具协议

#### Scenario: 用户改写角色描述

- **WHEN** 用户修改 `scene3d` 技能正文后运行
- **THEN** 新的角色描述生效，代码 ABI、工具协议和安全限制保持完整

#### Scenario: 不注入冲突身份

- **WHEN** 运行时组装系统提示
- **THEN** 不额外加入写死的“你是 3D 场景 agent”身份前缀；面向用户的说明语言由技能正文决定

#### Scenario: 只读技能不改 3D 契约

- **WHEN** 用户在 3D 线程加载一个只读技能
- **THEN** 只读技能不能替换 `scene3d` 的锁定契约，也不能获得写代码或渲染工具
