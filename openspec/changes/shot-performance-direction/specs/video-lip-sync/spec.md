# Spec Delta

## Purpose

让对白镜头的口型可以被明确选择、执行和验收：默认不改变现有出片，开启后能强化嘴部提示，或手动调用外部口型服务，并以静音段/发声段抽帧判定是否通过。

## ADDED Requirements

### Requirement: 镜头可选择口型模式

每个镜头 SHALL 保存 `off`、`prompt` 或 `provider` 三档口型模式，旧镜头默认 `off`。`prompt` 只影响首帧/视频提示词；`provider` 需要已接受的视频与台词音频。切换模式 MUST NOT 删除已接受视频、已生成口型结果或现有配音。

#### Scenario: 默认关闭

- **WHEN** 打开一个旧项目或新镜头
- **THEN** 口型模式为 off，视频生成与现在完全一致

#### Scenario: 提示词模式

- **WHEN** 用户把对白镜头切到 prompt
- **THEN** 后续首帧/视频提示词写入说话状态与嘴部动作，不提交任何口型服务任务

#### Scenario: 缺少输入

- **WHEN** 镜头没有视频或没有带台词的配音，用户切到 provider
- **THEN** provider 入口显示缺少视频或音频，不发起任务

#### Scenario: 切回关闭

- **WHEN** 用户从 provider 切回 off
- **THEN** 已生成的口型结果和原视频都保留，播放按 off 使用原视频

### Requirement: 多说话人镜头限制 provider 模式

provider 模式 SHALL 只用于单说话人镜头。镜头包含两个或更多说话人且没有按说话人分段时，系统 MUST 禁用 provider 并说明原因，不得把混合音轨交给只支持单脸的 provider；prompt 模式仍可用于这类镜头。

#### Scenario: 单说话人

- **WHEN** 镜头只有 A 一句台词
- **THEN** provider 模式可用，音频使用 A 的台词音轨

#### Scenario: 多说话人未分段

- **WHEN** 镜头里 A 和 B 都有台词，且没有按说话人拆分音频
- **THEN** provider 模式禁用并提示拆成单人镜或等待分段支持，prompt 模式仍可用

#### Scenario: 画外音

- **WHEN** 镜头里只有一个人物在画面内说话，另一句是画外音
- **THEN** 只有画面内说话人进入 provider，画外音不驱动口型

### Requirement: Provider 模式必须手动确认

provider 模式 SHALL 只允许用户对单个镜头手动发起，并在提交前展示 provider、源视频、台词音频、预计时长、估算成本和是否覆盖已有口型结果。MUST NOT 在批量出片、批量重生成或后台任务中自动提交口型服务。

#### Scenario: 提交前预览

- **WHEN** 用户点“生成口型”
- **THEN** 系统先展示本次任务参数和成本，用户确认后才提交

#### Scenario: 批量任务

- **WHEN** 用户批量重生成一集视频
- **THEN** 不会自动为任何镜头提交口型服务

#### Scenario: 缺少 Key

- **WHEN** 当前口型 provider 没有配置 Key
- **THEN** 系统提示去设置页配置，不发起请求，也不自动改用其他 provider

### Requirement: 口型结果与源视频分离

口型结果 MUST 作为独立版本保存，包含源视频指纹、音频指纹、provider、状态和输出路径；MUST NOT 直接覆盖已接受视频。成功结果由用户采用后才进入预览与导出；失败或取消时原视频保持可用。

#### Scenario: 成功待采用

- **WHEN** 口型服务成功返回视频
- **THEN** 原视频和口型视频都保留，界面提供“采用口型版”和“保留原版”

#### Scenario: 失败

- **WHEN** 口型服务返回错误或超时
- **THEN** 原视频仍可播放和导出，失败原因可读，不产生半成品

#### Scenario: 采用

- **WHEN** 用户采用口型版
- **THEN** 该镜头的预览与导出使用口型视频，仍保留切回原版的入口

#### Scenario: 源或音频变化

- **WHEN** 源视频或台词音频变化
- **THEN** 已有口型结果标记为需要重做，不自动删除

### Requirement: 口型验收以抽帧结果为准

系统 SHALL 对口型结果和 prompt 模式的成片抽帧验收：静音段取帧检查嘴部闭合，发声段取帧检查嘴部打开或运动，并记录时间点、帧路径和判定。默认把“静音张嘴”或“发声闭嘴”判为不通过；用户 MUST 能带理由忽略单个告警。

#### Scenario: 静音张嘴

- **WHEN** 静音段抽到的帧嘴部明显张开
- **THEN** 该镜标记为口型未通过，不自动采用结果

#### Scenario: 发声闭嘴

- **WHEN** 发声段抽到的帧嘴部完全闭合且没有运动
- **THEN** 该镜标记为口型未通过，提示重做或换镜头

#### Scenario: 没有音频

- **WHEN** 镜头没有台词音频
- **THEN** 系统不做口型验收，并说明缺少音频而不是报告通过

#### Scenario: 人工忽略

- **WHEN** 用户确认某个静音段张嘴是表演需要并填写理由
- **THEN** 该告警不再阻止采用，理由和帧记录保留

### Requirement: 口型服务配置默认关闭且错误可读

设置页 SHALL 提供独立的口型 provider 配置，默认关闭；Key MUST 只保存在设置库或本地凭据，不得写入项目、日志或证据文件。鉴权失败、额度不足、输入不合规和服务错误 MUST 返回可读原因，不得自动回退到其他 provider。

#### Scenario: 默认关闭

- **WHEN** 用户没有配置任何口型 provider
- **THEN** 所有镜头只能用 off 或 prompt，provider 入口显示未配置

#### Scenario: 鉴权失败

- **WHEN** provider 返回 401 或 403
- **THEN** 界面显示鉴权失败和配置入口，不重试其他 provider

#### Scenario: Key 不落项目

- **WHEN** 用户保存项目、导出项目或生成证据
- **THEN** 项目文件、日志和证据中不包含口型 provider 的 Key

### Requirement: 采用后预览与导出使用口型版本

用户采用口型版后，预览、时间线和导出 SHALL 使用口型视频；台词音频 MUST 仍使用原配音轨，字幕不得重复或改变。切回原版后 MUST 恢复原视频，口型结果继续保留。

#### Scenario: 导出采用口型版

- **WHEN** 用户采用口型版并导出
- **THEN** 成片使用口型视频，配音与字幕位置保持不变

#### Scenario: 切回原版

- **WHEN** 用户从口型版切回原版并导出
- **THEN** 成片使用原视频，口型结果仍可在之后重新采用

#### Scenario: 项目重载

- **WHEN** 用户重新打开项目
- **THEN** 口型模式、采用状态、原视频与口型视频都恢复
