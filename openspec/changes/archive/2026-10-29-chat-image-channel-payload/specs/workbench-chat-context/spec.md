# Spec Delta

## REMOVED Requirements

### Requirement: 图片附件先经视觉理解

**Reason**: 图片不再先交给另一个视觉模型写成摘要。本轮图片与用户文字一起交给当前聊天模型。

**Migration**: 能看图的渠道直接收到每张原图。不能看图的渠道改为「渠道不能看图时明确占位」。参考板与视觉摘要不再生成。

### Requirement: 无视觉模型时明确降级

**Reason**: 降级条件从「有没有单独的视觉模型」改为「当前聊天渠道能不能接收图片」。

**Migration**: 见「渠道不能看图时明确占位」与「单张图片无法送出时不阻断消息」。

### Requirement: 视觉理解必须先于同步渲染算好

**Reason**: 发送前不再预调用视觉模型，因此没有需要缓存的理解结果，也不再因理解未完成而拦住发送。

**Migration**: 加入图片不得禁用输入框，也不得在发送前调用视觉模型。图片随本轮用户消息送出。

## ADDED Requirements

### Requirement: 图片与文字一起交给当前模型

本轮仍挂着的图片 MUST 与该轮用户文字处于同一条用户消息。多张图片 MUST 各自独立送出，MUST NOT 先拼成一张参考板，MUST NOT 先经另一个视觉模型转成文字摘要。

#### Scenario: 单张图与文字同发

- **WHEN** 用户加入一张参考图并发送一句要求
- **THEN** 当前聊天模型在同一条用户消息里同时收到这张图和这句要求

#### Scenario: 多张图保持独立

- **WHEN** 用户加入三张参考图后发送
- **THEN** 模型收到三张互相独立的图片，而不是一张拼板或三段外观摘要

#### Scenario: 不再预调用视觉模型

- **WHEN** 用户加入图片到发送完成
- **THEN** 系统不调用单独的视觉理解接口，输入框保持可用，发送不被「正在理解」拦住

### Requirement: 渠道不能看图时明确占位

当前聊天模型所在渠道不接受图片内容，或该模型未声明可看图时，系统 MUST NOT 把图片数据当作正文文本送出。每张这样的图片 MUST 换成说明该图未送入模型的文字占位，用户 MUST 能在发送前或本轮回执里看到这个说明。

#### Scenario: Agent Plan 渠道

- **WHEN** 当前聊天模型走 Agent Plan 渠道，用户带一张图发送
- **THEN** 请求里没有图片数据，消息中改为该图未送入模型的占位说明

#### Scenario: 模型未声明可看图

- **WHEN** 渠道能接收图片，但当前模型未声明可看图
- **THEN** 该图同样改为占位说明，不把图片数据送进请求

#### Scenario: 能看图的渠道

- **WHEN** 渠道接受图片内容且当前模型声明可看图
- **THEN** 每张图以图片内容送出，不替换成占位

### Requirement: 单张图片无法送出时不阻断消息

某一张图片无法读取或超过单张 4MB 时，系统 MUST 只将该张换成说明原因的占位，MUST NOT 因此让整条消息发送失败。其余可读且未超限的图片仍按渠道规则送出。

#### Scenario: 一张图损坏

- **WHEN** 本轮有两张图，其中一张无法解码
- **THEN** 消息仍然发送；损坏的那张变为占位，另一张按渠道规则送出

#### Scenario: 超过单张上限

- **WHEN** 一张图解码后超过 4MB
- **THEN** 该张变为说明超限的占位，同条消息里的文字和其他合格图片仍送出

## MODIFIED Requirements

### Requirement: 每轮调用留下可审计的上下文

系统 MUST 为每一轮模型调用记录本轮实际发送的上下文摘要（附件数量、类型分布、每个附件的标签），并 MUST 能与该轮消息对应。图片附件 MUST 额外记录它是以图片送出还是被替换为占位及原因。审计记录 MUST 在会话内可查看，MUST NOT 只保留在内存中随时丢失而不提示。

#### Scenario: 查看本轮上下文

- **WHEN** 用户点开某一轮消息的上下文卡
- **THEN** 显示该轮的附件清单与数量，与发送时一致；每张图标明是已送出还是占位

#### Scenario: 两轮附件不同

- **WHEN** 用户第一轮带图、第二轮不带图
- **THEN** 两轮的上下文卡分别反映各自的附件，不互相覆盖
