# Spec Delta

## ADDED Requirements

### Requirement: 用户图片保持到渠道出口再转换

用户消息中的图片 MUST 保持为图片，直到服务端代理按渠道转换。代理 MUST NOT 在转换前把图片数据拼进普通文本。接受图片内容的渠道 MUST 把每张图转成该渠道的图片内容块，与同一条用户消息里的文字一起提交。不接受图片内容的渠道 MUST 把每张图换成说明未送入模型的文字占位。

#### Scenario: 接受图片的渠道

- **WHEN** 用户消息带有两张图片，且当前渠道接受图片内容、模型声明可看图
- **THEN** 提交给渠道的该条用户消息同时包含文字和两张图片内容

#### Scenario: 不接受图片的渠道

- **WHEN** 用户消息带有图片，且当前渠道不接受图片内容
- **THEN** 提交给渠道的消息不含图片数据，对应位置是说明未送入的占位文字

#### Scenario: 历史轮次不重复带上旧图

- **WHEN** 用户发送新的一轮，输入区里已经没有上一轮曾经用过、后来移除的图片
- **THEN** 新请求不包含那张已移除的图片

## MODIFIED Requirements

### Requirement: 工具结果必须分离模型可见与界面可见内容

工具执行结果 SHALL 同时提供模型可见摘要与界面可见详情。模型可见内容 MUST 只包含摘要与必要提示，MUST NOT 包含图片数据地址、视频数据地址或整段代码正文；界面可见内容 MUST 保留完整结果供工具卡片渲染。本约束只适用于工具结果，不适用于用户消息里由用户附加的图片。

#### Scenario: 抓帧结果

- **WHEN** 工具返回关键帧
- **THEN** 模型只收到帧数量与时间点摘要，界面仍能显示缩略图

#### Scenario: 代码提交结果

- **WHEN** 工具提交或修改代码
- **THEN** 模型只收到行数、字符数与内容哈希摘要，完整代码留在草稿与界面

#### Scenario: 工具结果不夹带用户附件

- **WHEN** 同一轮里用户消息带有图片，工具随后返回结果
- **THEN** 工具结果仍只有文字摘要，不把用户那张图片或工具自己的图片数据放进工具回传
