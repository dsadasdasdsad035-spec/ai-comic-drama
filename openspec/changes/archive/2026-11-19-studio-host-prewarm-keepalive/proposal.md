# Proposal

## Why

创意视图每次进入都要冷启动 dsh 宿主（源码注释自述"可能十几秒"），并重新加载宿主前端（约 22 MB 产物 + Cordis 插件树激活 + 激活审计）；切走时条件渲染销毁 iframe，切回再付一次。应用内其它视图切换是亚毫秒的组件替换，这条差异让创意视图在体感上像"另一个软件"。这两个成本都不是用户操作带来的必要成本：宿主可以在后台先起来，前端文档可以在首次进入后复用。

## What Changes

- **宿主空闲预热**：应用监听端口成功后，在应用自身首屏稳定之后异步拉起宿主，把首次进入的冷启动挪到后台。预热受创意入口开关（`studioEnabled`）约束，只在宿主处于 `idle` 时触发，失败不自动重试——错误页上的「重试」仍是唯一显式入口。
- **创意视图首次进入后常驻**：首次访问才创建 iframe；之后用 `display: none` 隐藏而不是卸载，切回时保留会话列表、滚动位置、输入草稿与 WebSocket 连接。首次进入仍按需挂载，避免应用启动时与主 bundle 抢带宽。
- **加载期观感对齐**：应用侧在 iframe 文档可用时立即注入一条样式隐藏宿主的品牌启动页（`[data-dsh-boot]`），改用应用自己的三栏骨架；失败态仍由应用自己的中文错误页与「重试」承担。
- **可量化的就绪与复用验收**：新增宿主就绪时间、切页往返是否重建 iframe 文档、常驻内存基线三项验收口径，并写入 `docs/creative-host.md`。
- **明确内存代价与开关**：常驻宿主进程与常驻宿主前端的内存计入部署说明，并提供环境变量关闭常驻与预热。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `creative-dsh-host`: 新增「创意入口就绪不被首次访问阻塞」与「加载期呈现应用自有加载态」两项要求；保留原有「宿主不可用时给出可读错误」「访问控制」「模型调用经代理」不变。
- `creative-layout`: 新增「创意视图往返不重建宿主文档」要求，与既有「导航位置稳定」「只呈现宿主对话外壳」并列。

## Impact

- 代码：`server/index.mjs`（空闲预热）、`src/App.tsx`（首次挂载 + 常驻容器）、`src/theme.css`（隐藏容器样式）、`src/creative/StudioFrame.tsx`（提前注入隐藏启动页、骨架替换）。
- 文档：`docs/creative-host.md`（预热、常驻、内存基线、关闭开关）。
- 测试：`tests/studio-*` 新增就绪与常驻用例；沿用 `npm run test:studio` 入口。
- 资源：常驻宿主进程与常驻前端各占一份内存；预热期间宿主启动会短暂占用 CPU 与磁盘。
- 非目标：不修改 `deepseek-harness` 子模块；不改变 `/studio/` 的鉴权、反代、WebSocket 透传与模型出口；不改变 `DSH_HOME` 布局。
