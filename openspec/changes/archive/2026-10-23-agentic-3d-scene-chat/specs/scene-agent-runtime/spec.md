# Spec Delta

## Purpose

让 3D 调度聊天从一次性代码生成升级为可观察、可取消、受限修复的多步场景 agent，并通过沙箱与视觉验收判断场景是否真的生成。

## ADDED Requirements

### Requirement: 聊天由多步工具循环驱动

3D 聊天 SHALL 由有状态的多步循环驱动，至少支持读取镜头上下文、提交代码、沙箱运行、抓取关键帧、视觉验收和结束；每一步 MUST 产生可观察的开始/结束状态，MUST NOT 只返回最终文本。

#### Scenario: 正常多步执行

- **WHEN** 用户要求生成一个新场景
- **THEN** 聊天按顺序产生上下文读取、代码提交、沙箱运行、抓帧和验收步骤

#### Scenario: 工具失败

- **WHEN** 某一步工具失败
- **THEN** 该步骤显示失败原因，后续步骤不假装成功

#### Scenario: 最终回答

- **WHEN** 循环正常结束
- **THEN** 聊天给出最终摘要，并保留完整工具轨迹

### Requirement: 模型调用必须经过服务端代理

agent 的模型调用 MUST 通过应用服务端代理完成，浏览器 MUST NOT 持有模型渠道 API Key；模型适配层 MUST 只消费服务端返回的文本/JSON，不得把 Key 写入聊天、项目或日志。

#### Scenario: 正常模型调用

- **WHEN** agent 需要生成或修复代码
- **THEN** 浏览器请求本地代理，服务端再调用配置的模型渠道

#### Scenario: 缺少模型 Key

- **WHEN** 当前代码模型渠道没有可用 Key
- **THEN** agent 以可读错误结束，不把请求伪装成成功

#### Scenario: 不泄露 Key

- **WHEN** 聊天轨迹或项目被保存
- **THEN** 不包含模型 Key 或渠道鉴权头

### Requirement: agent 工具集受控且最小化

运行时 SHALL 只向 agent 暴露受控工具：读取当前镜头上下文、提交场景代码、沙箱试运行、抓取关键帧、视觉验收和结束。工具 MUST NOT 提供任意 shell、文件写入、网络请求、跨镜头修改或自动保存/渲染能力。

#### Scenario: 允许的上下文读取

- **WHEN** agent 调用上下文工具
- **THEN** 只返回当前镜头、参考内容和当前代码的摘要

#### Scenario: 禁止越权

- **WHEN** agent 尝试修改其他镜头或访问网络
- **THEN** 没有可用工具能完成该操作，请求被拒绝

#### Scenario: 不自动保存

- **WHEN** agent 完成代码和验收
- **THEN** 代码只作为草稿，保存仍需用户操作

### Requirement: 代码必须通过沙箱才能成为草稿

agent 提交的代码 MUST 先经过大小/入口/静态检查，并在沙箱执行 `init`、`renderAt(0)` 和 `renderAt(duration)`；失败、超时或未产生可渲染画面时 MUST NOT 覆盖上一版代码。

#### Scenario: 代码运行成功

- **WHEN** agent 提交的代码通过沙箱试运行
- **THEN** 代码进入当前镜头的草稿并更新预览

#### Scenario: 首帧失败

- **WHEN** 代码首帧没有绘制对象
- **THEN** 工具返回错误，代码不进入草稿

#### Scenario: 运行超时

- **WHEN** 代码在初始化或单帧中超时
- **THEN** 沙箱被终止，旧代码继续有效

### Requirement: 修复与验收循环必须有上限

运行时 MUST 限制代码生成/修复轮次和视觉验收轮次，达到上限 MUST 停止并返回可读失败结果；用户取消或整体超时 MUST 立即中止循环并保留上一版有效代码。

#### Scenario: 修复成功

- **WHEN** 沙箱返回错误且修复次数未超限
- **THEN** agent 可以提交新代码并再次试运行

#### Scenario: 达到修复上限

- **WHEN** 连续修复达到配置上限仍未通过
- **THEN** 循环停止，显示失败原因和已尝试次数

#### Scenario: 用户取消

- **WHEN** 用户在工具执行中取消
- **THEN** 后续工具不执行，旧代码和视频不被改动

#### Scenario: 整体超时

- **WHEN** 整个 agent 运行超过时限
- **THEN** 运行被终止并显示超时，不写入半成品

### Requirement: 视觉验收基于关键帧和明确清单

视觉验收工具 SHALL 抓取当前代码场景的关键帧，并依据明确清单判断场景内容；验收结果 MUST 包含通过/失败项和缺失项，MUST NOT 只返回一句“看起来不错”。没有视觉模型时 MUST 明确回退为人工验收，不得伪造通过。

#### Scenario: 抓取关键帧

- **WHEN** 沙箱运行成功
- **THEN** 至少抓取开头、中段和结尾帧供验收

#### Scenario: 清单失败

- **WHEN** 画面缺少山体、人物或剑
- **THEN** 验收返回具体缺失项，agent 可据此修复

#### Scenario: 没有视觉模型

- **WHEN** 项目未配置视觉模型
- **THEN** agent 标记自动验收不可用，等待人工检查，不把结果标为通过

### Requirement: 验收场景必须生成山、两人双剑对打和环绕镜头

验收场景 SHALL 要求：山体/地形背景；一名男人和一名女人；两人各持剑对打；镜头从远处环绕飞行并始终正对两人；4 秒、16:9、clean。验收 MUST 同时检查代码、关键帧、视频和清单，不能只检查最终文本。

#### Scenario: 场景内容通过

- **WHEN** 验收场景运行完成
- **THEN** 关键帧中能看到山体、两个可区分人物、两把剑和双人对打

#### Scenario: 镜头环绕

- **WHEN** 对比不同时间的关键帧
- **THEN** 相机位置随时间变化，但两人始终在画面内且位于视觉中心附近

#### Scenario: 场景内容失败

- **WHEN** 缺少山、人物、剑或环绕运动
- **THEN** 验收不通过，并列出缺失项

### Requirement: agent 只能修改当前镜头

agent 的所有代码、选择和运行状态 MUST 只作用于打开工作台的当前镜头，MUST NOT 修改上一镜、下一镜、同场其他镜头或项目级素材。

#### Scenario: 当前镜代码

- **WHEN** agent 提交新代码
- **THEN** 只有当前镜头的 sceneCode 草稿变化

#### Scenario: 其他镜头

- **WHEN** 当前镜 agent 运行结束
- **THEN** 其他镜头的代码、选择和视频状态不变

#### Scenario: 项目级资源

- **WHEN** agent 需要参考素材
- **THEN** 只读取当前镜头选择的素材，不修改项目素材库

### Requirement: 运行轨迹必须可审计

运行时 MUST 记录每次模型调用、工具调用、工具结果、失败原因和修复次数，并能返回给聊天 UI；MUST NOT 暴露模型隐藏推理或 chain-of-thought，只展示可观察动作、参数摘要和结果。

#### Scenario: 成功轨迹

- **WHEN** agent 完成场景
- **THEN** 轨迹包含工具顺序、每次沙箱结果和验收结论

#### Scenario: 失败轨迹

- **WHEN** agent 达到上限失败
- **THEN** 轨迹保留失败步骤和错误，不删除中间记录

#### Scenario: 不展示隐藏推理

- **WHEN** 聊天渲染轨迹
- **THEN** 只显示工具事件和摘要，不显示模型内部思维过程

### Requirement: mock 与真实模型验收必须分开

测试 SHALL 提供不消耗真实模型的 mock agent 图验收，以及使用真实模型的手动/半自动验收。mock 验收 MUST 覆盖工具事件、沙箱、抓帧、清单和代码应用；真实模型验收 MUST 生成山/男女/双剑/环绕场景并保存关键帧、视频和清单。

#### Scenario: mock 图测试

- **WHEN** 在 CI 运行 mock agent 测试
- **THEN** 不发起真实模型调用，验证完整工具链和 UI 事件

#### Scenario: 真实模型验收

- **WHEN** 使用配置的代码模型运行验收场景
- **THEN** 保存代码、关键帧、4 秒视频和验收结果供人工确认
