# Acceptance：转场首尾帧手动选择

## 数据边界

- [ ] 新转场首次打开「选择出片参考 → 首尾帧」时，`generated.boundary` 不存在或为空，两槽显示「未选择」
- [ ] 点选候选后写入 `generated.boundary.out` / `in` 与 `outFrom` / `inFrom`，随 `project.json` 落库
- [ ] 旧项目已有 `boundary` 原样展示，无来源字段时标签为中性「已选画面」
- [ ] `outFrom` 写入非枚举值时不落库（normalize 丢弃），不影响出片

## 槽位交互

- [ ] 空边界下弹窗仍渲染首帧、尾帧两个槽位（不再显示「当前模式无首尾帧槽位」）
- [ ] 候选顺序：首帧以上镜画面开头，尾帧以下镜画面开头；两侧画面都可选
- [ ] 点选候选 → 槽位高亮并写入；再次点同一候选 → 取消并清空该槽
- [ ] 「清除」按钮仅在槽位有值时可用
- [ ] 手填地址与点选共用同一字段；点选会覆盖手填值
- [ ] 「媒体库…」打开图片选择器，确认后写入并标 `library`

## 抽取语义

- [ ] 点「抽取两镜成片帧」后只在对应槽位的候选区新增「上镜尾帧（本次抽取）」「下镜首帧（本次抽取）」
- [ ] 抽取前后 `generated.boundary` 不变
- [ ] 上镜抽帧失败时提示失败，首帧槽保持原有选择或空值
- [ ] 两镜都没有成片/静帧时，抽取失败但现成画面候选与媒体库入口仍可用

## 生成路径

- [ ] 缺任一槽时面板 footnote 与底栏按钮为 blocking 状态，文案要求「选择」而不是「刷新」
- [ ] 两槽都选好后点生成，请求 `transition.boundaryOut/boundaryIn` 与所选 URL 完全一致
- [ ] 两镜都有成片时生成，不触发抽帧（`extractFrames` 调用计数为 0）
- [ ] 生成成功后不写回任何自动抽取结果，已选边界保持
- [ ] 绕过面板直接提交缺边界请求，服务端 400 文案要求先手动选择

## 标签与提示词

- [ ] 媒体库来源的首帧在 `vp-refs` 中显示「首帧 · 媒体库」，不显示「上一镜尾帧」
- [ ] 抽取来源显示「上镜尾帧 / 下镜首帧」
- [ ] 旧数据无来源时显示「首帧 · 已选画面」

## 自动化

```bash
node verify-transitions.mjs
npx tsc --noEmit
```

覆盖：来源标签与 normalize、候选顺序与去重、抽取只作候选、缺边界 blocking 文案、附件标签、生成路径不调用 `ensureTransitionBoundary`、服务端 400 文案。
