# Spec Delta

## MODIFIED Requirements

### Requirement: 提示词分层与手改全文

系统 SHALL 区分画面与过渡短提示、声音描述（无音色参考）、自动衔接约束段（只读或可折叠）与最终发送正文。各层文本 MUST 原样进入预览与请求，MUST NOT 按固定字符数截取或以省略号替代；正文为空时 MUST 以「未填写」状态呈现，MUST NOT 用兜底正文静默顶替。最终正文在非编辑态 MUST 以只读预览展示；手改 MUST 通过明确的编辑、保存、取消动作提交，MUST NOT 在只读区直接写入 override。存在已保存的手改正文时生成 MUST 逐字发送该正文，MUST NOT 再追加自动衔接段；用户 MUST 能恢复自动拼装、用当前字段重填手改，并在输入变化导致拼装指纹不匹配时看到「旧快照」状态（与分镜出片手改行为一致）。

#### Scenario: 自动拼装含衔接

- **WHEN** 用户未手改全文且填写了画面短提示
- **THEN** 最终正文包含短提示、衔接约束与 morph 尾句（与 `shot-transition-continuity` 一致）

#### Scenario: 手改优先

- **WHEN** 用户通过保存手改提交全文并生成
- **THEN** 请求 prompt 与手改正文逐字相同，不含系统追加的衔接段

#### Scenario: 短提示超长不被截断

- **WHEN** 用户填写的画面与过渡短提示超过 90 字符
- **THEN** 面板与请求中的该段正文完整保留，MUST NOT 出现 `…` 或半句截断

#### Scenario: 正文为空时的提示

- **WHEN** 一条生成转场的短提示与手改正文都为空
- **THEN** 面板显示「正文未填写」并给出补写或改用手改正文的入口，该状态出现在出片前的阻止或警示列表里

#### Scenario: 编辑流

- **WHEN** 用户点「编辑」修改正文并保存
- **THEN** 面板 badge 为「已手改」，只读区显示保存后的全文

#### Scenario: 旧快照

- **WHEN** 用户已保存手改后改变了边界、风格参考或画面/声音短提示使拼装指纹变化
- **THEN** 面板 badge 为「旧快照」，正文仍为手改版本，用户可继续生成或点「重新拼装」
