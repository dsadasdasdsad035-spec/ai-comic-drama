# Spec Delta

## Purpose

让用户把已经写好的剧本、镜头表与提示词直接带进流水线，而不必先让大模型重写一遍：按输入形态选择零模型的解析路径，只有在必要时才请模型做结构整理，并且任何导入都不得静默改写或删除用户已有的内容。

## ADDED Requirements

### Requirement: 三个文本工作台提供导入入口

剧本、镜头表、提示词三个工作台 SHALL 各自提供「导入」入口，支持上传本地文件与直接粘贴文本两种方式。导入入口 MUST NOT 要求先经过模型；MUST 在未选择项目时不可用并说明原因。

#### Scenario: 上传文件
- **WHEN** 用户在有项目的镜头表页点击「导入」并选择一个表格文件
- **THEN** 系统读取该文件并进入解析与预览流程，不要求用户先点生成

#### Scenario: 粘贴文本
- **WHEN** 用户把一段剧本文本粘贴进导入框并确认
- **THEN** 系统以同样的解析与预览流程处理该文本

#### Scenario: 没有项目
- **WHEN** 用户尚未选择项目时点击导入
- **THEN** 导入入口不可用，并显示先选择项目的提示

### Requirement: 解析按成本从低到高选择路径

系统 SHALL 先尝试零模型的解析路径：内容本身符合目标契约时直接通过契约校验，结构化表格按表头映射为契约形状。只有前两条都不成立时，才 SHALL 为用户提供请模型结构整理的选项。系统 MUST NOT 在零模型路径可用时自动调用模型。

#### Scenario: 文件就是契约
- **WHEN** 用户导入的 JSON 内容符合目标环节的输出契约
- **THEN** 系统直接进入预览，不发起任何模型请求

#### Scenario: 表格可以直接映射
- **WHEN** 用户导入含可识别表头的表格
- **THEN** 系统按表头映射生成契约形状并进入预览，不发起模型请求

#### Scenario: 无法结构化
- **WHEN** 导入内容既不是契约 JSON 也不是可识别表格
- **THEN** 系统显示「让模型整理」选项与将使用的环节模型，等待用户主动点击后才发起请求

### Requirement: 表格按表头别名映射字段

系统 SHALL 支持 Markdown 表格、CSV 与 TSV，并按中英文表头别名识别字段，至少覆盖镜号、时长、景别、机位、运镜、画面描述、台词/声音、首帧提示词与视频提示词。缺少镜号列时 MUST 拒绝导入并说明原因；其余列缺失时 MUST 只留空对应字段，MUST NOT 用默认值冒充用户内容。

#### Scenario: 中文表头
- **WHEN** 表格表头为「镜号 / 秒 / 景别 / 运镜 / 描述 / 台词」
- **THEN** 各列分别映射到对应字段并进入预览

#### Scenario: 英文表头
- **WHEN** 表格表头为 `shot / seconds / size / move / description / dialogue`
- **THEN** 各列按别名映射，行为与中文表头一致

#### Scenario: 缺少镜号列
- **WHEN** 表格没有任何可识别为镜号的列
- **THEN** 系统拒绝导入并说明必须有镜号列，不生成任何草稿

#### Scenario: 只有提示词列
- **WHEN** 表格只有镜号与首帧提示词两列
- **THEN** 导入只更新首帧提示词，不把视频提示词写成空值

#### Scenario: 制作方式等无对应字段的列
- **WHEN** 表格含「制作方式」这类在镜头数据里没有对应字段的列
- **THEN** 该列被忽略并计入预览的「忽略列」清单，不塞进画面描述或任意其他字段

### Requirement: 时长列同时接受区间与秒数

时长列 MUST 同时支持「直接给出秒数」和「给出时间区间」两种形态。区间形式（如 `00-05`、`0–5秒`、`5—11 秒`）MUST 按时长 = 结束 − 开始计算；连字符、短破折号、长破折号与波浪号 MUST 等价处理。无法解析的行 MUST 标记为跳过并说明原因，MUST NOT 猜测时长。

#### Scenario: 区间形式
- **WHEN** 时长列值为 `17–23秒`
- **THEN** 该镜时长为 6 秒

#### Scenario: 不同破折号
- **WHEN** 同一张表里混用 `00-05` 与 `0–5秒` 两种写法
- **THEN** 两者都被正确解析为 5 秒时长

#### Scenario: 直接给秒数
- **WHEN** 时长列值为 `6` 且列名是「秒」
- **THEN** 该镜时长为 6 秒

#### Scenario: 无法解析
- **WHEN** 时长列值为「约几秒」这类无法解析的文本
- **THEN** 该行被跳过并说明时长无法解析，不用默认值填充

### Requirement: 景别列允许自然语言并提取机位

景别列 MUST 接受标准枚举值与自然语言描述。含标准景别词的描述 MUST 归一化到既有枚举（如「极近景」→ 大特写、「中近景」→ 近景、「低机位远景」→ 远景）；归一化失败时 MUST 保留原文并标记为未识别，MUST NOT 静默套用默认景别。描述里的机位信息（如「低机位」「主观镜头」）MUST 被提取为画面描述的补充说明，MUST NOT 丢弃。

#### Scenario: 标准值
- **WHEN** 景别列为「中景」
- **THEN** 该镜景别为中景

#### Scenario: 自然语言含景别词
- **WHEN** 景别列为「低机位远景」
- **THEN** 景别归一化为远景，机位信息「低机位」被保留

#### Scenario: 极端景别
- **WHEN** 景别列为「极近景，猫眼」
- **THEN** 景别归一化为大特写，未匹配的「猫眼」作为补充说明保留

#### Scenario: 无法归一化
- **WHEN** 景别列为「猫咪主观镜头」
- **THEN** 该值被标记为未识别并保留原文，预览提示用户确认，不静默填入默认景别

### Requirement: 台词列分离台词、旁白与音效

台词/声音列 MUST 区分三类内容：带说话人的台词、旁白、以及音效/音乐等非语言声。只有前两类 MUST 进入镜头台词；音效与音乐 MUST NOT 进入台词，MUST 被保留为声音说明。旁白 MUST 标记为非角色说话人，MUST NOT 被当作出场角色。同一单元格里混排的多段内容 MUST 被拆成多条。

#### Scenario: 旁白
- **WHEN** 台词列为「旁白：那天晚上，我以为自己活不过去了。」
- **THEN** 生成一条说话人为旁白的台词，且该镜出场角色不含旁白

#### Scenario: 纯音效
- **WHEN** 台词列为「雨声、远处车声。」
- **THEN** 该镜不产生台词，这段文字作为声音说明保留

#### Scenario: 混合内容
- **WHEN** 台词列为「脚步声停止。人类轻声：小家伙，你怎么在这里？」
- **THEN** 拆成一条声音说明与一条说话人为人类的台词

#### Scenario: 音乐提示
- **WHEN** 台词列为「音乐由紧张转柔和」
- **THEN** 不产生台词，作为声音说明保留

### Requirement: 系统补的默认值必须可见

当表格缺少某个必填字段的列（如运镜）而项目结构要求该字段有值时，系统 MAY 填入默认值，但 MUST 在预览中把这类填充单列为「默认补全」并计数。用户 MUST 能看出哪些值是自己的原文、哪些是系统补的。

#### Scenario: 缺运镜列
- **WHEN** 表格没有运镜列
- **THEN** 所有镜头运镜为固定，预览显示「运镜默认补全 12 镜」

#### Scenario: 有运镜列
- **WHEN** 表格有运镜列
- **THEN** 预览不出现默认补全计数，运镜全部取自表格

### Requirement: 模型整理只允许结构整理

模型整理 MUST 只做结构切分与字段归位：按集/场/镜切分，把已有文字放回对应字段。MUST NOT 新增原文没有的情节、角色、台词或提示词内容，MUST NOT 改写用户已写的句子。整理结果 MUST 通过目标环节的输出契约校验后才进入预览。

#### Scenario: 保留原文措辞
- **WHEN** 用户对一段手写剧本点「让模型整理」
- **THEN** 预览中的场次 beats 与台词保留原文措辞，只被切分到集、场与字段中

#### Scenario: 不补写空缺
- **WHEN** 原文没有写结尾钩子
- **THEN** 整理结果不生成钩子，该字段留空

#### Scenario: 输出不合契约
- **WHEN** 模型返回的内容不满足目标契约
- **THEN** 系统报告不符合契约，不写入任何草稿

### Requirement: 导入先预览后应用

任何导入 MUST 先展示差异预览，再等待用户确认应用。预览 MUST 显示新增、更新、保留与跳过的数量，并 MUST 显式列出需要人判断的项，包括场次号未匹配、镜号未匹配与解析失败的条目。

#### Scenario: 预览计数
- **WHEN** 导入 12 行，其中 3 行是新镜号
- **THEN** 预览显示新增 3、更新 9 与保留的镜数，应用前不修改任何数据

#### Scenario: 场次号对不上
- **WHEN** 表格里的场次号在当前集场次中不存在
- **THEN** 预览显式列出受影响的镜数与回退到的场次，而不是静默归类

#### Scenario: 取消导入
- **WHEN** 用户在预览阶段取消
- **THEN** 项目数据、工作台草稿与脏状态都保持导入前的样子

### Requirement: 导入采用行级合并语义

导入 MUST 只修改文件中出现的行，并只修改这些行中文件明确给了值的字段。文件中未出现的行 MUST 保留。用户 MUST 能对镜头表显式选择「按此文件替换整集」，该选项 MUST 在预览中说明将删除的行数。

#### Scenario: 只补三镜
- **WHEN** 当前集有 20 镜，导入文件只含 3 个镜号
- **THEN** 这 3 镜被新增或更新，其余 17 镜原样保留

#### Scenario: 只改一列
- **WHEN** 导入文件只给了首帧提示词列
- **THEN** 已存在的视频提示词不被清空

#### Scenario: 显式替换整集
- **WHEN** 用户勾选「按此文件替换整集」并确认
- **THEN** 预览事先显示将删除的行数，应用后该集镜头与文件一致

#### Scenario: 剧本按集合并
- **WHEN** 导入的剧本只包含第 2 集
- **THEN** 其他集保持不变，第 2 集按导入内容更新

### Requirement: 导入与生成不静默覆盖手改内容

系统 SHALL 把通过导入或手写得到的字段标记为人改。后续模型生成 MUST NOT 静默覆盖这些字段；用户 MUST 能显式清除人改标记，让生成重新接管。

#### Scenario: 导入后被生成覆盖
- **WHEN** 用户导入首帧提示词后又点了一次「生成提示词」
- **THEN** 已导入的镜头保留导入值，不被生成结果替换

#### Scenario: 提示词表手改
- **WHEN** 用户在提示词表直接编辑某一镜的首帧提示词
- **THEN** 该字段被标记为人改，刷新并重新打开项目后仍然保留

#### Scenario: 清除人改标记
- **WHEN** 用户清除某镜的人改标记后再点生成
- **THEN** 该镜的提示词被生成结果替换

### Requirement: 导入失败不产生部分写入

一次导入 MUST 要么整体应用，要么完全不应用。解析失败、契约校验失败或用户取消时，MUST NOT 留下已写入的行、半更新的字段或意外的脏状态。

#### Scenario: 中途契约失败
- **WHEN** 表格前 10 行可映射、第 11 行镜号重复导致无法生成合法草稿
- **THEN** 整次导入被拒绝，没有任何行被写入

#### Scenario: 保存失败
- **WHEN** 预览通过后保存到项目时请求失败
- **THEN** 界面报告失败并保持草稿，不谎报已保存

### Requirement: 超长文本按结构切块或拒绝

当输入长度可能超出所选模型的上下文时，系统 SHALL 按文本中已有的集、场结构标记切块整理。没有可用结构标记时 MUST 拒绝整理并提示用户先手动分集，MUST NOT 截断后悄悄丢弃后半部分。

#### Scenario: 有集标记
- **WHEN** 长文本含明确的「第 N 集」标记
- **THEN** 系统按集切块整理并逐块校验，最后合并为一次预览

#### Scenario: 没有结构标记
- **WHEN** 一份超长文本没有任何可识别的集或场标记
- **THEN** 系统拒绝整理并说明需要先手动分集，不发送截断内容
