# Spec Delta

## Purpose

让用户把一个装满剧本、分镜、提示词、角色档案与参考照片的压缩包一次性带进流水线：安全解包、按内容判断每个文件的用途、把多版本冲突摆到人面前，再分派到既有导入链路，而不是让用户逐个文件复制粘贴。

## ADDED Requirements

### Requirement: 导入入口接受压缩包

文本工作台与素材/角色页的导入入口 SHALL 接受 `.zip` 压缩包。上传后系统 MUST 在服务端解包并返回文件清单，MUST NOT 让浏览器解压后再上传内容。未选择项目时 MUST 不可用。

#### Scenario: 上传压缩包
- **WHEN** 用户选择一个 `.zip` 文件
- **THEN** 系统在服务端解包并展示其中可导入的文件清单，不解压到项目目录

#### Scenario: 非压缩包
- **WHEN** 用户选择的文件不是合法的 ZIP
- **THEN** 系统明确说明不是有效的压缩包，不产生任何文件清单

#### Scenario: 未选择项目
- **WHEN** 用户没有选择项目
- **THEN** 导入入口不可用并提示先选择项目，不上传文件

### Requirement: 解包拒绝危险内容

解包 MUST 拒绝：含 `..` 的相对路径、绝对路径、盘符路径、符号链接、设备文件、嵌套压缩包。MUST 忽略 macOS 资源叉目录 `__MACOSX` 与 `.DS_Store` 等系统文件。任何一条拒绝项 MUST 在结果里说明被拒条目与原因。

#### Scenario: 路径穿越
- **WHEN** 压缩包内含 `../../etc/passwd`
- **THEN** 该条目被拒绝并说明原因，其余合法条目照常列出

#### Scenario: 符号链接
- **WHEN** 压缩包内含指向包外的符号链接
- **THEN** 该条目被拒绝

#### Scenario: macOS 系统文件
- **WHEN** 压缩包由 macOS 生成并含 `__MACOSX/` 与 `.DS_Store`
- **THEN** 这些条目被静默忽略，不进入文件清单也不报错

#### Scenario: 嵌套压缩包
- **WHEN** 压缩包内还有一个 `.zip`
- **THEN** 内层压缩包不被解包，作为不可导入文件列出并说明

### Requirement: 解包受大小与数量上限保护

系统 MUST 在解包前检查条目数量、单文件解压后大小与解压后总大小，并在任一项超限时中止整次解包。MUST 校验实际解压字节数与中央目录声明一致，MUST NOT 允许声明大小远小于实际内容的条目。

#### Scenario: 条目过多
- **WHEN** 压缩包有数千个条目
- **THEN** 系统拒绝解包并说明条目数超过上限

#### Scenario: 压缩炸弹
- **WHEN** 压缩包声明解压后为 1MB 但实际展开远超声明
- **THEN** 系统在超过上限时中止并删除已解出的文件

#### Scenario: 单文件超限
- **WHEN** 包内单个图片解压后超过图片大小上限
- **THEN** 该文件标记为不可导入并说明原因，其余文件仍可继续

### Requirement: 中文文件名编码兜底

ZIP 条目的 UTF-8 标志位未设置时，系统 MUST 依次尝试 UTF-8 与 GBK/GB18030 解码文件名。仍然失败或得到非法字符时 MUST 使用可写盘的安全文件名，并在清单里同时显示安全名与原名的可读形式。

#### Scenario: macOS 生成的中文名
- **WHEN** 压缩包由 macOS `zip` 生成，条目名是未标 UTF-8 的裸 UTF-8 字节
- **THEN** 文件名显示为正确中文

#### Scenario: Windows 生成的 GBK 名
- **WHEN** 压缩包来自 Windows 且文件名是 GBK 编码
- **THEN** 文件名显示为正确中文

#### Scenario: 无法解码
- **WHEN** 文件名既不是合法 UTF-8 也不是合法 GBK
- **THEN** 使用安全名落盘，清单里标注原名无法识别

### Requirement: 每个文件可产出多个用途且可人工改判

一个文件 MAY 同时承载多种产物（例如一份「完整剧本」里既有分集剧本也有嵌入的逐镜头分镜表）。系统 MUST 为每个文件列出它包含的全部用途，MUST NOT 强制归为单一类别。用户 MUST 能对每一项改判或排除，改判后该文件的解析路径随之改变。

#### Scenario: 剧本内含分镜表
- **WHEN** 文件标题为「第 N 集…完整剧本」且内含 `## 逐镜头分镜表` 小节
- **THEN** 该文件同时产出剧本用途与分镜表用途，预览里可分派到两个目标

#### Scenario: 按路径识别图片
- **WHEN** 文件位于名为「猫咪真实参考照片」的目录且是图片
- **THEN** 用途为参考图

#### Scenario: 按文件名识别
- **WHEN** 文件名含「角色档案」
- **THEN** 用途包含角色档案

#### Scenario: 按内容特征识别
- **WHEN** 文件名没有线索，但内容含以「镜头」为第一列表头的 Markdown 表格
- **THEN** 用途包含分镜表

#### Scenario: 人工改判
- **WHEN** 用户把一个被判为无关文档的文件改为剧本
- **THEN** 该文件按剧本路径解析并在预览里出现

#### Scenario: 排除文件
- **WHEN** 用户把某个文件标记为排除
- **THEN** 该文件不参与本次导入，也不产生任何预览项

### Requirement: 表格识别锚定表头而不是关键词

判断一个 Markdown 文件含分镜表时，系统 MUST 要求表格的表头行第一列是「镜头」或 `shot`，MUST NOT 仅因正文某行出现「镜头」二字就判定为分镜表。

#### Scenario: 图库索引里的「镜头」字样
- **WHEN** 一个参考照片目录的 README 在表格单元格里写着「走路镜头」「转场空镜」
- **THEN** 该文件不被判定为分镜表

#### Scenario: 真正的分镜表
- **WHEN** 文件含 `| 镜头 | 时间 | 景别/机位 | …` 这样的表头行
- **THEN** 该文件被判定为含分镜表

### Requirement: 一个文件覆盖多集时不得归给单集

系统 MUST 按内容里出现的 `## 第 N 集` 小节数判断文件覆盖的集数。覆盖多集的文件 MUST 被标为「多集大纲」并要求用户显式选择如何拆分或排除，MUST NOT 按所在目录或文件名推断成其中某一集。

#### Scenario: 十集大纲放在第01集目录里
- **WHEN** `第01集/02_前10集分集大纲.md` 含 10 个 `## 第N集` 小节
- **THEN** 该文件被标为多集大纲，不自动写成第 1 集剧本

#### Scenario: 单集剧本
- **WHEN** 文件只含一个 `## 第N集` 小节或一个集标题
- **THEN** 该文件归属于该集

#### Scenario: 目录与内容不一致
- **WHEN** 文件位于 `第01集/` 目录但内容是第 5 集的内容
- **THEN** 以内容为准，并在预览里标注目录与内容不一致

### Requirement: 分类不确定时只提供模型判断入口

当路径与内容特征都无法给出用途时，系统 MUST 把该文件列为「待判断」，MUST 提供「让模型分析」入口并显示将使用的模型。MUST NOT 自动发起模型请求。

#### Scenario: 无线索文件
- **WHEN** 一个 Markdown 文件既没有路径线索也没有可识别的表格或小节结构
- **THEN** 该项显示为待判断，提供「让模型分析」按钮

#### Scenario: 用户不点
- **WHEN** 用户不点「让模型分析」直接继续
- **THEN** 待判断的文件被排除，其余文件正常导入

### Requirement: 同一目标的多版本冲突必须由人选择

当同一集出现两个或以上结构相同的产物（例如两份不同的分镜表或两份不同的分集剧本）时，系统 MUST 列出冲突并等待用户选择其中一个或多个。MUST NOT 静默合并、MUST NOT 以文件顺序覆盖。

#### Scenario: 两份分镜表
- **WHEN** 包内同时有「第01集_…md」与「第01集/03_第1集完整剧本与分镜.md」，两者都含第 1 集的逐镜头表且镜数不同（10 镜 vs 12 镜）
- **THEN** 预览显示冲突并提出两种选择：只导入其一，或分别导入到不同集号

#### Scenario: 用户未处理冲突
- **WHEN** 用户没有为冲突项做出选择就点应用
- **THEN** 系统拒绝应用并指出未处理的冲突，不导入任一方

#### Scenario: 十集剧本不视为冲突
- **WHEN** 包内有 10 个文件分别对应第 1 至 10 集
- **THEN** 它们互不冲突，作为同一批剧本导入

### Requirement: 同一文件的分镜表写入时先对比镜数

同一集存在多个分镜来源时，系统 MUST 在预览里显示每个来源的镜数与表头差异，供用户判断哪一份是最新版本。MUST NOT 只显示文件名让人凭记忆选。

#### Scenario: 镜数不同
- **WHEN** 第 1 集有两份分镜表，分别为 10 镜与 12 镜
- **THEN** 预览并列显示「10 镜」「12 镜」与各自的表头列名

#### Scenario: 镜数相同
- **WHEN** 两份分镜表镜数相同
- **THEN** 预览提示「镜数相同但内容可能不同」并建议逐份导入对比

### Requirement: 分派复用既有导入语义

每个文件 MUST 走对应目标的既有解析与合并路径：文本走格式识别、表头映射与 `merge` 合并，图片走上传校验与落盘。MUST NOT 为压缩包另建一套解析或写入逻辑。整套导入 MUST 先整体预览再应用，MUST 要么全部应用要么完全不应用。

#### Scenario: 文本文件
- **WHEN** 一个被分类为分镜表的文件通过预览被应用
- **THEN** 它按表格映射与行级合并写入，行为与单独上传该文件一致

#### Scenario: 图片文件
- **WHEN** 一个被分类为参考图的文件被应用
- **THEN** 它经既有上传链路落盘并获得站内地址

#### Scenario: 部分失败
- **WHEN** 图片保存成功但后续文本写入失败
- **THEN** 系统报告失败，不留下已写入的镜头或半更新的字段，并说明已落盘的文件

### Requirement: 解包产物不进入项目目录

解包 MUST 写入系统临时目录，MUST 在请求结束或用户在预览中取消后清理。MUST NOT 把压缩包本身或中间文件写进项目媒体目录；只有用户确认导入的图片才转化为项目媒体文件。

#### Scenario: 取消导入
- **WHEN** 用户解包后在预览阶段取消
- **THEN** 临时目录被清理，项目媒体目录不新增任何文件

#### Scenario: 确认导入
- **WHEN** 用户确认导入其中三张图片
- **THEN** 只有这三张被复制为项目媒体文件，其余解包产物被清理
