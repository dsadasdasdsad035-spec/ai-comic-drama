# Spec Delta

## Purpose

定义工作台聊天把什么送给模型：附件清单是唯一输入来源，每一段文本与每一张图在发送前可见、可移除；图片先经视觉理解再进入上下文，没有视觉模型时明确降级；异步理解结果必须在同步渲染前算好，不能让聊天每帧都触发视觉调用。

## ADDED Requirements

### Requirement: 附件清单是模型输入的唯一来源

工作台聊天送给模型的上下文 MUST 只由附件清单产生，MUST NOT 额外附加界面状态、未选中的素材或隐藏的默认值。清单 MUST 至少包含元数据与附件两项；每个附件 MUST 带可用于展示的标签与类型。

#### Scenario: 只有显式附件进入上下文
- **WHEN** 用户在聊天里只加入了角色「陈默」的一张参考图
- **THEN** 本轮上下文只包含该图，不包含项目里其他角色的图片或未加入的素材

#### Scenario: 没有附件
- **WHEN** 用户没有加入任何附件就发送消息
- **THEN** 模型只收到元数据与该轮用户输入，界面不出现空附件占位

#### Scenario: 元数据范围
- **WHEN** 聊天处于角色工作台
- **THEN** 元数据只描述本次编辑范围（项目、集号或角色范围），不伪造镜头号、时长或画幅

### Requirement: 附件在发送前可见且可移除

系统 MUST 在输入区上方列出本轮全部附件，逐个显示标签、类型与（图片的）缩略图；用户 MUST 能在发送前移除任意附件或清空全部。移除 MUST 立即反映到发送内容，MUST NOT 等到下一轮才生效。

#### Scenario: 移除图片附件
- **WHEN** 用户从附件栏移除一张图片
- **THEN** 该图不再出现在本轮上下文，后续消息也不包含它

#### Scenario: 清空附件
- **WHEN** 用户点清空
- **THEN** 附件栏变空，元数据与输入框内容保留

#### Scenario: 发送前检查
- **WHEN** 用户点开「查看将发送」
- **THEN** 能看到元数据、每个附件的缩略图或全文、文本附件字符数与图片数量，并能从检查器里排除某项

### Requirement: 图片附件先经视觉理解

图片附件进入上下文前 MUST 先经视觉模型理解，产出可读的描述片段；MUST NOT 只把图片 URL 当文本交给文本模型。多张图片 MUST 先合成一张带标签的参考板再提交，因为视觉接口只接受单张图片。参考板 MUST 标注每张图的稳定键，使模型能把描述对应回具体图片。

#### Scenario: 单图理解
- **WHEN** 用户只加入一张参考图
- **THEN** 视觉模型收到该图，返回的描述与这张图的标签对应

#### Scenario: 多图合成参考板
- **WHEN** 用户加入三张参考图
- **THEN** 系统合成一张带三个标签的参考板，视觉模型只被调用一次，返回三条按标签对应的描述

#### Scenario: 描述进入上下文
- **WHEN** 视觉理解成功
- **THEN** 上下文里同时存在图片附件与它的描述片段，描述在检查器里可见

### Requirement: 无视觉模型时明确降级

没有可用的视觉模型、参考板无效或视觉调用失败时，系统 MUST NOT 报成发送失败；MUST 退化为只用文本上下文，并在附件栏与回执里明确说明「没有看图」。降级 MUST 记录原因，供用户在检查器里看到。

#### Scenario: 未配置视觉模型
- **WHEN** 设置里没有可用的视觉模型，用户加入了一张参考图
- **THEN** 消息仍可发送，界面说明「未配置视觉模型，图片未参与理解」

#### Scenario: 视觉调用失败
- **WHEN** 视觉模型返回错误
- **THEN** 发送继续，回执里写明失败原因与「已回退为只用文本」

#### Scenario: 参考板无法生成
- **WHEN** 图片文件缺失或无法解码，合成参考板得到空图
- **THEN** 跳过视觉理解并说明原因，不阻断发送

### Requirement: 视觉理解必须先于同步渲染算好

视觉理解是异步操作，而聊天在渲染期同步读取上下文。系统 MUST 在附件变化时预计算视觉理解并缓存结果，渲染期 MUST 只读缓存。MUST NOT 在渲染过程中发起视觉请求，MUST NOT 因重复渲染而重复计费。

#### Scenario: 同一附件不重复理解
- **WHEN** 用户加入一张图并触发多次渲染
- **THEN** 视觉模型只被调用一次，后续渲染命中缓存

#### Scenario: 附件变化后重算
- **WHEN** 用户移除一张图或加入新图
- **THEN** 缓存按新的附件集合重新计算，旧结果不再被使用

#### Scenario: 理解未完成时不阻塞界面
- **WHEN** 视觉理解仍在进行中
- **THEN** 附件栏显示该图正在理解，输入框仍可用

### Requirement: 每轮调用留下可审计的上下文

系统 MUST 为每一轮模型调用记录本轮实际发送的上下文摘要（附件数量、类型分布、每个附件的标签），并 MUST 能与该轮消息对应。审计记录 MUST 在会话内可查看，MUST NOT 只保留在内存中随时丢失而不提示。

#### Scenario: 查看本轮上下文
- **WHEN** 用户点开某一轮消息的上下文卡
- **THEN** 显示该轮的附件清单与数量，与发送时一致

#### Scenario: 两轮附件不同
- **WHEN** 用户第一轮带图、第二轮不带图
- **THEN** 两轮的上下文卡分别反映各自的附件，不互相覆盖
