# Spec Delta

## ADDED Requirements

### Requirement: 运行事件必须区分步骤、文本与工具调用

运行时 SHALL 把一次运行拆成三组可区分的事件：步骤生命周期、面向用户的文本消息生命周期、工具调用生命周期。文本消息 MUST 有稳定标识并支持开始/增量/结束；工具调用 MUST 有稳定标识并支持开始/参数增量/结束/结果。事件 MUST 按发生顺序提供，reasoning 或 thinking 增量 MUST NOT 进入事件流。

#### Scenario: 一次模型调用

- **WHEN** 图执行一次模型节点并产出说明文字
- **THEN** 事件依次包含步骤开始、文本消息开始、若干文本增量、文本消息结束、步骤结束

#### Scenario: 一次工具调用

- **WHEN** 模型返回一个工具调用
- **THEN** 事件包含工具调用开始、参数增量、参数结束与结果，且结果可通过同一标识匹配到调用

#### Scenario: 推理增量

- **WHEN** 渠道返回 reasoning 或 thinking 增量
- **THEN** 事件流中不出现这些内容

### Requirement: 工具参数完整前不得执行

工具参数以增量形式到达时 MUST 只作为可观察进度；只有收到明确的“参数完整”信号后，工具才可执行。代码类参数在完整前 MUST NOT 进入代码草稿、MUST NOT 触发试运行或保存。

#### Scenario: 参数分片

- **WHEN** 代码参数仍在分片到达
- **THEN** 代码页签不接收该草稿，试运行入口保持不可用

#### Scenario: 参数完整

- **WHEN** 参数完整信号到达且通过准入
- **THEN** 工具才执行，代码才可进入草稿

### Requirement: 取消必须终止未完成的流

用户取消或客户端断开时，运行时 MUST 停止提供后续增量、终止上游请求，并把本次运行标记为已取消。终止后 MUST NOT 再产生新的文本增量、工具开始或运行完成事件。

#### Scenario: 用户取消

- **WHEN** 用户在文本流或工具执行中取消
- **THEN** 后续增量不再到达，运行以已取消结束

#### Scenario: 客户端断开

- **WHEN** 浏览器断开与本地代理的连接
- **THEN** 代理终止对应的上游请求，不留下仍在写入的流
