# Spec Delta

## MODIFIED Requirements

### Requirement: 运行轨迹必须可审计

运行时 MUST 记录每次模型调用、工具调用、工具结果、失败原因和修复次数，并通过可消费的事件流逐步提供给聊天 UI；MUST NOT 暴露模型隐藏推理或 chain-of-thought，只展示可观察动作、参数摘要、面向用户的简短说明和结果。

#### Scenario: 成功轨迹

- **WHEN** agent 完成场景
- **THEN** 轨迹包含模型轮次、工具顺序、每次沙箱结果和验收结论

#### Scenario: 失败轨迹

- **WHEN** agent 达到上限失败
- **THEN** 轨迹保留失败步骤和错误，不删除中间记录

#### Scenario: 不展示隐藏推理

- **WHEN** 聊天渲染轨迹
- **THEN** 只显示工具事件、模型面向用户的简短说明和摘要，不显示模型内部思维过程

#### Scenario: 模型轮次事件

- **WHEN** agent 调用一次模型
- **THEN** 事件流产生该轮开始和结束事件，结束事件包含可展示的简短说明或明确的空说明状态

#### Scenario: 事件去重

- **WHEN** 同一工具调用同时产生生命周期事件和领域结果
- **THEN** 事件带有稳定标识，消费方更新同一张卡片，不产生重复的孤立卡片
