# Proposal

## Why

五个内容工作台（剧本、角色、素材、镜头表、提示词）都有聊天，且聊天与顶部一键按钮共用同一套技能和输出契约；但**顶部的一键动作没有成为聊天里的显式入口**。用户正在聊天里改稿时，想“拆镜/生成分集/从全剧拆角色/生成提示词”，只能离开聊天去点按钮，或者寄希望于模型自己按技能产出草稿。两条路径还存在真实差异：一键按钮用完整 inline 输入与本地 `brief`，聊天超过 2000 字只给引用行，而读工具读的是 project.json；角色/素材的“全剧”范围只在按钮上；提示词按钮的分批并行和任务进度也不会出现在聊天里。这个变更把“内置动作”变成每个工作台聊天自己的显式动作，同时不把一次昂贵的从零生成偷偷塞进 agent 的自动循环。

## What Changes

- 每个内容工作台聊天增加该工作台的内置动作，镜像顶部按钮：
  - 剧本：生成分集 / 重新生成分集（全剧）
  - 角色：从本集拆角色 / 从全剧拆角色
  - 素材：从本集拆 / 从全剧拆
  - 镜头表：拆镜（当前集）
  - 提示词：生成提示词（当前集，沿用分批并行）
- `WorkbenchChatAdapter` 增加内置动作契约（`builtins: BuiltinAction[]` 与统一的 `BuiltinResult`）；顶部按钮和聊天动作调用**同一个宿主函数**，不复制技能提示词或合并逻辑。
- 内置动作在模型循环之外运行：使用工作台的完整 inline 输入与本地草稿，复用 `startTask` / 进度 / 取消；支持 `AbortSignal`，取消后不写入半份草稿。
- 动作结果以结构化 `builtin` 回执进入聊天线程（动作、范围、数量、保存语义、模型、耗时），下一轮模型只看到摘要，不看到整份产物。
- 模型侧的 `read_*` + `submit_*` 工具保持不变；**v1 不把内置动作做成模型可调用的工具**（不新增 `run_builtin`，避免在 agent 循环里再套模型调用与额外费用）。
- 同一工作台一次只跑一个动作：运行中禁用聊天发送、顶部按钮和聊天内其他动作；模型运行中动作也禁用。
- 空态文案从“用上方的…”改为指向聊天内的动作；头部保留一个紧凑入口；顶部按钮继续保留。
- 保存语义沿用工作台：剧本/镜头/提示词显式保存，角色约 1 秒自动落库，素材立即落库；动作回执明确写出当前语义。
- 重构五个工作台的一键函数，使其返回结构化结果并接受取消信号；角色拆解从 `App.tsx` 收敛为可被按钮与聊天共用的宿主回调。

明确不做：

- 不做模型可调用的内置动作工具（A2 需要确认门禁、更长超时与成本提示，留作后续）。
- 不做跨工作台的统一聊天；每个动作只写自己工作台的产物。
- 不改变 3D 工作台聊天、工具集或验收流程。
- 不替换顶部按钮，也不改变现有合并/保存语义。
- 不新增项目数据字段，不需要迁移。

## Capabilities

### New Capabilities

- `workbench-chat-actions`: 五个内容工作台聊天里的内置动作入口、统一宿主执行契约、取消与进度、结构化回执、范围/保存语义与动作互斥。

### Modified Capabilities

（无。基座能力 `workbench-chat` 仍在进行中的 `skill-driven-workbench-chats` 里，尚未进入主规格；本变更以独立的新能力先捕获，归档顺序见 Impact。）

## Impact

- 聊天层：`src/agent/workbenchChat.ts`（adapter 契约）、`src/agent/SkillChat.tsx`、`src/chat-ui/WorkbenchHeader.tsx` / `WorkbenchEmpty.tsx`、`src/agent/stageToolUis.tsx`（builtin 回执）、`src/agent/threads.ts`（线程持久化摘要）。
- 五个工作台：`ScriptBoard`、`CharacterBoard`、`AssetBoard`、`ShotTable`、`PromptTable` 的 adapter 与一键函数；`App.tsx` 的 `extractCharacters` 收敛为共享回调。
- 技能层：沿用 `buildBoardSkillPrompt(..., 'inline')` 与现有输出契约，不新增技能文件；聊天任务的 `'chat'` 引用模式不变。
- 测试：按钮与聊天动作的结果一致性、inline 大输入、本集/全剧范围、取消不落半份、保存语义、线程恢复、项目隔离、动作互斥。
- 依赖与顺序：`skill-driven-workbench-chats` 当前 39/40，主规格 `workbench-chat` 尚未归档，且本变更会改同一批聊天文件。建议先完成/归档该变更，再 apply 本变更；本变更的规划与归档可独立进行。
