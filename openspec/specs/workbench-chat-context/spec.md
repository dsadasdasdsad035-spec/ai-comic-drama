# workbench-chat-context Specification

## Purpose
定义工作台聊天把什么送给模型：附件清单是唯一输入来源，每一段文本与每一张图在发送前可见、可移除；本轮图片与用户文字一起交给当前聊天模型，渠道不能接收图片时改为明确占位。

## Requirements

### Requirement: 附件清单是模型输入的唯一来源

工作台聊天送给模型的上下文 MUST 只由附件清单产生，MUST NOT 额外附加界面状态、未选中的素材或隐藏的默认值。清单 MUST 至少包含元数据与附件两项；每个附件 MUST 带可用于展示的标签与类型。

#### Scenario: 只有显式附件进入上下文
- **WHEN** 用户在聊天里只加入了角色「陈默」的一张参考图
- **THEN** 本轮上下文只包含该图，不包含项目里其他角色的图片或未加入的素材

#### Scenario: 没有附件
- **WHEN** 用户没有加入任何附件就发送消息
- **THEN** 模型只收到元数据与该轮用户输入，界面不出现空附件占位

#### Scenario: 元数据范围
- **WHEN** 聊天处于角色工作台
- **THEN** 元数据只描述本次编辑范围（项目、集号或角色范围），不伪造镜头号、时长或画幅

### Requirement: 附件在发送前可见且可移除

系统 MUST 在输入区上方列出本轮全部附件，逐个显示标签、类型与（图片的）缩略图；用户 MUST 能在发送前移除任意附件或清空全部。移除 MUST 立即反映到发送内容，MUST NOT 等到下一轮才生效。

#### Scenario: 移除图片附件
- **WHEN** 用户从附件栏移除一张图片
- **THEN** 该图不再出现在本轮上下文，后续消息也不包含它

#### Scenario: 清空附件
- **WHEN** 用户点清空
- **THEN** 附件栏变空，元数据与输入框内容保留

#### Scenario: 发送前检查
- **WHEN** 用户点开「查看将发送」
- **THEN** 能看到元数据、每个附件的缩略图或全文、文本附件字符数与图片数量，并能从检查器里排除某项

### Requirement: 图片与文字一起交给当前模型

本轮仍挂着的图片 MUST 与该轮用户文字处于同一条用户消息。多张图片 MUST 各自独立送出，MUST NOT 先拼成一张参考板，MUST NOT 先经另一个视觉模型转成文字摘要。

#### Scenario: 单张图与文字同发

- **WHEN** 用户加入一张参考图并发送一句要求
- **THEN** 当前聊天模型在同一条用户消息里同时收到这张图和这句要求

#### Scenario: 多张图保持独立

- **WHEN** 用户加入三张参考图后发送
- **THEN** 模型收到三张互相独立的图片，而不是一张拼板或三段外观摘要

#### Scenario: 不再预调用视觉模型

- **WHEN** 用户加入图片到发送完成
- **THEN** 系统不调用单独的视觉理解接口，输入框保持可用，发送不被「正在理解」拦住

### Requirement: 渠道不能看图时明确占位

当前聊天模型所在渠道不接受图片内容，或该模型未声明可看图时，系统 MUST NOT 把图片数据当作正文文本送出。每张这样的图片 MUST 换成说明该图未送入模型的文字占位，用户 MUST 能在发送前或本轮回执里看到这个说明。

#### Scenario: Agent Plan 渠道

- **WHEN** 当前聊天模型走 Agent Plan 渠道，用户带一张图发送
- **THEN** 请求里没有图片数据，消息中改为该图未送入模型的占位说明

#### Scenario: 模型未声明可看图

- **WHEN** 渠道能接收图片，但当前模型未声明可看图
- **THEN** 该图同样改为占位说明，不把图片数据送进请求

#### Scenario: 能看图的渠道

- **WHEN** 渠道接受图片内容且当前模型声明可看图
- **THEN** 每张图以图片内容送出，不替换成占位

### Requirement: 单张图片无法送出时不阻断消息

某一张图片无法读取或超过单张 4MB 时，系统 MUST 只将该张换成说明原因的占位，MUST NOT 因此让整条消息发送失败。其余可读且未超限的图片仍按渠道规则送出。

#### Scenario: 一张图损坏

- **WHEN** 本轮有两张图，其中一张无法解码
- **THEN** 消息仍然发送；损坏的那张变为占位，另一张按渠道规则送出

#### Scenario: 超过单张上限

- **WHEN** 一张图解码后超过 4MB
- **THEN** 该张变为说明超限的占位，同条消息里的文字和其他合格图片仍送出

### Requirement: 每轮调用留下可审计的上下文

系统 MUST 为每一轮模型调用记录本轮实际发送的上下文摘要（附件数量、类型分布、每个附件的标签），并 MUST 能与该轮消息对应。图片附件 MUST 额外记录它是以图片送出还是被替换为占位及原因。审计记录 MUST 在会话内可查看，MUST NOT 只保留在内存中随时丢失而不提示。

#### Scenario: 查看本轮上下文

- **WHEN** 用户点开某一轮消息的上下文卡
- **THEN** 显示该轮的附件清单与数量，与发送时一致；每张图标明是已送出还是占位

#### Scenario: 两轮附件不同

- **WHEN** 用户第一轮带图、第二轮不带图
- **THEN** 两轮的上下文卡分别反映各自的附件，不互相覆盖
