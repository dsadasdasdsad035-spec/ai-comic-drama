# chat-agent-runtime Specification

## Purpose

定义应用内所有聊天共用的执行运行时：一个循环、一套原生工具调用协议、一套模型能力前提与一套运行上限，使 3D 调度、工作台、发布与创意聊天在工具语义、事件形状和取消行为上保持一致。

## Requirements

### Requirement: 所有聊天共用同一个执行运行时

应用内所有聊天 SHALL 由同一个有状态工具调用运行时驱动，包括 3D 调度、五个工作台聊天、发布助手与创意会话。任何聊天 MUST NOT 自带第二套模型循环或第二套工具执行路径。运行时的模型调用 MUST 继续经过服务端代理。

#### Scenario: 统一运行时

- **WHEN** 任一聊天发起一轮对话
- **THEN** 它走同一个运行时，并产生同形状的步骤、文本与工具事件

#### Scenario: 不存在第二套循环

- **WHEN** 检查聊天实现
- **THEN** 不存在按技能、按工作台或按界面分叉的模型循环

#### Scenario: 线程记录兼容

- **WHEN** 用户打开切换前保存的聊天线程
- **THEN** 历史消息、工具卡片与草稿回执仍按原样恢复

### Requirement: 聊天只使用原生工具调用

聊天 SHALL 向渠道以原生函数声明提交工具，并只执行渠道返回的结构化工具调用。系统 MUST NOT 要求模型输出文本形式的动作 JSON，MUST NOT 把模型文本解析或翻译成工具调用，MUST NOT 为该协议保留回退路径。

#### Scenario: 原生工具调用

- **WHEN** 模型返回结构化工具调用
- **THEN** 运行时按模型给出的顺序执行，并以同一调用标识回填结果

#### Scenario: 文本不变成动作

- **WHEN** 模型只返回文本而没有工具调用
- **THEN** 该文本只作为面向用户的回答展示，不产生任何工具执行

#### Scenario: 不支持时直接失败

- **WHEN** 当前渠道或模型不支持原生工具调用
- **THEN** 运行以可读错误结束，不切换到文本动作协议，也不伪造执行成功

### Requirement: 聊天模型必须声明支持原生工具调用

发起聊天前，运行时 MUST 依据原生工具能力表校验当前环节模型。未声明的模型 MUST 以可读错误结束，错误 MUST 指明渠道、模型与可选替代。能力判定 MUST 以模型标识为准，MUST NOT 因同一模型改走不同渠道而改变结论。

#### Scenario: 能力表内模型

- **WHEN** 当前环节模型已声明支持原生工具调用
- **THEN** 聊天正常开始，并在触发轨迹中记录实际使用的协议

#### Scenario: 能力表外模型

- **WHEN** 当前环节模型未声明支持原生工具调用
- **THEN** 错误说明该模型不能用于聊天，并列出可用模型

#### Scenario: 同一模型更换渠道

- **WHEN** 同一模型标识通过另一渠道配置提供
- **THEN** 能力判定结论与原先一致

### Requirement: 工具声明必须来自唯一的参数 schema

工具的参数结构与校验 SHALL 由同一份 schema 定义生成，MUST NOT 另维护一份手写声明。带默认值的可选参数 MUST NOT 在声明中被标记为必填。

#### Scenario: 单一来源

- **WHEN** 某工具的参数定义发生变化
- **THEN** 模型看到的声明随之变化，不需要修改第二处定义

#### Scenario: 默认值参数

- **WHEN** 工具参数是可省略且有默认值的字段
- **THEN** 声明不把它列为必填，省略时按默认值处理

#### Scenario: 声明与校验一致

- **WHEN** 模型提交的参数不符合声明
- **THEN** 工具在执行前被拒绝，并向模型返回可读的校验错误

### Requirement: 工具结果必须分离模型可见与界面可见内容

工具执行结果 SHALL 同时提供模型可见摘要与界面可见详情。模型可见内容 MUST 只包含摘要与必要提示，MUST NOT 包含图片数据地址、视频数据地址或整段代码正文；界面可见内容 MUST 保留完整结果供工具卡片渲染。本约束只适用于工具结果，不适用于用户消息里由用户附加的图片。

#### Scenario: 抓帧结果

- **WHEN** 工具返回关键帧
- **THEN** 模型只收到帧数量与时间点摘要，界面仍能显示缩略图

#### Scenario: 代码提交结果

- **WHEN** 工具提交或修改代码
- **THEN** 模型只收到行数、字符数与内容哈希摘要，完整代码留在草稿与界面

#### Scenario: 工具结果不夹带用户附件

- **WHEN** 同一轮里用户消息带有图片，工具随后返回结果
- **THEN** 工具结果仍只有文字摘要，不把用户那张图片或工具自己的图片数据放进工具回传

### Requirement: 用户图片保持到渠道出口再转换

用户消息中的图片 MUST 保持为图片，直到服务端代理按渠道转换。代理 MUST NOT 在转换前把图片数据拼进普通文本。接受图片内容的渠道 MUST 把每张图转成该渠道的图片内容块，与同一条用户消息里的文字一起提交。不接受图片内容的渠道 MUST 把每张图换成说明未送入模型的文字占位。

#### Scenario: 接受图片的渠道

- **WHEN** 用户消息带有两张图片，且当前渠道接受图片内容、模型声明可看图
- **THEN** 提交给渠道的该条用户消息同时包含文字和两张图片内容

#### Scenario: 不接受图片的渠道

- **WHEN** 用户消息带有图片，且当前渠道不接受图片内容
- **THEN** 提交给渠道的消息不含图片数据，对应位置是说明未送入的占位文字

#### Scenario: 历史轮次不重复带上旧图

- **WHEN** 用户发送新的一轮，输入区里已经没有上一轮曾经用过、后来移除的图片
- **THEN** 新请求不包含那张已移除的图片

### Requirement: 运行上限与取消必须由运行时统一实现

每次聊天运行 SHALL 受总时长上限约束；超时 MUST 终止上游请求与进行中的工具。用户取消 MUST 立即停止产生新事件，MUST NOT 继续执行后续工具。运行时 MUST 自身响应取消信号，MUST NOT 依赖底层只中止当前请求就假定循环已停止。工具轮次上限 MUST 只作为内部安全阀，MUST NOT 作为用户可配置的产品设置。

#### Scenario: 运行超时

- **WHEN** 运行超过总时长上限
- **THEN** 上游请求与进行中的工具被终止，运行以超时错误结束

#### Scenario: 用户取消

- **WHEN** 用户在模型流或工具执行中取消
- **THEN** 后续工具不再执行，不再产生新的文本或工具事件

#### Scenario: 底层只中止当前请求

- **WHEN** 底层中止能力只覆盖当前模型流
- **THEN** 运行时自身保证循环退出，不继续调度下一轮

### Requirement: 引擎事件必须映射为稳定的聊天事件

运行时 SHALL 把底层事件映射为既有聊天事件形状，覆盖步骤生命周期、面向用户的文本生命周期与工具调用生命周期。映射 MUST 保证同一工具调用只有一个开始与一个结束事件；底层推理或思维增量 MUST NOT 进入事件流或线程记录。

#### Scenario: 一次模型轮次

- **WHEN** 运行时完成一次模型调用
- **THEN** 产生该轮的开始与结束事件，结束事件携带可展示的文本或明确的空说明

#### Scenario: 工具事件去重

- **WHEN** 同一工具调用同时产生生命周期事件与领域结果
- **THEN** 界面更新同一张卡片，不出现重复的孤立卡片

#### Scenario: 隐藏推理

- **WHEN** 渠道返回推理或思维增量
- **THEN** 事件流与线程记录都不包含这些内容

### Requirement: 发往渠道的工具参数必须是 object JSON Schema

聊天运行时向文本渠道提交原生 function tools 时，每个工具的 `parameters` MUST 在 JSON Schema 顶层声明 `type: "object"`。系统 MUST NOT 将顶层为 `anyOf`、`oneOf` 或缺少 `type` 的 schema 原样发给声明校验严格的渠道。若某工具契约在运行时仍接受多种 payload 形状，模型可见的声明 MUST 使用单一 object 形状；其它形状 MUST 在工具执行或契约校验前归一化。

#### Scenario: APIMart Responses 接受角色 submit 工具

- **WHEN** 角色聊天使用 APIMart 推理模型且走 Responses 工具路由
- **THEN** `submit_characters` 的 parameters 为顶层 object，请求不因 invalid_function_parameters 在发工具声明阶段失败

#### Scenario: 模型返回裸数组仍可通过契约

- **WHEN** 模型调用 `submit_characters` 且 arguments 为角色数组而非 `{ characters: [...] }`
- **THEN** 系统在契约校验前归一化为 object 形状，校验与合并草稿行为与归一化前合法数组一致

#### Scenario: 静态验收覆盖全部 submit 工具

- **WHEN** 运行工具 schema 验收脚本
- **THEN** 各工作台 `submit_*` 工具导出的 parameters 均满足顶层 `type: "object"`
